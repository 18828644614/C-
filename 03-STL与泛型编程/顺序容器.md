# 顺序容器

## 学习目标
- [ ] 理解“顺序容器”保存元素的基本方式，以及连续存储和节点存储的区别。
- [ ] 会使用 `std::array`、`std::vector`、`std::deque`、`std::list` 和 `std::forward_list` 的常见操作。
- [ ] 能区分 `size()` 与 `capacity()`，理解 `reserve()`、`resize()` 和扩容的作用。
- [ ] 能根据访问、插入、内存局部性、复杂度和迭代器失效规则选择容器。

## 要点

### 1. 什么是顺序容器

顺序容器（sequence container）按照元素加入容器的先后顺序保存数据。它们不会像 `std::map` 那样根据键自动排序，也不会像 `std::set` 那样自动去重。容器通常允许重复元素，元素的位置由序号（下标）或迭代器表示。

常见顺序容器如下：

| 容器 | 长度 | 典型存储方式 | 最适合的场景 |
| --- | --- | --- | --- |
| `std::array<T, N>` | 固定，编译期确定 | 一整块连续内存 | 元素个数固定，希望有 STL 接口 |
| `std::vector<T>` | 可变 | 一整块连续内存 | 默认选择：遍历、下标访问、末尾追加 |
| `std::deque<T>` | 可变 | 多个内存块组成 | 需要在两端频繁插入和删除 |
| `std::list<T>` | 可变 | 双向链表节点 | 已经有迭代器，且确实频繁在中间移动节点 |
| `std::forward_list<T>` | 可变 | 单向链表节点 | 只需单向遍历，并且非常在意节点开销 |

这里的“连续内存”很重要。`vector` 的元素通常紧挨着放在一起，CPU 读取一批相邻元素时可以充分利用缓存；链表的节点则可能散落在内存各处，虽然某些插入操作便宜，但遍历常常更慢。因此不能只看到“链表插入是 `O(1)`”就认为链表总是更快。

### 2. 先掌握一组通用操作

下面这些成员函数在多个顺序容器中都能看到：

| 操作 | 含义 | 新手注意点 |
| --- | --- | --- |
| `size()` | 当前元素个数 | 返回的是数量，不是最后一个下标 |
| `empty()` | 是否没有元素 | 等价于 `size() == 0`，通常更直接 |
| `front()` / `back()` | 访问首元素 / 尾元素 | 容器为空时不能调用 |
| `begin()` / `end()` | 首元素迭代器 / 尾后迭代器 | `end()` 不是最后一个元素，不能解引用 |
| `push_back(x)` | 在末尾添加一个元素 | 传入已经构造好的对象时很常用 |
| `emplace_back(args...)` | 在容器末尾直接构造元素 | 参数是元素构造函数参数，不是一个现成对象 |
| `pop_back()` | 删除末尾元素 | 只删除，不返回被删元素 |
| `clear()` | 删除全部元素 | 容器对象本身仍然存在 |
| `erase(pos)` | 删除某个位置 | 返回删除位置之后的迭代器（若存在） |

访问元素时，`at(i)` 会进行边界检查，越界通常抛出 `std::out_of_range`；`operator[](i)` 不检查边界，越界访问属于未定义行为。初学或处理外部输入时可以优先使用 `at()`，确认下标可靠且追求简洁时再使用 `[]`。

### 3. `std::vector`：最值得先学会的容器

`vector` 同时拥有三个特征：

1. 元素连续存储，因此支持快速下标访问，`values[i]` 是 `O(1)`。
2. 长度可以变化，`push_back()` 可以在运行时添加元素。
3. 容量不足时会重新分配一整块更大的内存，并把旧元素移动或复制过去。

#### 3.1 `size`、`capacity`、`reserve` 和 `resize`

- `size()`：现在有多少个真实元素。
- `capacity()`：当前这块内存不用重新分配时，最多能放多少个元素。
- `reserve(n)`：只预留至少 `n` 个元素的空间，不创建元素，所以不会改变 `size()`。
- `resize(n)`：改变真实元素个数；变大时新增元素，变小时销毁多余元素。

可以把 `capacity` 想成“已经租下的座位”，把 `size` 想成“已经坐下的人数”。预留座位不会凭空增加学生；只有 `push_back` 或 `resize` 才会让元素真正存在。

```cpp
#include <iostream>
#include <vector>

int main() {
    std::vector<int> values;
    values.reserve(5);             // 预留空间，但此时没有任何元素

    std::cout << values.size() << '\n';     // 0：真实元素数量
    std::cout << values.capacity() << '\n'; // 至少 5：已分配容量

    // values[0] = 10;             // 错误：reserve 没有创建 values[0]
    values.push_back(10);           // 现在才真正创建第一个元素
    values.resize(3);               // 元素数量变成 3；新增 int 会值初始化为 0

    std::cout << values[0] << ' ' << values[1] << ' ' << values[2] << '\n';
    // 输出：10 0 0
}
```

`capacity()` 的具体增长策略由标准库实现决定，不能写代码假设它每次都翻倍。通常只要容量够用，追加元素就不需要搬家；但一旦扩容，旧的迭代器、指针和引用可能全部失效。`shrink_to_fit()` 只是“请求”减少多余容量，标准不保证一定真的收缩，因此不要把它当成强制命令。

#### 3.2 `push_back` 与 `emplace_back`

`push_back` 把一个对象放入容器，`emplace_back` 把构造函数参数转发给元素类型，在容器内部直接构造对象：

```cpp
#include <string>
#include <utility>
#include <vector>

struct User {
    std::string name;
    int level;

    User(std::string user_name, int user_level)
        : name(std::move(user_name)), level(user_level) {}
};

int main() {
    std::vector<User> users;

    User alice{"Alice", 3};
    users.push_back(alice);                 // 把已有对象复制进 vector
    users.push_back(std::move(alice));      // 允许 vector 移动 alice 的资源
    users.emplace_back("Bob", 5);          // 直接在 vector 末尾构造 User
}
```

`emplace_back` 并不保证在所有情况下都比 `push_back` 更快，也不能修复容器扩容带来的搬移。选择它的主要理由是“我手里只有构造参数，并希望直接构造元素”。如果已经有一个对象，`push_back` 往往更直观。

### 4. `std::array`：固定长度的连续容器

`std::array<T, N>` 的长度是类型的一部分，`N` 必须在编译期确定。它和内置数组一样连续存储，但额外提供 `size()`、`begin()`、`at()` 等 STL 接口，能够直接交给许多算法。

```cpp
#include <array>
#include <iostream>

int main() {
    std::array<int, 3> scores{90, 80, 70};

    for (int score : scores) {
        std::cout << score << ' ';
    }

    scores[1] = 85;             // 下标访问不检查边界
    std::cout << scores.at(1);  // at() 检查边界，越界会抛异常
}
```

`std::array<int, 3>` 和 `std::array<int, 4>` 是不同类型，不能在运行时改变长度。如果长度来自用户输入，应该使用 `vector`。如果长度固定但要把数组作为对象传递、排序或与算法配合，`array` 通常比裸数组更方便。

### 5. `std::deque`：两端操作更方便

`deque`（double-ended queue，双端队列）支持在头尾高效插入和删除：`push_front`、`push_back`、`pop_front`、`pop_back` 通常都是 `O(1)`。它也支持 `operator[]`，但内部不是一整块连续内存；不能把它当成可以直接传给要求连续缓冲区的 C API 的 `vector` 替代品。

```cpp
#include <deque>
#include <iostream>

int main() {
    std::deque<int> tasks{2, 3};
    tasks.push_front(1);   // [1, 2, 3]
    tasks.push_back(4);    // [1, 2, 3, 4]

    while (!tasks.empty()) {
        std::cout << tasks.front() << ' '; // 查看队头
        tasks.pop_front();                 // 删除队头
    }
}
```

如果主要工作是“在末尾追加、按下标读取、从头到尾遍历”，`vector` 通常仍然更合适；只有确实需要两端都频繁操作时，才优先考虑 `deque`。

### 6. `std::list` 与 `std::forward_list`：节点稳定，但不是默认答案

`list` 是双向链表，每个节点保存元素以及前后节点链接；`forward_list` 是单向链表，只保存下一个节点链接。它们的共同特点是：

- 不支持快速下标访问，找第 `i` 个元素必须从头遍历，通常是 `O(n)`。
- 已经拿到插入位置迭代器时，插入或删除节点通常是 `O(1)`。
- 插入或删除其他节点不会搬动已有元素，因此已有元素的迭代器、指针和引用通常仍然有效。
- 节点额外保存链接，且内存不连续，遍历和缓存局部性通常不如 `vector`。

链表的常数时间插入有一个前提：你已经知道位置。若每次都要先从头查找位置，查找本身仍是 `O(n)`，整个操作未必比 `vector` 快。

```cpp
#include <iostream>
#include <iterator>
#include <list>

int main() {
    std::list<int> numbers{1, 3};

    auto position = std::next(numbers.begin()); // 指向 3；查找这一步是线性的
    numbers.insert(position, 2);                // 在 3 前插入 2

    for (int number : numbers) {
        std::cout << number << ' ';             // 1 2 3
    }
}
```

`forward_list` 没有 `size()`、`back()` 和 `push_back()`，因为单向链表要维护这些操作会增加额外成本。它常用 `before_begin()` 和 `insert_after()`：

```cpp
#include <forward_list>

int main() {
    std::forward_list<int> numbers{2, 3};

    // before_begin() 表示“第一个元素之前”的特殊位置。
    numbers.insert_after(numbers.before_begin(), 1); // [1, 2, 3]
}
```

如果只是想“保存一串会增长的数据”，先选 `vector`；只有数据结构本身需要稳定节点、频繁移动节点，或算法天然按链表操作时，才使用链表。`list::splice` 可以把一个链表中的节点整体接到另一个链表中，而不复制元素，这是它较有代表性的用途。

### 7. 复杂度：不要只背一个 `O(1)`

下表是常见的平均或摊销复杂度。具体实现和元素类型仍会影响实际性能。

| 操作 | `array` | `vector` | `deque` | `list` | `forward_list` |
| --- | ---: | ---: | ---: | ---: | ---: |
| 按下标访问 | `O(1)` | `O(1)` | `O(1)` | 不支持 / `O(n)` | 不支持 / `O(n)` |
| 末尾添加 | 不可变 | 摊销 `O(1)` | `O(1)` | `O(1)` | 不支持 `push_back` |
| 头部添加 | 不可变 | `O(n)` | `O(1)` | `O(1)` | `O(1)`（`push_front`） |
| 已知位置插入 | 不可变 | 位置后元素需移动，`O(n)` | 通常需移动，`O(n)` | `O(1)` | `O(1)`（`insert_after`） |
| 查找某个值 | `O(n)` | `O(n)` | `O(n)` | `O(n)` | `O(n)` |
| 遍历全部元素 | `O(n)` | 通常很快 | 通常较快 | `O(n)`，节点跳转开销较大 | `O(n)`，节点跳转开销较大 |

“摊销 `O(1)`”表示：某一次 `vector::push_back` 可能因为扩容而搬移 `n` 个元素，但把很多次追加平均起来，每次的平均成本仍接近常数。不要把它理解成“每一次都绝对是常数时间”。

### 8. 迭代器、引用和指针何时失效

迭代器、引用和指针只是访问容器元素的通道，容器改变后它们不一定还能继续使用。使用失效的通道属于未定义行为，可能表现为崩溃，也可能“看起来没问题”但以后随机出错。

| 容器 | 插入 / 追加 | 删除 |
| --- | --- | --- |
| `vector` | 发生扩容时，原有迭代器、引用和指针全部失效；未扩容时，插入点及其后的迭代器失效 | 被删位置及其后的迭代器失效 |
| `deque` | 两端操作也可能使迭代器失效；中间插入应按“迭代器可能全部失效”处理 | 中间删除通常使迭代器全部失效；两端删除影响较小但仍应及时更新迭代器 |
| `list` | 已有元素的迭代器、引用和指针保持有效 | 只有指向被删元素的通道失效 |
| `forward_list` | 已有元素的通道保持有效 | 只有被删元素的通道失效 |
| `array` | 容器大小不能改变，不存在扩容失效 | 不能通过 `erase` 改变长度 |

对 `deque` 的细节规则比较多，初学阶段只要记住：不要在修改后继续盲用旧迭代器，优先使用操作返回的新迭代器；需要精确到某个边界情况时再查标准库文档。

一个典型错误是保存了 `vector` 的迭代器，然后追加元素：

```cpp
std::vector<int> values{1, 2, 3};
auto it = values.begin();

values.push_back(4); // 可能扩容，it 可能已经指向旧内存
// std::cout << *it;  // 错误：不能继续使用可能失效的 it
```

如果要在遍历时删除元素，应接住 `erase` 的返回值。返回值指向删除位置之后的下一个仍可访问元素；如果删除的是末尾元素，它可能等于 `end()`：

```cpp
#include <iostream>
#include <vector>

int main() {
    std::vector<int> values{1, 2, 3, 4, 5};

    for (auto it = values.begin(); it != values.end();) {
        if (*it % 2 == 0) {
            it = values.erase(it); // 不要再 ++it，erase 已返回下一个位置
        } else {
            ++it;
        }
    }

    for (int value : values) {
        std::cout << value << ' '; // 1 3 5
    }
}
```

### 9. 删除满足条件的元素：`erase`、`remove` 和 C++20

`std::remove` 这个名字很容易误导：它是算法，不会改变容器的长度。它会把“不需要删除的元素”搬到前面，并返回新的逻辑末尾；真正缩短 `vector` 的动作仍要调用容器的 `erase`。这就是经典的 erase-remove idiom：

```cpp
#include <algorithm>
#include <iostream>
#include <vector>

int main() {
    std::vector<int> values{1, 2, 2, 3, 4};

    // remove 把不等于 2 的元素移到前面，返回新的逻辑 end。
    auto new_end = std::remove(values.begin(), values.end(), 2);
    values.erase(new_end, values.end()); // 这一步才真正删除多余尾部

    for (int value : values) {
        std::cout << value << ' '; // 1 3 4
    }
}
```

C++20 提供了更直接的 `std::erase(container, value)` 和 `std::erase_if(container, predicate)`，它们会同时完成“移动并缩短容器”的工作：

```cpp
#include <iostream>
#include <vector>

int main() {
    std::vector<int> values{1, 2, 3, 4, 5};

    std::erase_if(values, [](int value) {
        return value % 2 == 0; // 删除所有偶数
    });

    for (int value : values) {
        std::cout << value << ' '; // 1 3 5
    }
}
```

### 10. 如何选择：一条给新手的判断路径

可以依次问自己：

1. 长度是否在编译期固定？是：考虑 `std::array`；否：继续判断。
2. 是否主要在末尾追加，并且需要快速遍历或下标访问？是：优先 `std::vector`。
3. 是否经常在头尾两端插入和删除？是：考虑 `std::deque`。
4. 是否经常在中间插入、删除或移动节点，并且已经持有位置迭代器？是：考虑 `std::list`；只需单向链接则考虑 `std::forward_list`。
5. 是否需要把数据作为连续缓冲区传给 C 接口？优先 `vector` 或 `array`，并通过 `data()` 获取首地址；不要假设 `deque` 和链表连续。

没有特殊证据时，`vector` 是很好的默认选择。之后再根据测量结果、内存限制和接口要求调整，而不是根据容器名称的“理论最快操作”猜测性能。

还要注意 `std::vector<bool>` 是一个特殊的位压缩实现，它不一定返回真正的 `bool&`。如果需要普通布尔引用、与某些 API 交互或避免初学阶段的代理对象困惑，可以考虑 `std::vector<unsigned char>` 或其他明确的表示方式。

## 示例与实践

### 综合示例：读取、筛选、排序和安全删除

下面的程序把几个核心动作串起来：用 `vector` 拥有数据，用范围 `for` 遍历，用算法筛选，并演示如何在遍历时正确处理 `erase` 返回的迭代器。

```cpp
#include <algorithm>
#include <iostream>
#include <string>
#include <utility>
#include <vector>

struct Book {
    std::string title;
    int pages;

    Book(std::string book_title, int book_pages)
        : title(std::move(book_title)), pages(book_pages) {}
};

int main() {
    std::vector<Book> books{
        {"C++ Basics", 320},
        {"Algorithms", 180},
        {"Templates", 450},
    };

    // 预留空间不会改变 books.size()，只是减少后续扩容概率。
    books.reserve(10);
    books.emplace_back("STL", 260); // 直接构造一个 Book 并追加到末尾

    // 按页数从少到多排序；sort 要求随机访问迭代器，vector 满足要求。
    std::sort(books.begin(), books.end(), [](const Book& left, const Book& right) {
        return left.pages < right.pages;
    });

    // 删除页数少于 200 的书。
    for (auto it = books.begin(); it != books.end();) {
        if (it->pages < 200) {
            it = books.erase(it); // 返回下一个元素，避免使用失效迭代器
        } else {
            ++it;
        }
    }

    for (const Book& book : books) {
        std::cout << book.title << ": " << book.pages << " pages\n";
    }
}
```

这里有一个容易忽视的限制：`std::sort` 不能直接处理 `std::list`，因为它需要随机访问迭代器；如果确实使用链表，应调用 `books.sort(...)` 这样的容器成员函数，或者先把数据转移到 `vector` 再排序。
