# 字符串、视图与范围

## 学习目标

- [ ] 理解 `std::string`、C 风格字符串和 `std::string_view` 的区别。
- [ ] 能安全地创建、拼接、查找、切分和遍历字符串。
- [ ] 能判断一个视图是否会因为原字符串销毁或修改而悬空。
- [ ] 理解范围（range）与迭代器的关系，并会使用 C++20 范围算法。
- [ ] 能组合 `filter`、`transform` 等视图完成数据处理，并知道何时需要复制结果。

## 先建立一个总模型

处理文本时，常会遇到三个容易混淆的词：**字符串、视图、范围**。

| 类型 | 是否拥有数据 | 主要用途 | 典型风险 |
| --- | --- | --- | --- |
| `std::string` | 是 | 保存和修改一段文本 | 复制或拼接可能分配内存 |
| `std::string_view` | 否，只借用一段字符 | 只读地传参、切片，避免复制 | 原字符串销毁后视图悬空 |
| range / view | 通常否，表示“可遍历的一段数据” | 组合筛选、变换、截取 | 视图通常是惰性的，且也有生命周期要求 |

可以用“书”和“书签”来类比：`std::string` 是自己拥有的一本书；`std::string_view` 是指向书中一页的书签；range 是“从哪一页走到哪一页”的描述。书被销毁后，书签和范围描述就不能再使用。

## 一、`std::string`：真正拥有字符的字符串

### 1. 创建和基本操作

`std::string` 位于 `<string>` 头文件中。它可以保存空格、中文（以 UTF-8 字节形式保存）以及嵌入的空字符，但它本身不负责理解“字符”在某种编码中占几个字节。

```cpp
#include <iostream>
#include <string>

int main() {
    std::string name = "Alice";
    std::string message{"Hello, "};

    message += name;                 // 追加字符串，message 变成 "Hello, Alice"
    message += '!';                  // 追加一个字符

    std::cout << message << '\n';
    std::cout << message.size() << '\n'; // 字符串长度（更准确地说是字节数）
}
```

常用操作如下：

| 写法 | 作用 |
| --- | --- |
| `s.size()` / `s.length()` | 返回长度；两者对 `string` 等价 |
| `s.empty()` | 判断是否为空 |
| `s[i]` | 访问下标为 `i` 的字符，不做边界检查 |
| `s.at(i)` | 访问字符，越界时抛出 `std::out_of_range` |
| `s.front()` / `s.back()` | 访问首字符 / 尾字符；空字符串上调用是错误的 |
| `s.substr(pos, count)` | 复制出一段新的字符串 |
| `s.find("abc")` | 查找子串，找不到时返回 `std::string::npos` |

`size()` 返回的是 `std::size_t`（无符号整数）。和有符号整数比较时要小心，通常让下标也使用 `std::size_t`，或使用范围 `for` 避免手写下标。

### 2. `[]` 还是 `at()`？

当下标一定有效时，`s[i]` 简洁而高效；当下标来自用户输入或计算结果时，`at()` 能在越界时明确报错，调试阶段尤其有帮助。

```cpp
#include <iostream>
#include <string>

int main() {
    std::string word = "cat";
    std::size_t index = 5; // 假设这是外部输入

    // word[index] 越界会产生未定义行为，可能悄悄读到错误数据。
    // std::cout << word[index];

    try {
        std::cout << word.at(index); // 越界时抛出 std::out_of_range
    } catch (const std::out_of_range& error) {
        std::cout << "下标无效：" << error.what() << '\n';
    }
}
```

### 3. 输入：`operator>>` 与 `getline`

`std::cin >> text` 会跳过开头空白，并在遇到下一个空白时停止；读取整行（包括空格）应使用 `std::getline`。

```cpp
#include <iostream>
#include <limits>
#include <string>

int main() {
    int age{};
    std::string full_name;

    std::cin >> age;

    // 输入数字后，回车符仍留在输入缓冲区。
    // 如果直接 getline，它可能只读到这个“空行”。
    std::cin.ignore(std::numeric_limits<std::streamsize>::max(), '\n');
    std::getline(std::cin, full_name); // 现在可以读取包含空格的姓名
}
```

如果前一步读取失败，先处理流状态（如 `std::cin.clear()`），再决定如何丢弃错误输入；不要无条件地把 `ignore` 当成“修复所有输入问题”的万能函数。

### 4. 查找和替换

```cpp
#include <iostream>
#include <string>

int main() {
    std::string text = "C++ is fast. C++ is portable.";
    const std::string target = "C++";

    std::size_t position = text.find(target);
    while (position != std::string::npos) {
        text.replace(position, target.size(), "C++20");
        // 从替换后的文本继续查找，避免重复处理同一位置。
        position = text.find(target, position + 4);
    }

    std::cout << text << '\n';
}
```

`find` 的返回类型是 `std::size_t`，失败值是特殊常量 `std::string::npos`。不要把返回值直接和 `-1` 混用；使用 `npos` 语义最清晰。

### 5. C 风格字符串和 `c_str()`

C 风格字符串是以 `\0`（空字符）结尾的字符数组，例如 `"cat"` 实际保存为 `{'c', 'a', 't', '\0'}`。许多旧的 C API 需要 `const char*`，此时可以调用 `c_str()`：

```cpp
#include <cstdio>
#include <string>

int main() {
    std::string filename = "notes.txt";
    std::FILE* file = std::fopen(filename.c_str(), "r");
    if (file != nullptr) {
        std::fclose(file);
    }
}
```

`c_str()` 返回的指针由字符串管理，不能手动 `delete`。只要后续修改字符串导致重新分配，之前保存的指针就可能失效；因此通常只在调用 C API 的那一刻使用它。

## 二、`std::string_view`：不拥有数据的只读窗口

### 1. 为什么需要视图

如果函数只需要读取字符串，参数写成 `std::string` 可能产生一次不必要的复制。`std::string_view` 只保存“字符起始地址 + 长度”，创建它通常很便宜，也可以接受字符串字面量、`std::string` 和字符数组。

```cpp
#include <iostream>
#include <string>
#include <string_view>

void print_title(std::string_view title) {
    // view 不拥有字符，也不能通过它修改字符。
    std::cout << "[" << title << "]\n";
}

int main() {
    std::string owned = "C++ 学习";
    print_title(owned);       // 不复制 owned 的内容
    print_title("入门指南");  // 也可以直接传字符串字面量
}
```

选择参数类型时，可以先记这个经验：

- 函数需要**拥有并保存**文本：用 `std::string`；
- 函数只在调用期间**读取**文本：优先用 `std::string_view`；
- 函数需要修改调用者的字符串：用 `std::string&`。

### 2. 视图的生命周期是最重要的难点

视图不拥有数据，所以必须保证被观察的字符串比视图活得更久。下面的代码会产生悬空视图：

```cpp
#include <string>
#include <string_view>

std::string_view make_view() {
    std::string local = "temporary";
    return local; // 危险：local 离开函数后销毁，返回的 view 指向已不存在的字符
}

int main() {
    std::string_view view = make_view();
    // 使用 view 是未定义行为，不要被“偶尔还能打印出来”迷惑。
}
```

安全做法是返回拥有数据的 `std::string`，或者让调用者提供仍然存活的字符串：

```cpp
#include <string>
#include <string_view>

std::string_view prefix(std::string_view text, std::size_t count) {
    return text.substr(0, count); // substr 对 view 仍然只是切一个窗口，不会复制
}

int main() {
    std::string source = "hello";
    std::string_view first_two = prefix(source, 2);
    // source 仍然存活，因此 first_two 有效。
}
```

### 3. 临时对象和字符串修改也会让视图失效

不要让 `string_view` 绑定到临时 `std::string`，也不要在保存视图后随意修改原字符串：

```cpp
#include <string>
#include <string_view>

int main() {
    // std::string_view bad = std::string("hello"); // 危险：临时 string 很快销毁

    std::string text = "hello";
    std::string_view view = text;

    text += " world"; // 可能重新分配内存，view 可能悬空
    // 使用 view 前不能假定它仍然有效。
}
```

即使这次 `+=` 没有重新分配，改变字符内容也会改变视图看到的内容。把 `string_view` 当作“只读期间使用的借用”，不要把它当成可长期保存的字符串。

### 4. `string_view` 的常用操作

它支持 `size()`、`empty()`、`substr()`、`find()`、`at()`、`starts_with()`、`ends_with()` 等只读操作。其中 `at()` 属于 C++17，`starts_with()` 和 `ends_with()` 需要 C++20。`operator[]` 不做边界检查；需要检查边界时可使用 `at()`。

```cpp
#include <iostream>
#include <string_view>

int main() {
    std::string_view path = "images/cat.png";

    if (path.ends_with(".png")) {
        std::cout << "这是 PNG 文件\n";
    }

    const auto slash = path.find('/');
    if (slash != std::string_view::npos) {
        std::cout << "目录：" << path.substr(0, slash) << '\n';
        std::cout << "文件：" << path.substr(slash + 1) << '\n';
    }
}
```

如果确实需要得到独立、可保存的字符串，再显式复制：

```cpp
std::string filename = std::string(path.substr(slash + 1));
```

## 三、范围（range）：一段可以遍历的数据

### 1. 范围和迭代器的关系

一个 range 可以粗略理解为一对“起点和终点”，也就是 `begin` 和 `end`。范围 `for`、`std::ranges` 算法和 `views` 都建立在这个模型上。

```cpp
#include <iostream>
#include <string>

int main() {
    std::string word = "hello";

    // 范围 for 隐藏了 begin/end 和迭代器递增。
    for (char& ch : word) {
        if (ch == 'l') {
            ch = 'L'; // 使用引用才能修改原字符串
        }
    }

    for (const char ch : word) {
        std::cout << ch; // 输出：heLLo
    }
}
```

只读遍历时可使用 `const auto&`；想复制每个元素时才用 `auto`。对字符这种小类型，复制通常没问题，但养成先问“我要修改还是只读”的习惯很重要。

### 2. C++20 范围算法

传统算法需要手写两个迭代器：`std::sort(v.begin(), v.end())`；范围算法可以直接接收容器：

```cpp
#include <algorithm>
#include <iostream>
#include <ranges>
#include <string>
#include <vector>

int main() {
    std::vector<std::string> words{"pear", "apple", "banana"};

    std::ranges::sort(words); // 按字典序排序，等价于 sort(begin, end)

    if (std::ranges::find(words, "banana") != words.end()) {
        std::cout << "找到了 banana\n";
    }
}
```

算法返回的仍可能是迭代器。范围只是让接口更直观，并不能取消迭代器失效、元素类型或算法复杂度等基本规则。

### 3. 视图管道：惰性地筛选和变换

`std::views::filter`、`transform`、`take` 等适配器不会立刻生成新容器，而是返回一个“需要遍历时再计算”的视图。多个视图可以用 `|` 连接：

```cpp
#include <iostream>
#include <ranges>
#include <string>
#include <vector>

int main() {
    std::vector<std::string> words{"apple", "a", "banana", "avocado"};

    auto result = words
        | std::views::filter([](const std::string& word) {
              return word.starts_with('a'); // 只保留 a 开头的单词
          })
        | std::views::transform([](const std::string& word) {
              return word.size(); // 遍历时才计算长度
          })
        | std::views::take(2); // 最多取前两个结果

    for (std::size_t length : result) {
        std::cout << length << ' '; // 输出 5 1（顺序取决于原数据）
    }
}
```

这里的 `result` 不是 `vector<size_t>`，而是一条计算规则。每次遍历它都可能重新执行谓词和变换函数；如果需要保存结果、随机访问或跨越原数据生命周期使用，应把它物化：

```cpp
#include <ranges>
#include <vector>

auto lengths = result | std::ranges::to<std::vector>(); // C++23
// C++20 没有 ranges::to 时，可以手动：
// std::vector<std::size_t> lengths;
// for (auto value : result) lengths.push_back(value);
```

### 4. 范围视图也有生命周期要求

视图通常保存对底层范围的引用或迭代器，因此不能返回指向局部容器的视图：

```cpp
#include <ranges>
#include <vector>

auto bad_range() {
    std::vector<int> local{1, 2, 3};
    return local | std::views::filter([](int value) { return value > 1; });
    // local 销毁后，返回的视图内部引用悬空。
}
```

把数据和视图一起放在拥有者对象中，或直接返回已经物化的容器，通常更安全。字符串视图和范围视图的共同原则是：**先确认底层数据还活着，再保存或返回视图**。

## 四、综合示例：解析一行文本

下面的例子用 `string_view` 切分字段，用范围视图筛选非空字段，最后把需要长期保存的结果复制到 `vector<string>`。它展示了“借用以减少复制，拥有以延长生命周期”的组合方式。

```cpp
#include <iostream>
#include <ranges>
#include <string>
#include <string_view>
#include <vector>

std::vector<std::string> split_non_empty(std::string_view line) {
    std::vector<std::string> fields;

    while (!line.empty()) {
        const auto comma = line.find(',');
        const auto field = line.substr(0, comma);

        if (!field.empty()) {
            fields.emplace_back(field); // 这里复制到 string，结果可脱离 line 保存
        }

        if (comma == std::string_view::npos) {
            break;
        }
        line.remove_prefix(comma + 1); // 让 view 窗口向后移动，不复制剩余文本
    }

    return fields;
}

int main() {
    const std::string line = "C++,,views,ranges";
    const auto fields = split_non_empty(line);

    for (const auto& field : fields) {
        std::cout << field << '\n'; // 输出 C++、views、ranges
    }
}
```

## 常见错误

### 错误 1：把 `\0` 当成 `std::string` 的结束标志

`std::string` 保存长度，因此可以包含空字符；但传给只接受 C 字符串的旧 API 时，API 会在第一个 `\0` 处停止。使用 C API 前要确认它是否支持显式长度。

### 错误 2：返回局部字符串的 `string_view`

局部 `std::string` 返回后已经销毁，视图变成悬空。返回 `std::string`，或让调用者提供生命周期更长的源字符串。

### 错误 3：修改原字符串后继续使用旧视图

`append`、`insert`、`replace` 等操作可能重新分配内存，使已有 `string_view` 失效。即使没有重新分配，也要记住它看到的是被修改后的内容。

### 错误 4：认为视图会自动缓存结果

`filter` 和 `transform` 视图是惰性的；遍历时才计算，不自动保存结果。需要索引、排序、跨越源数据生命周期或多次稳定访问时，应复制到容器。

### 错误 5：忽略空范围和边界

调用 `front()`、`back()`、解引用 `begin()` 前先确认非空。`substr(pos, count)` 中 `pos` 超出长度会抛出异常；范围算法返回 `end()` 时表示没有找到，不要解引用它。

## 示例与实践

1. 写一个函数 `bool has_prefix(std::string_view text, std::string_view prefix)`，判断文本是否以指定前缀开头。
2. 读取一整行，统计其中元音字母的数量；分别尝试 `std::string` 下标和范围 `for`。
3. 用 `std::views::filter` 筛选长度大于 3 的单词，再用 `transform` 转换为长度；说明为什么结果不是 `vector`。
4. 构造一个会产生悬空 `string_view` 的函数，用 AddressSanitizer 或调试器观察问题，再改为返回 `std::string`。
5. 把综合示例改成返回 `std::vector<std::string_view>`，然后说明为什么调用者必须保证输入字符串一直存活。
