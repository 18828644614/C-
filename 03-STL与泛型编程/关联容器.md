# 关联容器

## 学习目标
- [ ] 理解关联容器“通过键查找数据”的基本思路。
- [ ] 会使用 `std::map`、`std::set`、`std::unordered_map` 和 `std::unordered_set` 的常见操作。
- [ ] 区分唯一键和允许重复键的 `multi` 容器。
- [ ] 理解排序、哈希、比较器和迭代器失效的基本规则。
- [ ] 能根据是否需要有序遍历、查找性能和键类型选择合适的容器。

## 要点

### 1. 什么是关联容器

顺序容器（例如 `vector`）主要按照“第几个元素”访问数据；关联容器则按照一个**键（key）**查找数据。可以把它们想象成两种日常物品：

- `map` 像字典：通过单词（键）找到解释（值）。它保存的是“键 + 值”的键值对。
- `set` 像一张名单：只关心某个值是否出现过，不另外保存与它对应的值。

关联容器不提供“按下标访问第几个元素”的语义。即使 `map` 支持 `books["C++"]` 这种写法，方括号里的内容也是键，不是从 0 开始的序号。

标准库中的关联容器可以按两个维度分类：

| 类型 | 是否保存值 | 是否允许重复键 | 是否自动有序 | 常见查找复杂度 |
| --- | --- | --- | --- | --- |
| `std::map<Key, T>` | 键和值 | 不允许 | 是，按键排序 | `O(log n)` |
| `std::multimap<Key, T>` | 键和值 | 允许 | 是，按键排序 | `O(log n)` |
| `std::set<Key>` | 只有键 | 不允许 | 是，按键排序 | `O(log n)` |
| `std::multiset<Key>` | 只有键 | 允许 | 是，按键排序 | `O(log n)` |
| `std::unordered_map<Key, T>` | 键和值 | 不允许 | 否 | 平均 `O(1)` |
| `std::unordered_multimap<Key, T>` | 键和值 | 允许 | 否 | 平均 `O(1)` |
| `std::unordered_set<Key>` | 只有键 | 不允许 | 否 | 平均 `O(1)` |
| `std::unordered_multiset<Key>` | 只有键 | 允许 | 否 | 平均 `O(1)` |

这里的“平均 `O(1)`”不是绝对保证。无序容器依靠哈希函数把键分配到桶（bucket）中；如果很多键落到同一个桶，查找可能变慢。另一方面，有序容器的 `O(log n)` 是由树形结构提供的稳定上界，并且可以按从小到大的顺序遍历。

### 2. `std::map`：最常用的键值表

`map` 的每个元素是一个键值对，类型可以理解为 `std::pair<const Key, T>`。键带有 `const`，因为如果直接修改键，容器内部的排序位置可能就不正确了。

```cpp
#include <iostream>
#include <map>
#include <string>

int main() {
    std::map<std::string, int> scores{
        {"Alice", 90},
        {"Bob", 85},
    };

    scores["Cindy"] = 95;       // 没有 Cindy 时，先创建键并把值初始化为 0，再赋值 95
    scores.at("Alice") = 92;    // 键不存在时，at() 会抛出 std::out_of_range

    // map 会按照键的比较顺序遍历，而不是按照插入顺序遍历。
    for (const auto& [name, score] : scores) { // C++17 结构化绑定
        std::cout << name << ": " << score << '\n';
    }
}
```

#### 2.1 `operator[]` 可能“偷偷插入”元素

这是新手最容易踩到的坑：读取 `scores["Unknown"]` 并不是只查询。如果键不存在，`operator[]` 会插入一个默认值。例如 `int` 的默认值是 `0`，`std::string` 的默认值是空字符串。

只想查询时使用 `find` 或 `at` 更清楚：

```cpp
std::map<std::string, int> scores;

if (auto it = scores.find("Alice"); it != scores.end()) {
    std::cout << it->second << '\n'; // 找到：it->first 是键，it->second 是值
}

// C++20 可以写成 scores.contains("Alice")，只返回 true / false，不会插入元素。
```

`find` 找不到时返回 `end()`。`end()` 表示“尾后位置”，不能解引用；使用 `it->second` 前必须先判断查找成功。

由于 `operator[]` 需要在缺少键时创建一个默认值，所以映射的值类型必须能够默认构造。例如值类型只有 `Widget(int)` 构造函数、没有 `Widget()` 时，不能写 `widgets["id"]`；此时应改用 `try_emplace("id", 构造参数...)` 或 `insert`。

#### 2.2 插入、更新和“只在不存在时构造”

```cpp
std::map<std::string, int> counts;

auto [it1, inserted1] = counts.insert({"apple", 3});
// inserted1 为 true 表示插入成功；如果 apple 已存在，insert 不会覆盖旧值。

counts.insert_or_assign("apple", 4); // 有则覆盖，无则插入（C++17）
counts.try_emplace("banana", 2);     // 只有键不存在时，才用 2 构造值（C++17）

// 对代价较大的值类型，try_emplace 可以避免“先构造一个临时值、结果却没插入”的浪费。
```

当需求是“已有键不能覆盖”，用 `insert`；需求是“无论如何都写入新值”，用 `insert_or_assign`；需求是“只在新键出现时构造值”，用 `try_emplace`。

### 3. `std::set`：去重并保持有序

`set` 只保存键本身，插入相同的值不会产生第二份元素。插入函数同样返回一个 `pair`，可以用它判断这次是否真的插入：

```cpp
#include <iostream>
#include <set>

int main() {
    std::set<int> numbers{3, 1, 3, 2}; // 自动去重并排序为 1、2、3

    auto [position, inserted] = numbers.insert(2);
    std::cout << std::boolalpha << inserted << '\n'; // false：2 已经存在

    if (numbers.find(5) == numbers.end()) {
        std::cout << "5 不在集合中\n";
    }

    for (int number : numbers) {
        std::cout << number << ' '; // 1 2 3
    }
}
```

如果只需要判断“某个元素是否出现过”，`set` 比用 `vector` 保存后每次线性查找更直接。若不需要有序遍历，且键有合适的哈希函数，可以考虑 `unordered_set`。

### 4. `multi` 容器：允许同一个键出现多次

普通 `map` 和 `set` 只允许一个唯一键；`multimap` 和 `multiset` 允许重复键。例如一个学生可能选修多门课程，就可以用 `multimap<学生, 课程>` 表示。

```cpp
#include <iostream>
#include <map>
#include <string>

int main() {
    std::multimap<std::string, std::string> courses{
        {"Alice", "C++"},
        {"Alice", "Algorithms"},
        {"Bob", "Databases"},
    };

    // equal_range 返回“键等于 Alice”的连续范围。
    auto [first, last] = courses.equal_range("Alice");
    for (auto it = first; it != last; ++it) {
        std::cout << it->first << " -> " << it->second << '\n';
    }
}
```

如果一个键对应多个值，也可以使用 `map<Key, std::vector<Value>>`。这种写法更适合需要直接替换某个键的全部值、或经常按键取得一个值列表的场景；`multimap` 则更适合把每条记录当作独立元素处理。

### 5. `unordered_map` 和 `unordered_set`：用哈希换取平均常数时间

无序关联容器不按键排序，而是先对键计算哈希值，再根据哈希值找到桶。只要哈希函数分布合理，`find`、插入和删除的平均成本接近 `O(1)`。

```cpp
#include <iostream>
#include <string>
#include <unordered_map>

int main() {
    std::unordered_map<std::string, int> visits;

    ++visits["/home"]; // 第一次访问时会先创建键，int 值从 0 变成 1
    ++visits["/home"];
    ++visits["/about"];

    // 遍历顺序不固定，也不保证是插入顺序；不要依赖这个顺序输出结果。
    for (const auto& [page, count] : visits) {
        std::cout << page << ": " << count << '\n';
    }
}
```

`reserve(n)` 可以提前为大约 `n` 个元素准备空间，减少后续扩容和重新分桶的次数；`load_factor()` 表示平均每个桶中有多少元素；`max_load_factor()` 可以调整触发重新分桶的阈值。重新分桶（rehash）后，无序容器的迭代器可能失效，因此不要长期保存迭代器并在插入很多元素后继续使用它。引用和指针的稳定规则更细，初学阶段也应在修改容器后重新获取访问位置。

#### 5.1 自定义键类型需要哈希和相等比较

整数、字符串等常见类型已经有标准哈希函数。自定义类型作为无序容器的键时，至少要提供哈希函数和相等比较：

```cpp
#include <cstddef>
#include <iostream>
#include <string>
#include <unordered_map>

struct Point {
    int x;
    int y;

    bool operator==(const Point& other) const {
        return x == other.x && y == other.y;
    }
};

struct PointHash {
    std::size_t operator()(const Point& point) const {
        // 这里只是教学用的简单组合；实际项目可选择更成熟的哈希方案。
        auto hx = std::hash<int>{}(point.x);
        auto hy = std::hash<int>{}(point.y);
        return hx ^ (hy << 1);
    }
};

int main() {
    std::unordered_map<Point, std::string, PointHash> names;
    names[{1, 2}] = "起点";
    std::cout << names[{1, 2}] << '\n';
}
```

相等的键必须得到相同的哈希值；否则容器可能无法找到已经插入的元素。哈希函数不要求不同键一定产生不同结果，因为冲突是允许的，但应尽量让元素分布均匀。

### 6. 有序容器的比较器：只要满足“严格弱序”

有序容器默认使用 `std::less<Key>`，通常就是“小于”比较。如果传入自定义比较器，它必须建立一致的排序关系：不能出现 `a` 小于 `b`、同时 `b` 又小于 `a` 的情况，也不能在比较过程中修改对象。

```cpp
#include <iostream>
#include <set>

struct Descending {
    bool operator()(int left, int right) const {
        return left > right; // 返回 true 表示 left 应排在 right 前面
    }
};

int main() {
    std::set<int, Descending> numbers{1, 3, 2};
    for (int number : numbers) {
        std::cout << number << ' '; // 3 2 1
    }
}
```

比较器决定的不只是显示顺序，还决定容器认为什么叫“等价键”：如果 `comp(a, b)` 和 `comp(b, a)` 都是 `false`，有序容器就会把它们视为等价，即使 `a == b` 不一定为 `true`。

### 7. 常见操作和复杂度

| 操作 | `map` / `set` | `unordered_map` / `unordered_set` | 新手提示 |
| --- | ---: | ---: | --- |
| `find` / 插入 / 删除 | `O(log n)` | 平均 `O(1)`，最坏可能 `O(n)` | 无序容器不保证顺序 |
| `lower_bound` | `O(log n)` | 不提供此操作 | 需要按范围查找时选有序容器 |
| `begin()` 到 `end()` 遍历 | 按键有序 | 顺序不固定 | 不要拿无序遍历结果直接做展示排序 |
| 已知迭代器的 `erase` | 摊销 `O(1)`（查找位置另计） | 平均 `O(1)`（查找位置另计） | `erase` 后被删迭代器失效 |

有序容器还提供 `lower_bound(key)` 和 `upper_bound(key)`：前者找到“不小于 key”的第一个位置，后者找到“大于 key”的第一个位置。它们适合做排名、分段和范围查询；无序容器没有“下一个更大键”的概念，因此不能提供这类操作。

### 8. 迭代器失效与安全删除

- `map`、`set`、`multimap`、`multiset` 插入新元素通常不会让已有元素的迭代器失效。
- 删除时，只有指向被删元素的迭代器失效；其他元素的迭代器通常仍然有效。
- 无序容器插入时如果触发重新分桶，迭代器可能全部失效；删除通常只使被删元素的迭代器失效。
- 无论哪种容器，调用 `erase(it)` 后都不能再解引用旧的 `it`。

遍历并删除时，使用 `erase` 返回的下一个迭代器：

```cpp
#include <iostream>
#include <map>

int main() {
    std::map<std::string, int> scores{{"Alice", 90}, {"Bob", 55}, {"Cindy", 72}};

    for (auto it = scores.begin(); it != scores.end();) {
        if (it->second < 60) {
            it = scores.erase(it); // 返回下一个元素；不要在这里再递增 it
        } else {
            ++it;
        }
    }
}
```

### 9. 如何选择关联容器

可以按下面的顺序判断：

1. 只需要“值是否存在”吗？是：选择 `set` 或 `unordered_set`。
2. 需要通过键找到对应值吗？是：选择 `map` 或 `unordered_map`。
3. 一个键是否可以对应多条记录？是：选择 `multi` 容器，或 `map<Key, vector<Value>>`。
4. 是否需要按键排序、`lower_bound`、范围遍历？是：选择有序容器。
5. 是否只关心快速的单键查找，不需要顺序？可以选择无序容器。
6. 键类型是否有合适的哈希函数？没有的话，先使用有序容器，或为自定义类型补充哈希和相等比较。

没有明确证据时，`map` 和 `unordered_map` 都是合理起点：需要稳定排序就选 `map`，只需要快速查找就选 `unordered_map`。最终还应根据数据规模、键分布和实际性能测试决定，而不是只背复杂度表。

## 示例与实践

### 综合示例：统计单词频率并按字母顺序输出

这个例子展示了 `map` 的典型用途：每个单词是键，出现次数是值。使用 `operator[]` 做计数很方便，因为第一次遇到新单词时，计数会自动从 0 开始。

```cpp
#include <iostream>
#include <map>
#include <string>
#include <vector>

int main() {
    std::vector<std::string> words{
        "cpp", "map", "cpp", "set", "map", "cpp"
    };
    std::map<std::string, int> frequency;

    for (const std::string& word : words) {
        ++frequency[word]; // 新键默认得到 0，再加 1；已有键直接累加
    }

    // map 按字符串升序遍历，因此输出天然是按字母顺序排列。
    for (const auto& [word, count] : frequency) {
        std::cout << word << ": " << count << '\n';
    }
}
```

如果把上面的 `map` 换成 `unordered_map`，统计逻辑仍然成立，但输出顺序不再固定；如果只想统计出现过哪些不同单词，则可以改用 `set<std::string>`。
