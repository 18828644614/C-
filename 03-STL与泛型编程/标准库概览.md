# 标准库概览

## 学习目标
- [ ] 了解 C++ 标准库是什么，以及它与 STL、第三方库和 Windows API 的区别。
- [ ] 能根据任务找到合适的标准库头文件，并正确使用 `std::` 命名空间中的类型和函数。
- [ ] 理解“容器保存数据、迭代器表示区间、算法处理区间”的基本协作方式。
- [ ] 对字符串、视图、智能指针、时间、文件系统、随机数、并发和错误处理等常用模块有整体认识。
- [ ] 能在 Windows 环境中使用 C++17 编译并运行一个使用多个标准库组件的程序。

## 要点

### 1. 什么是 C++ 标准库

C++ 语言本身规定了语法和语言规则，例如变量、函数、类、模板、继承和异常；标准库则是一组由 C++ 标准规定接口和行为的现成组件，例如 `std::vector`、`std::string`、`std::sort` 和 `std::thread`。标准库通常随编译器一起安装，使用它不需要自己下载一个额外的“STL 安装包”。

这里要区分三个容易混淆的说法：

| 名称 | 含义 | 例子 |
| --- | --- | --- |
| C++ 标准库 | C++ 标准规定的完整库组件集合 | 输入输出、容器、算法、时间、文件系统、并发等 |
| STL | 最初以“标准模板库”著称的一组泛型组件，今天通常特指容器、迭代器和算法这一核心部分 | `std::vector`、`std::map`、`std::sort` |
| 第三方库 | 标准之外，由个人、社区或公司维护的库 | Boost、Qt、Eigen、OpenCV |

因此，STL 是标准库的重要组成部分，但“标准库”不等于“只有 STL”。例如，`std::filesystem`、`std::chrono` 和 `std::thread` 通常不被狭义地称为 STL 容器算法组件，却都是标准库的一部分。

标准库也不同于 Windows API。Windows API 是 Windows 操作系统提供的平台接口，例如窗口、注册表、进程和文件句柄等功能；标准库则追求跨平台的 C++ 接口。实际项目经常同时使用二者：先用标准库处理字符串、容器和业务逻辑，在必须调用系统能力的边界处再使用 Windows API。能用标准库解决的问题，优先使用标准库通常更容易测试和移植。

标准库的实现由编译器工具链提供。例如 Visual Studio 常用 Microsoft 的实现，MinGW 常用 GCC 的 libstdc++，Clang 常用 libc++ 或与平台配套的实现。不同实现负责内部代码，但对外应遵守同一个 C++ 标准接口。我们通常只需要学习标准接口，而不应依赖某个实现的内部文件或未规定行为。

### 2. 头文件、命名空间与编译标准

标准库组件按功能分布在头文件中。使用哪个组件，就应该显式包含相应的头文件：

```cpp
#include <algorithm>  // std::sort、std::find、std::count_if 等算法
#include <iostream>   // std::cout、std::cin
#include <vector>     // std::vector

int main() {
    std::vector<int> numbers{3, 1, 2};
    std::sort(numbers.begin(), numbers.end());

    for (int number : numbers) {
        std::cout << number << '\n';
    }
}
```

`std::` 中的 `std` 是标准库命名空间（namespace）。标准库把自己的名字放入 `std`，是为了减少与用户代码重名的机会。因此初学阶段建议始终写出 `std::vector`、`std::cout` 这样的完整名称。

不要在头文件中写 `using namespace std;`。这会把大量名字引入当前作用域，容易造成重名，尤其是在大型项目中。即使在 `.cpp` 文件中，也通常推荐保留 `std::`；如果确实想简化书写，可以只引入单个名字，例如 `using std::string;`，但要清楚它会影响当前作用域。

还要注意：某个头文件“碰巧”间接包含了另一个头文件，并不代表这种间接包含是标准保证的。代码使用 `std::sort` 就应包含 `<algorithm>`，使用 `std::accumulate` 就应包含 `<numeric>`。这样代码更稳定，也更容易看懂。

标准库功能会随 C++ 标准版本增加。编译器默认使用的语言版本不一定是你想要的版本，所以应明确指定：

| 工具 | C++17 编译示例 |
| --- | --- |
| Visual Studio 的开发者 PowerShell | `cl /std:c++17 /EHsc main.cpp /Fe:main.exe` |
| MinGW g++ | `g++ -std=c++17 -Wall -Wextra -pedantic main.cpp -o main.exe` |
| CMake | `set(CMAKE_CXX_STANDARD 17)` 并设置 `CMAKE_CXX_STANDARD_REQUIRED ON` |

在 Visual Studio 图形界面中，可以在“项目属性 → C/C++ → 语言 → C++ 语言标准”中选择 `/std:c++17` 或更高版本。编译后在 PowerShell 中运行当前目录下的程序通常写成 `./main.exe`，也可以写成 `.\main.exe`。

### 3. 标准库按功能如何分类

下面的分类是为了建立地图。各章节后续还会分别深入介绍容器、迭代器和算法。

| 功能类别 | 常见头文件 | 常用组件 | 解决的问题 |
| --- | --- | --- | --- |
| 输入输出 | `<iostream>`、`<fstream>`、`<sstream>` | `std::cout`、`std::ifstream`、`std::stringstream` | 控制台、文件和内存字符串的读写 |
| 顺序容器 | `<vector>`、`<array>`、`<deque>`、`<list>` | `std::vector`、`std::array` | 按顺序保存一组元素 |
| 关联容器 | `<map>`、`<set>`、`<unordered_map>`、`<unordered_set>` | `std::map`、`std::set` | 按键查找、去重和维护键值关系 |
| 容器适配器 | `<stack>`、`<queue>` | `std::stack`、`std::queue`、`std::priority_queue` | 以特定规则限制底层容器的操作 |
| 算法与迭代器 | `<algorithm>`、`<iterator>`、`<numeric>` | `std::sort`、`std::copy`、`std::accumulate` | 对一段元素进行查找、排序、变换和统计 |
| 字符串与范围 | `<string>`、`<string_view>`、`<ranges>` | `std::string`、`std::string_view`、`std::ranges` | 表示文本、非拥有视图和惰性数据处理管道 |
| 通用工具 | `<utility>`、`<tuple>`、`<optional>`、`<variant>`、`<any>` | `std::move`、`std::pair`、`std::optional` | 组织返回值、表达可选值和多种类型 |
| 动态内存与资源 | `<memory>` | `std::unique_ptr`、`std::shared_ptr`、`std::weak_ptr` | 表达动态对象的所有权和生命周期 |
| 时间与日期 | `<chrono>` | `std::chrono::duration`、`std::chrono::steady_clock` | 表示时间、计时和计算时间间隔 |
| 文件系统 | `<filesystem>` | `std::filesystem::path`、`exists`、`directory_iterator` | 处理路径、目录和文件属性 |
| 随机数与数学 | `<random>`、`<cmath>`、`<numeric>` | `std::mt19937`、`std::uniform_int_distribution` | 生成随机数和执行数值计算 |
| 并发 | `<thread>`、`<mutex>`、`<future>`、`<atomic>` | `std::thread`、`std::mutex`、`std::async` | 创建线程、同步共享数据和异步执行 |
| 错误处理 | `<exception>`、`<stdexcept>`、`<system_error>` | `std::exception`、`std::runtime_error`、`std::error_code` | 报告异常、系统错误和可检查的失败 |

表中的组件只是常见入口，不是完整清单。查阅文档时，应先从“功能”反推头文件和类型，而不是凭记忆猜一个名字。例如，需要保存可变长度的连续数据时先想到 `std::vector`；需要按键查找时再比较 `std::map` 和 `std::unordered_map`。作为粗略的复杂度印象，`map` 的查找、插入和删除通常是 `O(log n)`，无序容器在分布良好时平均接近 `O(1)`，但最坏情况可能退化到 `O(n)`；实际性能还会受到元素类型、哈希函数和数据规模影响。

### 4. 最重要的协作模型：容器、迭代器和算法

STL 的核心思想可以概括为：

> 容器负责保存数据，迭代器负责表示数据范围，算法负责处理范围。

例如，`std::vector<int>` 知道如何管理一组整数；`begin()` 和 `end()` 提供这组元素的起点和终点；`std::sort` 只要求传入一对满足条件的迭代器，因此它不需要知道底层一定是 `vector`。

标准库算法最常见的参数形式是半开区间 `[first, last)`：包含 `first` 指向的元素，但不包含 `last` 指向的元素。容器的 `end()` 指向“最后一个元素的下一个位置”，它可以用于比较和表示结束，但不能解引用。

```cpp
#include <algorithm>
#include <iostream>
#include <vector>

int main() {
    std::vector<int> numbers{5, 2, 4, 1};

    // sort 处理 [begin(), end())，也就是整个 vector
    std::sort(numbers.begin(), numbers.end());

    // end() 只是尾后位置，不能写 *numbers.end()
    for (auto it = numbers.begin(); it != numbers.end(); ++it) {
        std::cout << *it << ' ';  // 解引用迭代器，访问当前元素
    }
    std::cout << '\n';
}
```

区间循环 `for (int value : numbers)` 是更易读的遍历方式；需要把范围传给算法时，仍然经常使用 `begin()` 和 `end()`。C++20 增加了 ranges 算法，例如 `std::ranges::sort(numbers)`，可以减少迭代器书写，但它并没有改变“算法处理一段元素”的基本思想。

算法通常通过迭代器访问元素，而不是通过容器的成员函数完成所有工作。这带来了复用性：`std::find` 可以用于 `vector`、数组和其他提供合适迭代器的范围。但不同算法对迭代器能力的要求不同：`std::sort` 需要随机访问迭代器，不能直接用于 `std::list`；`std::find` 的要求则低得多。算法的复杂度也很重要，例如线性查找通常是 `O(n)`，排序通常是 `O(n log n)`。

### 5. 选择容器时先问什么问题

初学者常常只记“哪个容器更快”，但容器没有脱离场景的绝对排名。可以按下面顺序思考：

1. 是否需要按下标快速访问？通常优先考虑 `std::vector`；固定长度且长度在编译期确定时可考虑 `std::array`。
2. 是否频繁在两端插入和删除？可以考虑 `std::deque`。
3. 是否需要按键查找并保持有序？考虑 `std::map` 或 `std::set`；只关心平均快速查找而不需要顺序时，可以考虑无序容器。
4. 是否只需要先进先出、后进先出或优先级操作？考虑 `std::queue`、`std::stack` 或 `std::priority_queue`。
5. 是否真的需要在中间位置频繁插入和删除，并且已经持有目标位置的迭代器？`std::list` 有其适用场景，但它节点分散、缓存局部性较差，不应因为“插入是常数时间”就默认选择它。若还要先在线性链表中查找位置，查找本身仍然是 `O(n)`。

在没有特殊理由时，`std::vector` 往往是很好的默认选择：元素连续存储、遍历快、与许多 C 风格接口容易互操作。这里的“连续”表示元素通常紧挨着存储，而不是说 `vector` 的容量永远不会改变。

容器的 `size()` 和 `capacity()` 也容易混淆：

- `size()` 是当前实际拥有的元素个数。
- `capacity()` 是当前已分配空间在不重新分配的情况下最多能容纳的元素个数。
- `reserve(n)` 只请求至少容纳 `n` 个元素的容量，不会增加 `size()`，也不会创建元素。
- `resize(n)` 会改变 `size()`；变大时会新增元素，变小时会销毁多余元素。

```cpp
#include <iostream>
#include <vector>

int main() {
    std::vector<int> values;
    values.reserve(10);       // 预留空间，但此时仍然没有元素
    std::cout << values.size() << '\n';  // 输出 0

    values.push_back(42);     // 现在才真正添加一个元素
    values.resize(3);         // 变成 3 个元素，新元素进行值初始化
    std::cout << values.size() << '\n';  // 输出 3
}
```

### 6. 所有权、生命周期与“拥有数据”

标准库类型不一定都拥有它们所指向的数据，这是使用现代 C++ 时必须建立的意识：

- `std::vector` 和 `std::string` 通常拥有自己的元素或字符，销毁对象时会释放自己管理的资源。
- 迭代器、指针、引用和 `std::string_view` 通常只是访问已有对象，不负责延长对象寿命。
- `std::unique_ptr` 表示独占所有权；`std::shared_ptr` 表示共享所有权；`std::weak_ptr` 观察共享对象但不拥有它。

例如，下面的视图指向一个已经被销毁的临时字符串，使用 `view` 会产生悬空引用，属于未定义行为：

```cpp
// 错误示例：不要这样返回
std::string_view bad_view() {
    std::string text = "temporary";
    return text;  // text 离开函数后销毁，返回的 view 不再有效
}
```

正确做法之一是返回拥有数据的 `std::string`；如果调用方保证原字符串在视图使用期间一直存在，也可以传入一个长期存活的字符串并构造视图。判断一个对象是否安全，不能只看类型名称，还要追踪它引用的对象何时创建、何时销毁以及是否发生了重新分配。

### 7. 迭代器失效：容器变化后不要盲目继续使用旧迭代器

当容器改变内部存储时，原来的迭代器、指针或引用可能失效。以 `std::vector` 为例，扩容时通常会把元素搬到新地址，扩容前得到的迭代器就不能继续使用。即使没有扩容，删除元素也可能使被删除位置及其后的迭代器失效。

```cpp
std::vector<int> values{1, 2, 3};
auto it = values.begin();
values.push_back(4);
// 错误：push_back 可能扩容，it 可能已经失效
// std::cout << *it;
```

这不是“迭代器自动跟踪元素”的问题，而是迭代器往往包含地址或能够定位地址的信息。修改容器后，应查阅该容器对应操作的失效规则；如果算法返回了新的迭代器，也应使用返回值。例如 `erase` 常会返回删除位置之后仍可使用的迭代器。

### 8. 字符串、视图和编码

`std::string` 是拥有一串 `char` 的对象，但标准并没有规定它一定使用 UTF-8；它更准确地说是一个字节序列。Windows 控制台、源文件编码、字体和终端设置可能导致中文显示乱码，这属于编码或输出环境问题，不是 `std::string` 自动完成了 Unicode 转换。

`std::wstring` 使用 `wchar_t`，在 Windows 上常用于与某些宽字符 API 交互，但它也不是跨平台统一的 Unicode 解决方案。新代码应根据项目的编码约定选择表示方式，并明确边界处如何转换。

`std::string_view` 只保存一段字符的地址和长度，不拥有字符。它适合把只读字符串传给函数，避免不必要的复制，但使用前必须确保原字符串仍然存活且没有因扩容而搬家。它通常适合作为函数的只读参数，不适合作为长期保存而不加生命周期说明的成员变量。

### 9. 工具类型：让接口表达更准确

标准库提供了许多小而通用的类型，用来表达程序中的状态：

- `std::pair` 和 `std::tuple` 可以组合多个值，但成员缺少业务语义，复杂返回值通常应优先考虑命名结构体。
- `std::optional<T>` 表示“可能有一个 `T`，也可能没有”，适合查找失败、配置项缺省等情况。
- `std::variant<A, B>` 表示“当前是这些类型中的一种”，访问时必须处理类型分支。
- `std::any` 可以容纳任意可复制类型，但类型检查和运行时开销更高，不能把它当作没有代价的万能变量。
- `std::move` 只是把表达式转换成右值引用，允许重载函数选择移动版本；它本身不搬运数据，也不会自动销毁原对象。

这些类型的价值不只是“少写几行代码”，更在于把接口约束表达出来。例如返回 `std::optional<int>` 比返回特殊数字 `-1` 更清晰，因为 `-1` 可能本来就是合法结果。

### 10. 输入输出、时间、文件系统和随机数

标准库的输入输出流通过类型安全的运算符读写数据。`std::ifstream` 打开文件后应检查是否成功；不要把“文件不存在”当作程序一定会抛异常，因为流默认通常通过状态位表示失败，除非显式配置异常。

`std::filesystem::path` 专门表示路径，比手工用字符串拼接路径更合适。路径分隔符、绝对路径和相对路径在不同系统上有差异，使用 `path` 的 `/` 运算符组合路径通常比直接拼接字符串可靠。Windows 下可以使用 `std::filesystem::path{L"..."}` 或普通窄字符串，具体取决于项目编码和 API 边界。

计时应优先使用 `<chrono>` 的时钟和 duration，而不是手动把 `clock()` 的数值当作毫秒。测量经过时间时通常使用 `std::chrono::steady_clock`，因为它不会因系统时间校准而倒退；显示当前日期时间则可考虑 `system_clock`。

需要随机数时，优先使用 `<random>` 中的“引擎 + 分布”模型，例如 `std::mt19937` 配合 `std::uniform_int_distribution<int>`。`std::rand()` 历史悠久且质量和接口都有限，不适合需要可靠随机性的场景；密码学安全随机数还需要专门的安全方案，不能把普通随机引擎当作密码学工具。

### 11. 错误处理与资源安全

标准库中常见的失败表达方式有三类：

1. 返回布尔值、迭代器或 `std::optional`，表示调用方应检查结果。
2. 抛出异常，例如 `std::out_of_range` 或 `std::runtime_error`，表示正常返回值无法或不适合携带错误。
3. 使用 `std::error_code`，让调用方显式检查错误而不必依赖异常，文件系统等接口常提供这种重载。

选择哪一种取决于接口约定。无论采用哪种方式，都要避免“检查了失败却继续使用无效结果”。RAII 是标准库资源管理的重要基础：对象构造时取得资源，析构时释放资源，因此应优先使用 `std::vector`、流对象和智能指针等自动管理资源的类型，而不是手写 `new`/`delete`。

### 12. 并发与线程安全的基本边界

`std::thread` 可以创建线程，`std::mutex` 和 `std::lock_guard` 可以保护共享数据，`std::future`/`std::async` 可以表达异步结果，`std::atomic` 可以对适合的简单共享状态提供原子操作。

但“使用标准库类型”不代表程序自动线程安全。多个线程同时读取同一个对象通常比一边写一边读安全；只要有并发写入，或者一个线程修改容器、另一个线程遍历它，就需要设计同步。锁的作用是保护共享不变量，不能只凭感觉到处加锁；锁的生命周期也应使用 RAII 类型管理，避免异常路径忘记解锁。

## 示例与实践

### 1. Windows 下编译并运行第一个标准库程序

将下面内容保存为 `main.cpp`。示例只使用标准 C++，没有调用 Windows 专有 API，因此在 Visual Studio、MinGW 和其他支持 C++17 的编译器中都可以使用。代码中的注释说明了每个标准库组件在程序中的角色。

```cpp
#include <algorithm>  // std::sort、std::count_if、std::transform
#include <iomanip>    // std::fixed、std::setprecision
#include <iostream>   // std::cout
#include <numeric>    // std::accumulate
#include <optional>   // std::optional、std::nullopt
#include <string>     // std::string
#include <string_view> // std::string_view
#include <vector>     // std::vector

struct Student {
    std::string name;
    int score;
};

// 没有成绩时返回“没有结果”，而不是约定一个容易冲突的特殊数字。
std::optional<double> average_score(const std::vector<Student>& students) {
    if (students.empty()) {
        return std::nullopt;
    }

    const int total = std::accumulate(
        students.begin(), students.end(), 0,
        [](int sum, const Student& student) {
            return sum + student.score;
        });

    return static_cast<double>(total) / students.size();
}

void print_title(std::string_view title) {
    // string_view 不拥有 title；本函数只在调用期间读取它。
    std::cout << "=== " << title << " ===\n";
}

int main() {
    std::vector<Student> students{
        {"Alice", 88},
        {"Bob", 73},
        {"Carol", 95},
        {"David", 61},
    };

    print_title("Student scores");

    // 算法只接收一对迭代器，不需要知道数据来自哪种容器。
    std::sort(students.begin(), students.end(),
              [](const Student& left, const Student& right) {
                  return left.score > right.score; // 按成绩从高到低
              });

    // count_if 根据条件统计元素个数。
    const auto passed = std::count_if(
        students.begin(), students.end(),
        [](const Student& student) {
            return student.score >= 60;
        });

    // transform 把一个范围转换成另一个范围；这里先准备足够大的目标容器。
    std::vector<std::string> names(students.size());
    std::transform(students.begin(), students.end(), names.begin(),
                   [](const Student& student) {
                       return student.name;
                   });

    for (const auto& student : students) {
        std::cout << student.name << ": " << student.score << '\n';
    }

    std::cout << "Passed: " << passed << '\n';
    std::cout << "Names: ";
    for (const auto& name : names) {
        std::cout << name << ' ';
    }
    std::cout << '\n';

    const auto average = average_score(students);
    if (average.has_value()) {
        std::cout << std::fixed << std::setprecision(2)
                  << "Average: " << *average << '\n';
    } else {
        std::cout << "Average: no data\n";
    }
}
```

在 Windows 的 Visual Studio Developer PowerShell 中可以执行：

```powershell
cl /std:c++17 /EHsc main.cpp /Fe:main.exe
.\main.exe
```

如果使用 MinGW：

```powershell

.\main.exe
```

预期输出的顺序是 Carol、Alice、Bob、David，因为程序按成绩降序排序；通过人数是 4，平均分是 79.25。程序输出使用英文名称，是为了避免 Windows 终端代码页影响初学者判断程序逻辑；源代码中的中文注释不影响程序运行。

这个例子值得按数据流重新读一遍：`vector` 拥有 `Student` 数据，`begin()`/`end()` 表示整个范围，`sort` 改变范围内的顺序，`count_if` 读取范围并统计，`transform` 生成另一组数据，`optional` 表达平均分可能不存在，`string_view` 让标题函数以只读、非拥有方式接收字符串。

### 2. 一个简单的文件系统例子

下面的程序展示标准库如何处理 Windows 路径。它不会依赖固定的盘符；运行时使用当前工作目录，并只检查当前目录是否存在，因此更容易在不同电脑上复现。

```cpp
#include <filesystem>
#include <iostream>

int main() {
    namespace fs = std::filesystem;

    // current_path() 是程序启动时的当前工作目录，不一定是 exe 所在目录。
    const fs::path current = fs::current_path();

    std::cout << "Current directory: " << current.string() << '\n';
    std::cout << "Directory exists: "
              << (fs::is_directory(current) ? "yes" : "no") << '\n';

    // path 的 / 运算符用于拼接路径，避免手工处理反斜杠。
    const fs::path example = current / "example.txt";
    std::cout << "Example path: " << example.string() << '\n';
}
```

如果要访问用户输入的路径，实际程序还应检查权限、路径是否存在以及操作是否抛出异常。`current_path()` 与相对路径受“当前工作目录”影响，在 Visual Studio 中直接运行和在 PowerShell 中运行时，工作目录可能不同；这也是文件路径问题中很常见的原因。

### 3. 常见错误对照

#### 错误一：忘记包含使用到的头文件

```cpp
// 错误：直接使用 std::sort，却没有 #include <algorithm>
std::sort(numbers.begin(), numbers.end());
```

修正方法是补上 `#include <algorithm>`。不要依赖其他头文件的“顺带包含”，因为库实现或版本变化后这种代码可能突然无法编译。

#### 错误二：把 `end()` 当成最后一个元素

```cpp
// 错误：end() 指向尾后位置，不能解引用
// std::cout << *numbers.end();

// 正确：最后一个元素的位置是 end() 的前一个位置，但要先确认不为空
if (!numbers.empty()) {
    std::cout << numbers.back();
}
```

`end()` 的设计让空范围也能统一表示为 `[begin(), end())`；当容器为空时，`begin()` 和 `end()` 相等，但二者都不能解引用。

#### 错误三：以为 `reserve` 会创建元素

```cpp
std::vector<int> values;
values.reserve(5);
// 错误：reserve 只分配容量，values[0] 仍不是一个存在的元素
// values[0] = 10;

// 正确：使用 push_back 添加元素，或使用 resize 后再通过下标访问
values.push_back(10);
```

#### 错误四：保存了失效的迭代器或视图

如果一个 `std::string_view` 指向局部 `std::string`，或者一个 `vector` 扩容后继续使用扩容前获得的迭代器，就可能访问已经无效的地址。遇到容器修改、返回视图或保存引用时，要把生命周期问题和类型选择一起考虑。

#### 错误五：用 `using namespace std;` 掩盖名字来源

初学者看到 `vector<int>` 可能不知道它来自哪里。写成 `std::vector<int>` 虽然多了五个字符，却清楚表达了类型属于标准库，也能减少与自定义 `vector`、`count` 等名字冲突的机会。

#### 错误六：用 `std::endl` 代替所有换行

`std::endl` 会换行并强制刷新输出缓冲区；普通日志输出通常只需要 `\n`，不必每行都强制刷新。需要立刻让用户看到进度，或确实需要刷新时再使用 `std::endl` 或显式刷新。

#### 错误七：把标准库当成线程安全容器

标准容器通常不允许一个线程修改、另一个线程无同步地读取同一对象。即使每个成员函数单独看起来正常，组合起来也可能产生数据竞争。并发代码需要明确共享状态、同步方式和对象生命周期。

### 4. 建议的学习顺序

可以按照“先会用，再理解抽象”的顺序学习：

1. 先掌握 `std::string`、`std::vector`、范围 `for` 和基本输入输出。
2. 学习迭代器的 `[begin, end)` 区间约定，再学习 `find`、`count_if`、`sort`、`copy`、`transform` 等算法。
3. 对比 `vector`、`deque`、`list`、`map`、`set`、无序容器的操作特点和复杂度。
4. 学习 Lambda、`optional`、智能指针、`chrono`、`filesystem` 等现代工具。
5. 最后进入线程、锁、原子操作、异常安全和性能分析，把“能编译”提升为“生命周期正确、复杂度合理、并发安全”。

阅读标准库代码时，建议同时问四个问题：这个类型是否拥有资源？这个操作的复杂度是多少？操作后哪些迭代器或引用可能失效？失败是通过返回值、异常还是错误码表达的？这四个问题能帮助你从“记 API”逐步过渡到“理解设计”。
