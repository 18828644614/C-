# 线程与任务

## 学习目标

- [ ] 知道线程和任务分别解决什么问题。
- [ ] 能使用 `std::thread` 启动线程，并正确使用 `join()` 等待它结束。
- [ ] 能安全地向线程传递值、引用和多个参数，避免悬空引用。
- [ ] 能用 `std::async`、`std::future` 获取任务结果并处理异常。
- [ ] 了解 `std::jthread` 和 `stop_token` 的协作式停止（C++20）。
- [ ] 能识别数据竞争、未等待线程、随意 `detach()` 等常见错误。

## 一、先区分：线程是“人手”，任务是“工作”

可以把程序想象成一个厨房：

- **线程（thread）**是正在工作的厨师，负责执行指令；
- **任务（task）**是一份订单，例如“计算一张图片的缩略图”；
- 一个线程可以先后完成很多任务，一个任务也可以交给某个线程执行。

`std::thread` 让我们直接管理“哪个线程执行哪段函数”；`std::async` 则更关注“任务的结果何时准备好”，把线程调度细节交给标准库。初学时优先使用任务抽象，只有需要明确控制线程生命周期时才直接创建线程。

## 二、`std::thread`：启动、等待与生命周期

### 2.1 最小示例

```cpp
#include <chrono>
#include <iostream>
#include <thread>

void do_work(int id) {
    std::cout << "线程 " << id << " 开始工作\n";
    std::this_thread::sleep_for(std::chrono::milliseconds(100));
    std::cout << "线程 " << id << " 工作结束\n";
}

int main() {
    // 创建 thread 对象后，线程函数可能立刻在另一个执行流中运行。
    std::thread worker(do_work, 1);

    // join() 会阻塞当前线程，直到 worker 执行完。
    // 主线程不等待就离开 main，程序可能在线程还没做完时结束。
    worker.join();

    std::cout << "主线程继续执行\n";
}
```

`std::thread` 对象有一个重要规则：**析构时如果仍然处于 joinable 状态，程序会调用 `std::terminate()`**。因此，线程要么 `join()`，要么明确 `detach()`，不能什么都不做。

### 2.2 `join()`、`detach()` 和 `joinable()`

| 操作 | 含义 | 风险与建议 |
| --- | --- | --- |
| `join()` | 当前线程等待目标线程结束 | 最容易推理，默认优先选择 |
| `detach()` | 目标线程独立运行，`thread` 对象不再管理它 | 调用者必须保证所有捕获对象仍然存在；新手尽量少用 |
| `joinable()` | 检查是否仍有一个线程关联 | 在清理代码或异常处理路径中很有用 |

`detach()` 不是“安全的后台线程”。例如下面的引用会悬空：

```cpp
#include <iostream>
#include <string>
#include <thread>

void bad_detach() {
    std::string message = "hello";

    std::thread t([&message] {
        // bad_detach 返回后 message 已被销毁，这里再访问就是未定义行为。
        std::cout << message << '\n';
    });

    t.detach();
} // message 在这里销毁，分离线程可能还没开始运行
```

如果确实需要分离线程，至少让线程拥有自己的数据副本，并设计明确的程序退出策略：

```cpp
std::string message = "hello";
std::thread t([message] {
    // 按值捕获：线程闭包对象保存一份自己的字符串副本。
    std::cout << message << '\n';
});
t.detach();
```

不过，按值捕获只能解决数据生命周期，不能自动解决“程序退出时线程是否仍在访问文件、日志器或其他全局资源”的问题。能 `join()` 就不要 `detach()`。

### 2.3 线程函数的参数：默认会复制

```cpp
#include <iostream>
#include <string>
#include <thread>

void print_name(const std::string& name) {
    std::cout << name << '\n';
}

int main() {
    std::string name = "Alice";

    // std::thread 默认会把参数复制（或移动）到线程内部。
    // 这里即使 main 中的 name 后面改变，线程拿到的也是自己的副本。
    std::thread t(print_name, name);
    name = "Bob";
    t.join();
}
```

如果函数确实需要操作原对象，要用 `std::ref` 明确传递引用；同时必须保证引用对象在线程结束前一直存在：

```cpp
#include <functional>
#include <iostream>
#include <thread>

void add_one(int& value) {
    ++value;
}

int main() {
    int value = 0;
    std::thread t(add_one, std::ref(value)); // 不复制，传入 value 的引用
    t.join();                                // 先等待，再读取 value
    std::cout << value << '\n';
}
```

这里虽然没有数据竞争（主线程在 `join()` 前不读取 `value`），但如果多个线程同时读写 `value`，就必须使用 [[互斥、锁与条件变量]] 或原子操作。

### 2.4 线程对象不能复制，只能移动

```cpp
#include <utility>

std::thread first(do_work, 1);
// std::thread second = first;       // 错误：复制可能造成两个对象管理同一线程
std::thread second = std::move(first); // 线程的管理权转给 second

// first 现在不再关联线程；second 负责 join 或 detach。
second.join();
```

这和 [[左值、右值与移动语义]] 中的独占所有权很像：一个执行中的线程只能由一个 `std::thread` 对象负责管理。

## 三、异常安全：保证线程一定会被等待

如果线程创建后，主线程中途抛出异常，而清理路径没有 `join()`，`std::thread` 析构就会终止程序。一个简单的 RAII 包装器可以把等待动作放进析构函数：

```cpp
#include <thread>

class thread_guard {
public:
    explicit thread_guard(std::thread& thread) : thread_(thread) {}

    ~thread_guard() {
        // 析构函数不应抛异常；只要线程还可 join，就等待它结束。
        if (thread_.joinable()) {
            thread_.join();
        }
    }

    thread_guard(const thread_guard&) = delete;
    thread_guard& operator=(const thread_guard&) = delete;

private:
    std::thread& thread_;
};

void example() {
    std::thread worker([] { /* 执行工作 */ });
    thread_guard guard(worker);

    // 即使这里抛出异常，guard 析构时也会 join worker。
    // do_something_that_may_throw();
}
```

C++20 中的 `std::jthread` 已经内置了类似的自动等待行为，通常比手写 `thread_guard` 更方便。

## 四、`std::async` 与 `std::future`：把线程当成任务使用

### 4.1 获取返回值

线程函数本身不能直接向创建者返回结果；`std::async` 可以启动一个异步任务，并返回一个 `std::future<T>` 作为“将来会出现的 `T`”：

```cpp
#include <future>
#include <iostream>

int calculate_sum(int a, int b) {
    return a + b;
}

int main() {
    // std::launch::async 要求任务在异步线程中执行，而不是拖到 get() 才执行。
    auto result = std::async(std::launch::async, calculate_sum, 20, 22);

    std::cout << "主线程可以先做其他事情\n";

    // get() 会等待任务完成，并取出返回值。
    // 一个 future 通常只能成功调用一次 get()，因为结果会被移动出来。
    std::cout << result.get() << '\n'; // 输出 42
}
```

`std::launch::async` 和默认策略的区别很重要：默认策略允许实现自行选择“新线程”或“延迟到 `get()` 时执行”。需要确定并行执行时，显式写 `std::launch::async`。

最好保存返回的 `future`，不要直接丢弃：

```cpp
// 不推荐：临时 future 在这条语句结束时可能等待任务完成，
// 看起来“异步”，实际却可能立刻阻塞。
// std::async(std::launch::async, calculate_sum, 1, 2);

// 推荐：保存 future，稍后在合适的位置统一等待和取结果。
auto result = std::async(std::launch::async, calculate_sum, 1, 2);
```

这是因为 `future` 管理着任务的共享状态；任务仍在运行时，最后一个关联的 `future` 在销毁前可能需要等待异步函数结束。

### 4.2 任务中的异常会在 `get()` 重新抛出

```cpp
#include <future>
#include <iostream>
#include <stdexcept>

int risky_work() {
    throw std::runtime_error("任务失败");
}

int main() {
    auto result = std::async(std::launch::async, risky_work);

    try {
        result.get();
    } catch (const std::exception& error) {
        // 异常不会悄悄丢失，而是在 get() 处重新抛出。
        std::cout << "捕获到：" << error.what() << '\n';
    }
}
```

这正是任务抽象相对裸线程的便利之处：结果和异常都能通过同一个 `future` 传回调用者。使用 `std::thread` 时，需要自己设计结果存储、错误传递和同步方式。

### 4.3 `wait()`、`wait_for()` 和 `get()`

- `wait()`：只等待，不取出结果；
- `wait_for(duration)`：最多等待一段时间，返回 `ready`、`timeout` 或 `deferred`；
- `get()`：等待并取出结果，若任务抛异常则重新抛出。

```cpp
#include <chrono>
#include <future>
#include <thread>

int main() {
    auto result = std::async(std::launch::async, [] {
        std::this_thread::sleep_for(std::chrono::milliseconds(200));
        return 7;
    });

    if (result.wait_for(std::chrono::milliseconds(50)) ==
        std::future_status::timeout) {
        // 这里只说明“还没完成”，不是任务失败，也不是任务被取消。
    }
    int value = result.get();
    (void)value;
}
```

## 五、C++20：`std::jthread` 与协作式停止

### 5.1 自动 `join`

`std::jthread`（joining thread）离开作用域时会请求停止并自动 `join()`。它解决了忘记等待线程这一类常见错误：

```cpp
#include <chrono>
#include <iostream>
#include <thread>

void print_numbers() {
    for (int i = 0; i < 3; ++i) {
        std::cout << i << '\n';
        std::this_thread::sleep_for(std::chrono::milliseconds(10));
    }
}

int main() {
    std::jthread worker(print_numbers);
    // main 离开作用域时，worker 自动等待 print_numbers 结束。
}
```

### 5.2 停止是“请求”，不是强行杀死

C++ 没有可移植的“安全地立即杀死任意线程”接口。`stop_token` 采用协作式停止：一个线程发出请求，工作线程在合适的位置检查并自行收尾。

```cpp
#include <chrono>
#include <iostream>
#include <thread>

void worker(std::stop_token stop) {
    while (!stop.stop_requested()) {
        std::cout << "处理一批工作\n";
        std::this_thread::sleep_for(std::chrono::milliseconds(50));
    }

    // 检测到停止请求后，释放资源、保存状态，再正常返回。
    std::cout << "线程准备退出\n";
}

int main() {
    std::jthread thread(worker);
    std::this_thread::sleep_for(std::chrono::milliseconds(120));

    thread.request_stop(); // 只发出请求；worker 何时响应取决于它的检查点
} // jthread 仍会 join，确保 worker 真正结束
```

如果线程长时间阻塞在条件变量、文件或网络操作上，仅检查 `stop_requested()` 还不够，还需要让阻塞操作也能被唤醒。停止机制不是万能的超时机制，应结合任务自身的取消设计。

## 六、线程安全的基本边界

### 6.1 竞态条件与数据竞争不是同一个词

- **竞态条件（race condition）**：结果依赖执行时序，可能是设计层面的逻辑问题；
- **数据竞争（data race）**：多个线程并发访问同一内存位置，至少一个是写操作，且没有同步。数据竞争在 C++ 中属于未定义行为。

```cpp
int counter = 0;

// 两个线程同时执行 ++counter 并不安全。
// ++ 不是一个不可分割的动作，而是“读取、加一、写回”三个步骤。
```

应使用互斥量保护复合操作，或使用合适的 `std::atomic<int>`。具体选择见 [[互斥、锁与条件变量]] 和 [[原子操作与内存模型]]。

### 6.2 `std::cout` 的输出顺序不要想当然

多个线程同时输出时，单次插入通常不会让内存发生数据竞争，但多条输出可能交错，顺序也不确定。调试并发程序时，不要根据日志先后顺序推断真实执行顺序；必要时给日志加锁或使用线程安全的日志组件。

## 七、常见错误清单

1. **忘记 `join()` 或 `detach()`**：`std::thread` 析构时会调用 `std::terminate()`。
2. **分离线程捕获局部变量引用**：函数返回后引用可能悬空。
3. **以为 `join()` 会让线程“变成串行”**：它只是在某个同步点等待；多个线程仍可先启动，再分别等待。
4. **默认认为 `std::async` 一定新建线程**：默认启动策略允许延迟执行；需要并行时写 `std::launch::async`。
5. **把 `future::wait_for` 超时当成取消**：超时只表示结果尚未就绪，任务仍在运行。
6. **把 `volatile` 当成线程同步工具**：`volatile` 主要用于特殊硬件/信号场景，不能替代原子变量或互斥锁。
7. **共享对象却没有同步**：按值复制任务参数只能避免共享，不能让真正共享的数据自动安全。

## 示例与实践

### 1. 可运行示例：并行计算两个部分再合并

```cpp
#include <functional>
#include <future>
#include <iostream>
#include <numeric>
#include <vector>

int sum_range(const std::vector<int>& values, std::size_t begin,
              std::size_t end) {
    // 这里的 values 只读，因此两个任务可以安全共享同一个 vector。
    return std::accumulate(values.begin() + begin, values.begin() + end, 0);
}

int main() {
    const std::vector<int> values{1, 2, 3, 4, 5, 6};
    const auto middle = values.size() / 2;

    auto left = std::async(std::launch::async, sum_range,
                           std::cref(values), 0, middle);
    auto right = std::async(std::launch::async, sum_range,
                            std::cref(values), middle, values.size());

    // get() 同时承担等待、取值和传播异常三个职责。
    const int total = left.get() + right.get();
    std::cout << "总和 = " << total << '\n';
}
```
