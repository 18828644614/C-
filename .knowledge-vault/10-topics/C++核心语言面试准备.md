# C++核心语言面试准备

## 结论

第二章的面试主线是“对象状态、生命周期、所有权和可替换行为”：

- 用 `private`、构造函数和受控接口维护对象不变量；
- 用成员初始化列表、构造/析构顺序和特殊成员函数建立正确生命周期；
- 用 RAII、`unique_ptr`、`shared_ptr`、`weak_ptr` 和锁守卫表达资源所有权；
- 用 `virtual`、`override`、纯虚函数和虚析构函数实现安全的运行时多态；
- 用异常栈展开、异常安全保证和 `noexcept` 设计失败路径；
- 用运算符重载表达自然的值类型语义，而不是制造隐式行为。

## 面试重点地图

| 主题 | 面试官想验证什么 | 典型陷阱 |
| --- | --- | --- |
| 类与封装 | 能否维护不变量、区分接口和实现 | 把所有字段都公开，机械添加 setter |
| 构造与析构 | 是否理解初始化时机和逆序销毁 | 认为初始化列表顺序决定实际顺序 |
| 拷贝与移动 | 是否能表达资源复制、转移或禁止复制 | 裸指针浅拷贝导致重复释放 |
| RAII 与所有权 | 是否能覆盖 return、异常和多线程退出路径 | 把观察指针当成所有者 |
| 继承与多态 | 是否理解静态类型、动态类型和替换性 | 忘记 `virtual`、切片、非虚析构 |
| 异常安全 | 是否能保证资源和不变量 | `catch (...)` 吞错、析构抛异常 |
| 运算符重载 | 是否保持值语义、对称性和链式调用 | `operator+` 修改左值或返回悬空引用 |

## 关键判断规则

1. 如果类型拥有资源，优先让资源成为 RAII 成员，先考虑 Rule of 0。
2. 如果要通过基类指针销毁派生对象，基类析构函数必须是 `virtual`。
3. 如果要保留多态，接口通常使用基类引用、指针或智能指针，避免按基类值传递造成切片。
4. 如果操作失败时原状态必须不变，使用临时对象准备后再提交，争取强异常安全保证。
5. 如果只读成员函数不修改对象，应声明为 `const`；派生类实现虚函数应写 `override`。
6. 如果二元运算符左右对称，通常优先考虑非成员函数；修改左操作数的复合赋值通常返回 `T&`。
