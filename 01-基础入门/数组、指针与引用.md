# 数组、指针与引用

## 学习目标

- [ ] 理解数组在内存中的连续存储方式，并能安全地声明、初始化和遍历数组。
- [ ] 理解指针保存的是地址，掌握取地址、解引用、`nullptr` 和基本指针运算。
- [ ] 理解引用是对象的别名，知道它与指针的区别以及 `const` 引用的用途。
- [ ] 能识别数组越界、悬空指针、未初始化指针和返回局部对象地址等常见错误。
- [ ] 知道何时优先使用 `std::vector`、`std::string`、`std::array` 和 `std::span` 等现代 C++ 工具。

## 要点

## 1. 先建立一个简单的内存模型

程序运行时，变量通常对应内存中的一个**对象（object）**。对象有类型、值、大小和生命周期。可以把内存想象成许多连续编号的字节，每个对象占用其中的一段空间：

- **地址**：对象所占内存起始位置的编号，常用十六进制表示；
- **类型**：告诉编译器应当用多少字节、怎样解释这些字节；
- **值**：按照类型解释后得到的内容；
- **生命周期**：对象从开始存在到被销毁的时间段。

例如，`int score = 95;` 创建了一个 `int` 对象。表达式 `&score` 可以取得它的地址，类型是“指向 `int` 的指针”，写作 `int*`。如果有一个 `int*` 指针 `p`，表达式 `*p` 则表示“`p` 指向的那个 `int` 对象”。

~~~cpp
#include <iostream>

int main() {
    int score = 95;
    int* pointer = &score; // &：取得 score 的地址

    std::cout << "score 的值：" << score << '\n';
    std::cout << "score 的地址：" << pointer << '\n';
    std::cout << "通过指针读到的值：" << *pointer << '\n'; // *：解引用

    *pointer = 100; // 通过指针修改 score
    std::cout << "修改后 score：" << score << '\n';
}
~~~

地址每次运行都可能不同，不应把输出的具体地址当成固定结果。指针和引用都能间接访问对象，但它们表达的语义不同，后文会分别说明。

## 2. 数组：一组连续的同类型对象

### 2.1 声明、初始化与下标

数组把多个**相同类型**的元素按顺序存放在一段连续内存中。声明 `int scores[5];` 表示有 5 个 `int` 元素，编号（下标）从 `0` 到 `4`：

~~~cpp
#include <iostream>

int main() {
    int scores[5] = {90, 85, 92, 88, 76};

    std::cout << scores[0] << '\n'; // 第一个元素：90
    scores[4] = 80;                  // 修改第五个元素

    for (int i = 0; i < 5; ++i) {
        std::cout << "第 " << i << " 个元素：" << scores[i] << '\n';
    }
}
~~~

下标访问本质上是“从数组起始位置偏移若干个元素再访问”。因此有效下标一定是 `0 <= index < 元素个数`。访问 `scores[5]` 或 `scores[-1]` 都越过了数组边界，属于**未定义行为**：程序可能看似正常，也可能输出错误结果或直接崩溃，不能依赖任何一种表现。

常见初始化方式如下：

~~~cpp
int a[3] = {1, 2, 3}; // 全部显式初始化
int b[3] = {1};       // b[0] 为 1，其余元素为 0
int c[3]{};           // 所有元素初始化为 0
int d[] = {4, 5, 6};  // 省略长度，由初始值个数推导为 3
~~~

如果是函数内部的 `int a[3];`，元素不会自动清零，其中的值是不确定的；不要在写入前读取它们。具有静态存储期的数组（例如全局数组）会进行零初始化，但初学时不要靠这种差异“碰运气”。显式初始化更清楚。

### 2.2 遍历数组与元素个数

当只需要依次读取或修改元素时，范围 `for` 循环更不容易写错：

~~~cpp
#include <iostream>

int main() {
    int values[] = {2, 4, 6, 8};

    for (int value : values) {
        std::cout << value << ' ';
    }
    std::cout << '\n';

    for (int& value : values) {
        value *= 2; // 使用引用，直接修改数组元素
    }
}
~~~

在数组仍是“真正数组”的位置，可以使用 `sizeof` 计算元素个数：

~~~cpp
int values[] = {10, 20, 30, 40};
constexpr std::size_t count = sizeof(values) / sizeof(values[0]);
~~~

更推荐写成 `std::size(values)`（需要 `#include <iterator>`），它表达得更直接：

~~~cpp
#include <iterator>

int values[] = {10, 20, 30, 40};
const auto count = std::size(values);
~~~

这里的 `constexpr` 表示 `count` 必须在**编译期间**就能确定，并且初始化后不能修改。数组的大小在编译时已经确定，因此这个写法很合适：

~~~cpp
constexpr int fixed_value = 10; // 编译期常量
// fixed_value = 20;             // 错误：constexpr 变量不能修改
~~~

`std::size_t` 是标准库提供的、专门表示“大小、数量和索引”的无符号整数类型。`sizeof` 表达式的结果就是 `std::size_t`，所以用它保存数组元素个数很自然。使用它通常需要包含：

~~~cpp
#include <cstddef>

std::size_t count = 100;
~~~

`const` 和 `constexpr` 都表示变量不能修改，但侧重点不同：`const` 变量的值可以在运行时确定，而 `constexpr` 变量要求值在编译时就能确定：

~~~cpp
int get_value() {
    return 10;
}

const int runtime_value = get_value(); // 假设 get_value() 运行时才返回结果
constexpr int compile_time_value = 10; // 编译时就能确定
~~~

数组长度计算的原理是“整个数组占用的字节数 ÷ 一个元素占用的字节数”：如果 `values` 有 4 个 `int`，且每个 `int` 占 4 字节，那么 `sizeof(values)` 为 16，`sizeof(values[0])` 为 4，结果就是 4。

要注意，这种计算只适用于仍然是**真正数组**的表达式。数组传入函数后通常会转换成指针，此时 `sizeof(values)` 得到的是指针大小，而不是数组总大小；这也是推荐使用 `std::size(values)` 或 `std::span` 的原因之一。

注意：`sizeof` 只有在编译器仍然知道“这是一个数组”时才能得到整个数组大小；如果数组作为函数参数传递，情况会发生变化，见 2.4 节。

### 2.3 字符数组与 C 风格字符串

字符数组可以保存一串字符。以 `\0`（空字符，数值为 0）结尾的字符数组才是传统 C 风格字符串：

~~~cpp
#include <iostream>

int main() {
    char word[] = "cat"; // 实际占用 4 个 char：'c'、'a'、't'、'\0'
    std::cout << word << '\n';
}
~~~

`char word[3] = {'c', 'a', 't'};` 没有多余空间放 `\0`，它是字符序列而不是可直接交给 `std::cout` 的 C 风格字符串。忘记终止字符，或把字符串写入容量不足的数组，都会导致越界访问。新代码通常优先使用 `std::string`：

~~~cpp
#include <iostream>
#include <string>

int main() {
    std::string word = "cat"; // 自动管理长度和存储空间
    word += " dog";
    std::cout << word << '\n';
}
~~~

### 2.4 二维数组与数组参数

二维数组可以理解为“数组的数组”。`int table[2][3]` 有 2 行、每行 3 个元素，内存中仍是连续排列的：

~~~cpp
#include <iostream>

int main() {
    int table[2][3] = {{1, 2, 3}, {4, 5, 6}};

    for (int row = 0; row < 2; ++row) {
        for (int column = 0; column < 3; ++column) {
            std::cout << table[row][column] << ' ';
        }
        std::cout << '\n';
    }
}
~~~

把一维数组传给普通函数时，参数写成 `int values[]` 或 `int* values`，最终都会被调整为指针参数；函数不会自动知道元素个数。因此通常要把长度一起传入：

~~~cpp
#include <cstddef>
#include <iostream>

void print_values(const int values[], std::size_t count) {
    for (std::size_t i = 0; i < count; ++i) {
        std::cout << values[i] << ' ';
    }
    std::cout << '\n';
}

int main() {
    int values[] = {3, 1, 4};
    print_values(values, 3); // 数组传入函数时会转换为指向首元素的指针
}
~~~

二维数组参数必须保留除第一维以外的大小，例如 `void print(int table[][3], std::size_t rows)`；编译器需要知道每行跨过多少个元素，才能计算 `table[row][column]` 的地址。

如果希望函数既接收数组又保留其长度，可以使用 C++20 的 `std::span`。它是一个**不拥有数据**的连续内存视图：

~~~cpp
#include <iostream>
#include <span>

void print_values(std::span<const int> values) {
    for (int value : values) {
        std::cout << value << ' ';
    }
    std::cout << '\n';
}

int main() {
    int values[] = {3, 1, 4};
    print_values(values); // span 自动记录指针和元素个数
}
~~~

`std::span` 不会延长底层数组的生命周期。不能返回指向已经销毁的局部数组的 `span`，也不能让 `span` 比它所引用的数据活得更久。

### 2.5 数组与 `std::array`、`std::vector`

内置数组适合学习底层机制或与 C 接口交互，但它不能直接赋值、不能携带长度，传参时还容易退化为指针。现代 C++ 中可以按需求选择：

- `std::array<T, N>`：长度固定，但像普通对象一样可复制、可赋值，并提供 `.size()`；
- `std::vector<T>`：长度可动态变化，负责管理内存；
- `std::string`：专门表示文本；
- `std::span<T>`：只观察一段已有的连续数据，不拥有数据。

~~~cpp
#include <array>
#include <iostream>
#include <vector>

int main() {
    std::array<int, 3> fixed = {1, 2, 3};
    std::vector<int> dynamic = {4, 5};
    dynamic.push_back(6); // vector 可以自动扩容

    std::cout << "固定长度：" << fixed.size() << '\n';
    std::cout << "动态长度：" << dynamic.size() << '\n';
}
~~~

## 3. 指针：保存对象地址的变量

### 3.1 声明、取地址与解引用

指针也有类型。`int*` 只能指向 `int` 对象，`double*` 只能指向 `double` 对象（必要时还要考虑 `const`）。星号 `*` 在不同位置有两种常见含义：

~~~cpp
int* pointer = nullptr; // 声明一个“指向 int 的指针”
int value = 42;
pointer = &value;       // & 在表达式中表示“取得地址”
int copy = *pointer;    // * 在表达式中表示“解引用，访问所指对象”
~~~

解引用前必须保证指针指向一个仍然存在、类型匹配的对象。以下情况都不能解引用：

- 未初始化的指针，例如 `int* p;`；
- 空指针 `nullptr`；
- 已经释放对象后的悬空指针；
- 指向作用域已经结束的局部对象的指针；
- 经过错误类型转换得到的无效地址。

### 3.2 `nullptr` 与空指针检查

`nullptr` 表示“当前不指向任何对象”，类型是专门的空指针类型。它比旧式的整数 `0` 或宏 `NULL` 更安全：

~~~cpp
#include <iostream>

void set_zero(int* value) {
    if (value == nullptr) {
        return; // 调用者没有提供对象
    }
    *value = 0;
}

int main() {
    int number = 7;
    set_zero(&number);
    set_zero(nullptr); // 合法调用，但函数直接返回
    std::cout << number << '\n'; // 输出 0
}
~~~

`if (pointer)` 也可用于判断非空，但初学时写成 `pointer != nullptr` 更直观。检查一次并不代表对象的生命周期永远有效；如果对象随后被销毁，指针仍可能变成悬空指针。

### 3.3 指针运算与数组

数组元素连续存放，因此指向数组元素的指针可以做有限的加减运算。`p + 1` 会前进一个**元素**，不是只前进一个字节：

~~~cpp
#include <iostream>

int main() {
    int values[] = {10, 20, 30};
    int* begin = values;       // 数组名在此处转换为指向首元素的指针
    int* end = begin + 3;      // 可以指向“尾后位置”，但不能解引用

    for (int* current = begin; current != end; ++current) {
        std::cout << *current << ' ';
    }
    std::cout << '\n';
}
~~~

只有同一个数组（或同一数组的尾后位置）中的指针之间相减或比较才有明确意义。不能把指针运算当成任意内存访问手段，也不能解引用尾后指针。越过数组范围会导致未定义行为。

### 3.4 `const` 与指针：看清“谁不能改”

下面三种写法含义不同：

~~~cpp
int value = 1;
int other = 2;

const int* p1 = &value; // 不能通过 p1 修改 value；p1 可以改指向
p1 = &other;

int* const p2 = &value; // p2 的指向不能改变；可以通过 p2 修改 value
*p2 = 10;

const int* const p3 = &value; // 既不能改指向，也不能通过它修改对象
~~~

读声明时可从右向左理解：`p2` 先是一个 `const`（不可改的）指针，再指向 `int`；`p1` 是普通指针，但它指向的 `int` 视为只读。函数只读指针参数通常写成 `const int*`，并在文档中说明指针是否允许为空。

### 3.5 动态内存：了解机制，优先使用容器

`new` 在动态存储区创建对象并返回指针，`delete` 负责销毁单个对象；数组则必须配对使用 `new[]` 和 `delete[]`：

~~~cpp
int* number = new int(42);
delete number;
number = nullptr; // 删除后立即清空，避免继续误用

int* values = new int[3]{1, 2, 3};
delete[] values;
values = nullptr;
~~~

手写 `new`/`delete` 很容易出现内存泄漏、重复释放、释放后使用、`new[]` 与 `delete` 不匹配等错误。现代 C++ 通常优先使用 `std::vector` 管理动态数组，使用 `std::make_unique` 或 `std::make_shared` 表达对象所有权；相关内容见 [[智能指针]]。

## 4. 引用：对象的另一个名字

### 4.1 引用必须绑定到对象

引用声明中的 `&` 不表示“取得地址”，而是声明一个别名：

~~~cpp
#include <iostream>

int main() {
    int number = 10;
    int& alias = number; // alias 是 number 的另一个名字

    alias = 20;
    std::cout << number << '\n'; // 输出 20
}
~~~

引用必须在声明时初始化，不能绑定到 `nullptr`，也不能像指针那样稍后改为引用另一个对象：

~~~cpp
int first = 1;
int second = 2;
int& reference = first;
reference = second; // 这是把 second 的值赋给 first，不是改绑引用
~~~

引用通常不需要显式解引用，使用 `reference` 就是在使用 `first`。实现上编译器常用地址完成引用，但语言层面的语义是“别名”，不要据此假定引用一定占用某个固定大小或一定没有额外开销。

### 4.2 `const` 引用与临时对象

`const T&` 表示只读引用，常用于避免复制较大的对象：

~~~cpp
#include <iostream>
#include <string>

void print_name(const std::string& name) {
    // 不能修改 name，但不需要复制整段字符串
    std::cout << "你好，" << name << '\n';
}

int main() {
    std::string name = "小明";
    print_name(name);
    print_name("小红"); // const 引用可绑定到临时 string
}
~~~

普通的非常量引用 `T&` 不能绑定到字面量或临时对象，例如 `void change(int&); change(3);` 不合法，因为函数可能试图修改一个没有持久名字的临时值。`const T&` 可以延长某些临时对象的生命周期，但这种延长只在引用所处的有效范围内成立；不要从函数返回指向局部对象或临时对象的引用。

### 4.3 用引用传递参数和返回值

引用参数适合表达“调用者必须提供一个有效对象，而且函数可能修改它”：

~~~cpp
void increment(int& value) {
    ++value;
}
~~~

如果函数只读数据，优先考虑按值（小对象）或 `const T&`（较大对象）。返回引用时必须确认被引用对象在函数返回后仍然存在。下面的写法错误，因为 `local` 在函数返回时已经销毁：

~~~cpp
// 错误示例：不要返回局部变量的引用
int& wrong() {
    int local = 42;
    return local; // 悬空引用
}
~~~

通常按值返回最简单、最安全；现代 C++ 会尽量使用返回值优化。只有当对象由调用者或更长生命周期的所有者管理时，才考虑返回引用。

## 5. 数组、指针与引用的关系和区别

### 5.1 数组名不是指针，但常会“退化”为指针

数组和指针是两种不同的类型：数组包含全部元素，指针只保存一个地址。在大多数表达式中，数组名会自动转换为指向首元素的指针，这称为**数组到指针的转换（数组退化）**：

~~~cpp
int values[3] = {10, 20, 30};
int* pointer = values; // 等价于 &values[0]

// 但下面两者类型不同：
// values 是“含 3 个 int 的数组”，pointer 是“指向 int 的指针”。
~~~

数组退化有重要例外：`sizeof(values)`、`&values`，以及引用数组的场景中，数组不会退化。因此：

~~~cpp
int values[3] = {10, 20, 30};
static_assert(sizeof(values) == 3 * sizeof(int));
int (*whole_array)[3] = &values; // 指向整个数组的指针
~~~

`values + 1` 指向第二个元素；`&values + 1` 则会跳过整个数组，类型也不同。初学阶段最重要的是记住：传入函数后如果只剩 `int*`，函数就无法从指针本身推断数组长度。

### 为什么 `&values + 1` 会跳过整个数组

假设有一个数组：

~~~cpp
int values[3] = {10, 20, 30};
~~~

为了便于理解，假设一个 `int` 占 4 个字节，数组可能连续存放在如下位置：

~~~text
地址       内容
1000       values[0] = 10
1004       values[1] = 20
1008       values[2] = 30
~~~

在大多数表达式中，数组名 `values` 会转换为指向首元素的指针，因此：

~~~cpp
values
~~~

通常等价于：

~~~cpp
&values[0]
~~~

它的类型是 `int*`。所以：

~~~cpp
values + 1
~~~

表示向后移动一个 `int`，结果指向第二个元素：

~~~text
values       → 地址 1000
values + 1   → 地址 1004，即 values[1]
~~~

但是，`&values` 的含义不同。它取得的是**整个数组的地址**，而不是“第一个元素的地址”。它的类型是：

~~~cpp
int (*)[3]
~~~

这个类型读作“指向含有 3 个 `int` 的数组的指针”。因此，`&values + 1` 中的 `+1` 表示向后移动一个完整的 `int[3]` 数组，而不是一个 `int`：

~~~text
&values       → 地址 1000
&values + 1   → 地址 1012
~~~

这里的 1012 是按照示例中每个 `int` 占 4 字节计算的：整个数组占 `3 × 4 = 12` 个字节。C++ 的指针运算规则可以概括为：

> 指针加 1，移动一个“所指向类型”的大小。

所以：

~~~cpp
int* p1 = values;          // p1 指向一个 int
int* p2 = values + 1;      // 前进一个 int

int (*p3)[3] = &values;    // p3 指向一个 int[3] 数组
int (*p4)[3] = &values + 1; // 前进一个完整的 int[3] 数组
~~~

虽然 `values` 和 `&values` 的起始地址通常显示为同一个数值，但它们的类型不同，因此 `+1` 的移动距离不同：

| 表达式 | 类型 | `+1` 的含义 |
| --- | --- | --- |
| `values`（发生数组退化后） | `int*` | 前进一个 `int`，指向 `values[1]` |
| `&values` | `int (*)[3]` | 前进一个 `int[3]`，跳过整个数组 |

这种规则在二维数组中尤其有用：

~~~cpp
int table[2][3] = {
    {1, 2, 3},
    {4, 5, 6}
};

int (*row)[3] = table; // 指向第一行，所指类型是 int[3]
row + 1;               // 指向第二行，必须跳过一整行
~~~

`&values + 1` 指向整个数组之后的**尾后位置**。它可以用来表示范围的结束，但不能解引用或访问其中的元素：

~~~cpp
auto begin = &values;
auto end = &values + 1;

// end 只是尾后位置，不能写成 *end 来读取元素。
~~~

可以这样记忆：`values + 1` 是“下一项”，`&values + 1` 是“下一个完整数组”。决定移动距离的不是写法中的 `1`，而是指针所指向的类型。

### 5.2 `&` 和 `*` 为什么容易混淆

同一个符号在声明和表达式中作用不同：

| 写法 | 所在位置 | 含义 |
| --- | --- | --- |
| `int& ref = value;` | 声明 | 声明 `ref` 是 `int` 的引用 |
| `int* ptr = &value;` | 声明 + 表达式 | `ptr` 是指针；`&value` 取得地址 |
| `*ptr = 5;` | 表达式 | 解引用 `ptr`，修改所指对象 |
| `int* p;` | 声明 | 声明指针，不会自动指向有效对象 |

判断时先看它是在“声明一个名字”，还是在“计算一个表达式”。不要因为 `&` 在两处都出现，就把引用和取地址当成同一概念。

### 5.3 指针与引用如何选择

| 需求 | 常见选择 | 原因 |
| --- | --- | --- |
| 函数需要一份独立副本 | `T` | 修改副本不会影响调用者 |
| 函数必须接收一个有效对象并可能修改它 | `T&` | 语法直接，不能表示空对象 |
| 函数只读较大对象 | `const T&` | 避免复制，同时限制修改 |
| “对象可能不存在” | `T*`，检查 `nullptr` | 指针可以明确表示空值 |
| 观察连续数据并需要长度 | `std::span<T>` | 同时携带地址和元素数量，不拥有数据 |
| 拥有可变数量的元素 | `std::vector<T>` | 自动管理内存和长度 |

这不是绝对规则。还要结合所有权、生命周期、异常安全和接口习惯判断，但“引用表示必须存在，指针可以为空”是一个很实用的起点。

## 6. 常见错误与排查方法

| 错误写法或现象                                                    | 为什么有问题                             | 修改方向                                       |
| ---------------------------------------------------------- | ---------------------------------- | ------------------------------------------ |
| 访问 `array[array_size]`                                     | 最大有效下标是 `array_size - 1`，越界属于未定义行为 | 使用 `< array_size`，或使用范围 `for`              |
| `int* p; *p = 1;`                                          | `p` 未初始化，指向不确定位置                   | 初始化为有效地址或 `nullptr`，并在解引用前检查               |
| `int* p = nullptr; *p`                                     | 空指针没有指向对象                          | 先判断 `p != nullptr`                         |
| `delete` 之后继续使用指针                                          | 指针悬空，解引用是未定义行为                     | 释放后置 `nullptr`，更推荐 RAII 容器/智能指针            |
| `new[]` 配 `delete`                                         | 分配与释放形式不匹配                         | `new[]` 必须配 `delete[]`                     |
| 把数组参数写成 `void f(int values[])` 后在函数内用 `sizeof(values)` 求长度 | 参数已调整为 `int*`，`sizeof` 得到的是指针大小    | 额外传长度，或使用 `std::span`                      |
| `int& r = b;` 被误认为会让 `r` 改绑到 `b`                           | 这是给原对象赋值，引用不能改绑                    | 若需要改变目标，使用指针                               |
| 返回局部数组/局部变量的指针或引用                                          | 函数结束后对象已销毁，结果悬空                    | 按值返回容器，或确保目标对象由调用者管理                       |
| 用 `char text[3] = "cat"` 当 C 字符串                           | 没有存放结尾 `\0` 的空间                    | 改为 `char text[] = "cat"` 或使用 `std::string` |

编译时建议打开警告。MSVC 可使用 `/W4`，MinGW-w64 可使用 `-Wall -Wextra -pedantic`。警告不能发现所有越界和生命周期问题，但通常能尽早提示未使用变量、可疑转换和返回路径遗漏等问题。

## 示例与实践

### 1. 可运行的综合示例

下面的程序同时演示：固定数组、`std::span`、指针参数、引用参数、`const` 引用、数组到指针的转换，以及 `std::vector`。保存为 `array_pointer_reference.cpp` 后编译运行。

~~~cpp
#include <iostream>
#include <span>
#include <string>
#include <vector>

// const span：只读取一段连续数据，不修改元素
int sum(std::span<const int> values) {
    int result = 0;
    for (int value : values) {
        result += value;
    }
    return result;
}

// 引用参数：调用者必须提供一个有效的 int，函数会修改它
void add_bonus(int& score, int bonus) {
    score += bonus;
}

// 指针参数：允许调用者传入 nullptr，表示“没有要修改的对象”
void reset(int* score) {
    if (score != nullptr) {
        *score = 0;
    }
}

// const 引用：只读字符串，避免不必要的复制
void print_label(const std::string& label) {
    std::cout << "标签：" << label << '\n';
}

int main() {
    int scores[] = {70, 85, 92, 88}; // 内置数组，元素连续存放

    std::cout << "总分：" << sum(scores) << '\n';

    add_bonus(scores[0], 5); // scores[0] 是一个可修改的 int 左值
    std::cout << "加分后第一项：" << scores[0] << '\n';

    int* first = scores; // 数组名在这里退化为指向首元素的指针
    std::cout << "通过指针读取第一项：" << *first << '\n';

    reset(&scores[1]); // 传入第二项的地址
    reset(nullptr);    // 合法：reset 会安全返回

    std::vector<int> more_scores = {60, 75};
    more_scores.push_back(81); // vector 自动管理动态存储
    std::cout << "动态数组的元素个数：" << more_scores.size() << '\n';

    print_label("期末成绩"); // const 引用可绑定到临时字符串
}
~~~

使用 MSVC（Visual Studio Developer PowerShell）：

~~~powershell
cl /std:c++20 /W4 /EHsc array_pointer_reference.cpp /Fe:array_pointer_reference.exe
.\array_pointer_reference.exe
~~~

使用 MinGW-w64：

~~~powershell
g++ -std=c++20 -Wall -Wextra -pedantic array_pointer_reference.cpp -o array_pointer_reference.exe
.\array_pointer_reference.exe
~~~

PowerShell 运行当前目录下的程序时通常需要写 `.\` 前缀。如果提示 `cl` 或 `g++` 不是命令，请打开 Visual Studio Developer PowerShell，或把 MinGW-w64 的 `bin` 目录加入 `PATH`。
