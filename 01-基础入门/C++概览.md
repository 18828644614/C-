# C++概览

## 学习目标

- [ ] 说明 C++ 的定位、主要特点和常见应用场景。
- [ ] 区分语言标准、编译器、标准库、编辑器和构建工具。
- [ ] 说出从 `.cpp` 源文件到可执行程序的大致过程。
- [ ] 看懂一个最小 C++ 程序中 `#include`、`main`、`std::cout` 和 `return` 的作用。
- [ ] 知道 C++ 标准版本与编译器支持之间的关系，并能选择合适的学习版本。
- [ ] 区分编译错误、链接错误、运行时错误和逻辑错误。
- [ ] 在 Windows 环境下使用 MSVC 或 MinGW-w64 编译、运行一个简单程序。

## 要点

### 1. C++ 是什么

C++ 是一种通用的、静态类型的、编译型编程语言。它由 C 语言发展而来，同时加入了类、模板、异常、泛型编程等能力。现代 C++ 既可以写接近硬件的代码，也可以使用高级抽象构建大型软件。

这里有几个常见术语需要先建立正确的直觉：

| 术语 | 初学者可以怎样理解 | 需要注意的地方 |
| --- | --- | --- |
| 编译型 | 通常先把源代码转换成机器可以直接执行的程序，再运行 | “编译型”不等于绝对不能解释执行；关键是日常开发以编译为主 |
| 静态类型 | 编译时就要知道表达式和变量的类型，并检查很多错误 | 类型检查严格，但可以通过模板、继承和类型推导减少重复书写 |
| 多范式 | 可以使用过程式、面向对象、泛型和函数式等风格 | 风格越多，越需要学习如何选择合适的抽象 |
| 标准库 | 语言随附一套可移植的库，例如输入输出、字符串和容器 | 标准库不是操作系统的全部 API，Windows 专用功能仍属于平台 API |
| 零开销抽象 | 不使用的功能通常不会带来额外成本，使用的抽象尽量接近手写高效代码 | 这是设计目标而非保证；错误的算法和滥用抽象仍然会很慢 |

“C++ 很快”并不是因为它会自动优化一切。运行速度还取决于算法、数据结构、内存访问方式、编译选项以及程序设计。初学阶段应优先写出正确、清晰的程序，再根据测量结果优化。

### 2. C++ 适合做什么

C++ 的优势是性能、资源控制能力和跨平台能力，因此常见于：

- **系统软件**：操作系统组件、驱动周边工具、编译器、数据库和网络服务。
- **桌面应用**：图形编辑器、音视频软件、科学计算工具以及跨平台 GUI 框架的底层部分。
- **游戏与实时图形**：游戏引擎、渲染器、物理模拟和需要稳定帧率的程序。
- **嵌入式与物联网**：内存和处理器资源有限的设备，通常需要精确控制资源。
- **高性能计算**：仿真、金融计算、图像处理、机器学习基础设施等。
- **基础设施库**：为其他语言提供高性能的核心库，再通过绑定接口调用。

它也不是所有问题的最佳选择。一次性脚本、简单的数据清洗或快速搭建网页，可能更适合 Python、JavaScript 等语言。选择语言时要综合考虑性能要求、团队经验、生态和交付速度，而不是只看语言的“强弱”。

### 3. 标准版本：语言在不断演进

C++ 由 ISO 标准委员会维护。标准规定语言和标准库“应该怎样工作”，但不会提供一个叫作“C++ 官方编译器”的单一软件。常见版本包括：

| 版本 | 大致印象 | 学习时的意义 |
| --- | --- | --- |
| C++98/03 | 早期标准，奠定基本语言和 STL | 旧项目仍可能使用，但不建议作为新项目的首选 |
| C++11 | 现代 C++ 的重要起点，引入 `auto`、范围 `for`、智能指针、移动语义等 | 读旧代码和理解现代特性时经常遇到 |
| C++14 | 对 C++11 的小幅完善 | 兼容性较好，部分老项目使用 |
| C++17 | 结构化绑定、`if constexpr`、`std::filesystem` 等 | 目前仍是很多项目的稳定基线 |
| C++20 | 概念、范围、协程、模块等重要特性 | 适合系统学习现代 C++，但不同编译器支持程度要核对 |
| C++23 | 继续完善库和语言细节 | 新项目可按需要使用，先确认工具链和部署环境 |

标准版本和编译器版本是两件事。例如，“使用 C++20”表示希望编译器按 C++20 规则编译，并不表示编译器本身叫 C++20。MSVC、GCC（MinGW-w64 常用）、Clang 都在逐步实现标准，支持程度可能不同。

对于本教程，示例尽量使用 C++17/C++20 中已经普遍可用的特性。若某个项目规定了版本，应以项目的构建配置为准，而不是随意把编译选项改成最新版本。

### 4. 语言、标准库和开发工具的关系

编写一个 C++ 程序通常会接触以下几部分：

1. **语言本身**：关键字、表达式、类型、类、模板和并发模型等规则。
2. **标准库**：例如 `std::string`、`std::vector`、`std::cout` 和算法。标准库源码通常随编译器或开发套件提供。
3. **编译器**：读取源代码并生成目标文件或可执行文件。Windows 上常见的是 MSVC、MinGW-w64 GCC 和 Clang/Clang-cl。
4. **编辑器或 IDE**：用于编写和导航代码。Visual Studio、VS Code、CLion 等都可以作为编辑工具；IDE 不等于编译器。
5. **构建工具**：管理多个源文件、编译选项和依赖关系，例如 CMake、MSBuild 或 Ninja。
6. **调试器**：让程序逐行执行、查看变量和调用栈，帮助定位运行时问题。

编辑器只是“写代码的地方”。安装了 VS Code 并不会自动拥有 C++ 编译器；在 Windows 上仍需安装 Visual Studio 的 C++ 工作负载，或单独安装 MinGW-w64/LLVM 工具链。

### 5. 从源代码到可执行程序

一个简单的单文件程序看起来像“保存后直接运行”，实际上通常经历以下阶段：

1. **预处理**：处理 `#include`、宏和条件编译。`#include <iostream>` 可以粗略理解为把对应头文件的声明内容提供给当前源文件。
2. **编译**：检查语法和类型，把每个 `.cpp` 翻译成目标代码，常见中间产物是 `.obj` 或 `.o`。
3. **链接**：把多个目标文件和库组合起来，解析函数、变量等符号的引用，生成 `.exe` 等可执行文件。
4. **运行**：操作系统加载可执行文件，创建进程并调用 `main` 函数。

因此，“头文件找不到”通常是预处理阶段的问题，“语法错误”通常是编译阶段的问题，“找不到某个函数的实现”常见于链接阶段，而程序启动后崩溃属于运行时问题。后面的 [[源文件、编译与链接]] 会详细展开这些阶段。

### 6. 一个最小的 C++ 程序

```cpp
#include <iostream> // 提供标准输出 std::cout

int main() {
    std::cout << "Hello, C++!" << '\n'; // 输出一行文字
    return 0;                            // 返回 0，表示程序正常结束
}
```

逐行理解：

- `#include <iostream>` 让编译器知道输入输出流相关的声明。尖括号通常表示从编译器配置的标准库目录查找。
- `int main()` 是程序的入口函数。桌面程序启动后，操作系统最终会从这里开始执行。
- `{}` 包围函数体；分号 `;` 表示一条语句的结束。
- `std::cout` 是标准库中的控制台输出对象。`std` 是标准库使用的命名空间，`::` 是作用域运算符。
- `<<` 在这里表示把右侧内容写入输出流；它并不总是“左移运算”的意思，具体含义由操作数类型决定。
- `\n` 表示换行。它通常比强制刷新输出的 `std::endl` 更适合普通输出。
- `return 0` 把状态码交给操作系统。对 `main` 来说，到达右花括号也等价于返回 0，但显式写出更便于初学者理解。

`main` 也可以接收命令行参数：

```cpp
#include <iostream>

int main(int argc, char* argv[]) {
    // argc 是参数个数；argv[0] 通常是程序路径
    for (int i = 0; i < argc; ++i) {
        std::cout << "参数 " << i << ": " << argv[i] << '\n';
    }
    return 0;
}
```

命令行参数的类型是 C 风格字符串。需要更方便地处理文字时，通常会转换为 `std::string`；这会在后续的字符串章节中介绍。

### 7. 命名空间与 `std::`

不同库可能定义同名的类型或函数。命名空间为这些名字提供了边界，标准库把大多数名称放在 `std` 中，因此写作 `std::cout`、`std::string`。

可以用声明减少重复书写：

```cpp
#include <iostream>

int main() {
    using std::cout; // 只引入 cout，范围限于当前函数
    cout << "更明确的写法" << '\n';
}
```

初学者常见的 `using namespace std;` 会把整个 `std` 命名空间的名称带入当前作用域。小练习中可能看起来方便，但在大型项目中容易产生名称冲突，尤其是自己定义了与标准库同名的函数或类型。因此教程和工程代码通常保留 `std::`，或者只使用需要的单个名称。

### 8. C++ 程序中的数据与资源

变量保存数据，类型决定数据的表示方式以及允许的操作。例如，`int` 通常用于整数，`double` 用于带小数的数值，`bool` 表示真假，`std::string` 表示文字。类型、变量、常量和初始化方式会在 [[类型、变量与常量]] 中系统学习。

C++ 允许直接控制资源，例如动态内存、文件句柄和网络连接。这种能力带来性能和可控性，也带来责任：资源必须在合适的时机释放，不能使用已经失效的对象。现代 C++ 倾向于使用 **RAII** 和智能指针，让资源绑定到对象生命周期，而不是到处手写 `new`/`delete`。初学阶段应先掌握对象、作用域和生命周期，再学习手动内存管理。

“栈”和“堆”是常见的简化说法，但不要把它们当成 C++ 语法规则。局部对象通常具有自动存储期，动态分配的对象具有动态存储期；具体布局由实现决定。真正重要的是理解：对象何时创建、何时销毁，以及在销毁后是否还保存着指向它的指针或引用。

### 9. 四类常见错误

1. **编译错误**：源代码不符合语法或类型规则，例如漏写分号、调用不存在的函数。编译器通常会指出文件和行号。
2. **链接错误**：声明找到了，但实现没有被链接进来，例如只写了函数声明却没有提供定义，或漏掉了某个库。
3. **运行时错误**：程序编译成功，但运行时崩溃、异常退出、除零或访问无效内存。
4. **逻辑错误**：程序能够运行，却得到错误结果，例如把总价计算成了单价。编译器未必能发现，需要测试和调试。

还有一类特别危险的问题叫 **未定义行为**，例如越界访问数组、使用已经销毁对象的引用。标准没有规定这时必须发生什么，程序可能“看起来能运行”，也可能在换一台机器或打开优化后立刻出错。遇到警告时不要简单忽略，应尽早修正。

### 10. 初学者容易混淆的地方

- `=` 是赋值，`==` 才是比较是否相等。
- `'A'` 是一个字符，`"A"` 是字符串字面量，两者类型和用途不同。
- `#include` 不是运行时“加载文件”，而是编译前处理的一部分。
- `std::endl` 会换行并刷新输出；普通日志多数只需要 `\n`。
- 文件扩展名 `.cpp` 只是约定，真正决定编译方式的是构建命令和工具链配置。
- 头文件应包含必要的声明，源文件负责定义；把所有内容塞进一个文件可以做练习，但大型项目需要拆分。
- 编译器警告不是“可忽略的提示”。开启较高警告级别，能在运行前发现许多潜在错误。
- Windows 控制台的字符编码可能影响中文输出。教程示例默认输出英文以减少环境差异；源文件建议保存为 UTF-8，MSVC 可加 `/utf-8` 选项。

### 11. 建议的学习边界与路线

“C++概览”只负责建立地图，不要求一次掌握所有细节。推荐按下面的顺序深入：

1. 先学基本语法、类型、控制流和函数，能够读懂简单程序。
2. 再学习数组、指针、引用、对象生命周期和 RAII，理解资源安全。
3. 接着学习 STL 容器、迭代器、算法和字符串，减少重复造轮子。
4. 然后学习类、继承、多态、模板和现代 C++ 特性。
5. 最后结合 CMake、调试器、测试、并发和性能分析完成小项目。

不要把“会背语法”当成学会 C++。更可靠的标准是：能解释代码为什么这样写，能用编译器警告和调试器定位问题，能为关键行为编写测试。

## 示例与实践

### Windows 下编译一个完整示例

将下面内容保存为 `overview_demo.cpp`。代码只使用标准库，在 MSVC 和 MinGW-w64 GCC 上都可以编译。

```cpp
#include <iostream>
#include <string>

int main(int argc, char* argv[]) {
    std::cout << "C++ 概览示例" << '\n';
    std::cout << "参数个数（包含程序路径）: " << argc << '\n';

    if (argc > 1) {
        // argv[1] 是第一个用户传入的参数，转换为 std::string 后更易使用
        const std::string name = argv[1];
        std::cout << "你好，" << name << "！" << '\n';
    } else {
        std::cout << "没有传入名字，将使用默认问候。" << '\n';
    }

    const int answer = 6 * 7; // const 表示初始化后不再修改
    std::cout << "一个简单计算的结果: " << answer << '\n';
    return 0;
}
```

使用 MinGW-w64 GCC 时，在 PowerShell 中执行：

```powershell
g++ --version
g++ -std=c++20 -Wall -Wextra -pedantic overview_demo.cpp -o overview_demo.exe
.\overview_demo.exe Alice
```

使用 Visual Studio 的“开发者 PowerShell”时，执行：

```powershell
cl /std:c++20 /W4 /EHsc overview_demo.cpp
.\overview_demo.exe Alice
```

预期会看到类似输出（编译器版本和路径不会影响核心结果）：

```text
C++ 概览示例
参数个数（包含程序路径）: 2
你好，Alice！
一个简单计算的结果: 42
```

如果 PowerShell 提示找不到 `g++` 或 `cl`，通常不是代码错误，而是相应工具链没有安装，或当前终端没有加载工具链环境变量。可先阅读 [[开发环境]]，再重新打开对应的开发者终端。

### 动手练习

1. 删除命令行参数，再运行程序，观察 `if` 的另一条分支。
2. 把 `answer` 改成 `double`，尝试输出 `6.0 * 7.0`，比较结果和类型变化。
3. 故意删除一个分号，阅读编译器给出的错误位置；修复后再编译。
4. 把 `const int answer` 改名为 `result`，思考变量名怎样表达意图。
5. 为程序增加一个参数：当用户传入两个参数时，输出第二个参数的内容。注意先检查 `argc`，不要直接访问不存在的 `argv` 元素。

完成练习后，尝试用调试器在 `std::cout` 前设置断点，单步观察 `argc`、`argv` 和 `answer` 的值。
