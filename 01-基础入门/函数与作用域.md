# 函数与作用域

## 学习目标

- [ ] 理解函数的声明、定义、调用、参数和返回值。
- [ ] 区分值传递、引用传递和指针传递，并能按需要选择。
- [ ] 掌握块作用域、函数参数作用域、命名空间作用域和类作用域，并了解 C++ 中严格意义上的函数作用域。
- [ ] 理解“名字可见范围”和“对象生命周期”不是同一个概念。
- [ ] 能识别名称隐藏、重复定义、返回局部变量引用等常见错误。

## 要点

## 1. 为什么要使用函数

程序一长，所有语句都写在 `main` 中会很难阅读、测试和修改。函数可以把一组完成同一任务的语句打包，并给它一个名字。调用者只需要关心“传入什么、得到什么”，不必每次重复书写实现细节。

例如，下面的程序把“计算矩形面积”独立成函数：

~~~cpp
#include <iostream>

// 函数定义：返回两个 double 相乘的结果
double rectangle_area(double width, double height) {
    return width * height;
}

int main() {
    std::cout << rectangle_area(3.0, 4.0) << '\n'; // 调用函数，输出 12
}
~~~

函数带来的好处主要有：

- **复用**：同一个函数可以被调用多次；
- **分工**：每个函数只负责一个相对明确的任务；
- **隔离细节**：修改函数内部实现时，调用处通常不需要改变；
- **便于测试**：可以单独给函数准备输入，检查它的返回值。

一个函数通常有三个要素：

1. **参数（parameter）**：函数定义中接收数据的变量，例如 `width` 和 `height`；
2. **返回类型（return type）**：函数完成后交出的结果类型，例如 `double`；
3. **函数体（body）**：花括号中的执行语句。

调用时写入的具体数据叫**实参（argument）**，例如 `3.0` 和 `4.0`。参数是函数内部的名字，实参是调用时提供的值，二者不要混为一谈。

## 2. 声明、定义和调用

### 2.1 三个概念

~~~cpp
// 声明（函数原型）：告诉编译器函数的名字、参数类型和返回类型
int add(int left, int right);

// 定义：提供函数体，说明函数具体如何工作
int add(int left, int right) {
    return left + right;
}

// 调用：让函数实际执行
int result = add(2, 3);
~~~

声明末尾有分号，通常不写函数体；定义包含函数体。函数可以先声明、后定义，这样 `main` 就能在函数定义之前调用它：

~~~cpp
#include <iostream>

int add(int left, int right); // 先声明

int main() {
    std::cout << add(2, 3) << '\n';
}

int add(int left, int right) { // 后定义
    return left + right;
}
~~~

如果调用处之前没有声明，编译器通常会报告“未声明的标识符”。如果只有声明而整个程序中没有对应定义，当前源文件可能编译成功，但最后链接时会出现 `unresolved external symbol`（MSVC）或 `undefined reference`（GCC/MinGW）。这就是“编译通过不等于链接通过”。

在多文件项目中，声明通常放在 `.h`/`.hpp` 头文件，定义放在 `.cpp` 源文件；具体示例可参考 [[源文件、编译与链接]]。

### 2.2 函数签名和返回值

调用函数时，编译器主要根据函数名和参数列表（参数的数量、类型以及顺序）寻找匹配版本；返回类型不能用来区分重载。参数名在声明中可以省略：

~~~cpp
double average(double, double); // 参数名可省略，类型仍然必须写对
~~~

`return` 会结束当前函数，并把一个值交给调用者：

~~~cpp
double average(double a, double b) {
    return (a + b) / 2.0;
}
~~~

返回类型为 `void` 的函数表示“不返回一个值”，可以使用不带表达式的 `return;` 提前结束，也可以直接执行到函数末尾：

~~~cpp
#include <iostream>

void print_line(int count) {
    if (count <= 0) {
        return; // 提前结束 void 函数
    }
    for (int i = 0; i < count; ++i) {
        std::cout << '-';
    }
    std::cout << '\n';
}
~~~

非 `void` 函数必须在所有可能的执行路径上返回一个合适类型的值。遗漏 `return` 可能产生警告，调用结果也可能是未定义行为。`main` 是一个例外：执行到末尾等价于返回 `0`。

## 3. 参数传递：值、引用和指针

### 3.1 按值传递：函数得到一份副本

默认情况下，参数按值传递。函数接收到的是实参的副本，在函数内修改参数不会影响调用者的原变量：

~~~cpp
#include <iostream>

void try_to_change(int number) {
    number = 100; // 只修改副本
}

int main() {
    int value = 7;
    try_to_change(value);
    std::cout << value << '\n'; // 仍然输出 7
}
~~~

对于 `int`、`double` 等小对象，复制通常很便宜；对于很大的对象，复制可能有额外开销。

### 3.2 按引用传递：直接操作原对象

在类型后加 `&` 表示引用参数。引用像是原对象的另一个名字，函数内的修改会作用于原对象：

~~~cpp
#include <iostream>

void change_to_100(int& number) {
    number = 100; // 直接修改调用者的变量
}

int main() {
    int value = 7;
    change_to_100(value);
    std::cout << value << '\n'; // 输出 100
}
~~~

如果函数只需要读取一个可能较大的对象，又不需要复制和修改它，常用 `const T&`：

~~~cpp
#include <iostream>
#include <string>

void print_name(const std::string& name) {
    // const 引用避免复制，也保证本函数不会修改 name
    std::cout << "你好，" << name << '！' << '\n';
}

int main() {
    print_name("小明"); // const 引用可以绑定到临时字符串
}
~~~

选择时可以先记一个简单规则：需要独立副本就按值；需要修改调用者对象就用 `T&`；只读且不想复制较大对象就用 `const T&`。

### 3.3 指针参数：允许“没有对象”

指针参数传递的是地址。与引用不同，指针可以为空（`nullptr`），因此函数应先检查再解引用：

~~~cpp
#include <iostream>

void set_to_zero(int* number) {
    if (number == nullptr) {
        return; // 没有传入有效地址
    }
    *number = 0; // *number 表示该地址中的对象
}

int main() {
    int value = 7;
    set_to_zero(&value); // &value 取得 value 的地址
    set_to_zero(nullptr); // 合法，但函数不会修改任何对象
    std::cout << value << '\n'; // 输出 0
}
~~~

不要把引用和指针当成完全相同的东西：引用通常必须绑定到一个有效对象，调用语法像使用普通变量；指针可以为空，调用时要显式传地址，使用时也要考虑空指针和生命周期问题。

## 4. 默认参数、重载和 `const`

### 4.1 默认参数

可以为参数提供默认值，调用时省略该参数即可：

~~~cpp
#include <iostream>
#include <string>

void greet(const std::string& name, const std::string& punctuation = "！") {
    std::cout << "你好，" << name << punctuation << '\n';
}

int main() {
    greet("小明");       // 使用默认的“！”
    greet("小明", "！"); // 显式提供第二个参数
}
~~~

默认参数必须从最右侧开始连续提供。例如 `void f(int a = 1, int b);` 不合法，因为调用者无法只省略左边的参数。默认值通常只写在一次声明中（一般写在头文件声明），定义处不要重复写，否则可能产生重复默认参数错误。

### 4.2 函数重载

同一作用域内，可以定义多个同名函数，只要参数列表不同。编译器会根据实参选择最匹配的版本：

~~~cpp
#include <iostream>

int square(int value) {
    return value * value;
}

double square(double value) {
    return value * value;
}

int main() {
    std::cout << square(3) << '\n';    // 调用 int 版本
    std::cout << square(2.5) << '\n';  // 调用 double 版本
}
~~~

重载不能只靠返回类型区分：`int f(int);` 和 `double f(int);` 不能同时存在，因为仅凭 `f(1)` 无法决定调用哪一个。参数类型转换过多、默认参数与重载混用，也可能导致“调用有歧义”；初学时应让重载之间的参数差异清晰。

### 4.3 递归函数（了解）

递归是函数直接或间接调用自己的写法。一个正确的递归函数必须有**终止条件**，否则调用会不断深入，最终耗尽调用栈。下面用阶乘展示最简单的形式：

~~~cpp
#include <iostream>

long long factorial(unsigned int n) {
    if (n <= 1) {
        return 1; // 终止条件：0! 和 1! 都是 1
    }
    return static_cast<long long>(n) * factorial(n - 1); // 递归调用
}

int main() {
    std::cout << factorial(5) << '\n'; // 输出 120
}
~~~

递归适合表达树、目录等天然分层的问题，但每次调用都要保存一份参数和局部状态，层数过深会造成栈溢出。能用简单循环清楚解决的问题，初学时通常优先使用循环；使用递归时要明确终止条件和输入范围。

## 5. 作用域：名字在哪里可见

**作用域（scope）**是一个名字可以被直接使用的代码区域。花括号 `{}` 经常创建新的块作用域，但不同种类的声明还有各自的作用域。作用域回答“在哪里能写这个名字”，不直接回答“对象何时存在”。

在入门语境中，人们有时把“函数内部可见”简称为函数作用域。严格按 C++ 术语，函数参数有自己的参数作用域，函数体内声明的变量属于块作用域；函数作用域主要用于 goto 可以跳转到的标签。标签只在所在函数内可见，不能从另一个函数跳转过去：

~~~cpp
void example(bool skip) {
    if (skip) {
        goto end; // 只能跳到同一个函数中的标签
    }
    // 其他语句
end:
    ; // 标签本身没有变量类型，只是跳转位置
}
~~~

日常代码很少需要 goto。这里介绍它只是为了说明“函数作用域”这个严格术语；编写普通函数时，重点仍然是理解参数和局部变量的块作用域。

### 5.1 块作用域、参数和局部变量

函数参数和函数体内声明的局部变量，通常只能在该函数内部使用；`if`、`for`、`while` 或额外花括号也会产生更内层的块作用域：

~~~cpp
#include <iostream>

int main() {
    int value = 10; // main 的局部变量

    if (value > 0) {
        int doubled = value * 2; // 只在 if 的花括号内可见
        std::cout << doubled << '\n';
    }

    // std::cout << doubled; // 错误：doubled 已超出作用域
}
~~~

内层可以访问外层已经可见的名字；外层不能反过来访问内层名字。变量离开作用域时，普通局部对象的生命周期通常也结束，其资源会自动释放。

### 5.2 名称隐藏（遮蔽）

如果内层作用域声明了与外层同名的变量，内层名字会**隐藏**外层名字，而不是修改外层变量：

~~~cpp
#include <iostream>

int main() {
    int count = 10;
    {
        int count = 20; // 隐藏外层的 count
        std::cout << count << '\n'; // 输出 20
    }
    std::cout << count << '\n'; // 输出 10
}
~~~

名称隐藏很容易造成误读。除了教学或特别需要外，尽量不要在相邻嵌套作用域中重复使用同一个名字。函数参数也可能隐藏同名的全局变量；可以使用作用域运算符 `::` 明确访问全局名字：

~~~cpp
#include <iostream>

int value = 100; // 全局变量，位于全局作用域

void show(int value) { // 参数隐藏了同名全局变量
    std::cout << value << '\n';  // 参数
    std::cout << ::value << '\n'; // ::value 表示全局作用域中的变量
}

int main() {
    show(5);
}
~~~

### 5.3 命名空间作用域

命名空间用于组织名字、减少不同模块之间的冲突：

~~~cpp
#include <iostream>

namespace math_tools {
    int square(int value) {
        return value * value;
    }
}

int main() {
    std::cout << math_tools::square(4) << '\n';
}
~~~

`std::cout` 中的 `std` 就是标准库使用的命名空间。初学时可以写完整的 `std::`，不建议在头文件中使用 `using namespace std;`，以免把大量名字引入所有包含该头文件的代码中。

### 5.4 类作用域

类的成员（数据成员和成员函数）位于类作用域中，通常通过对象或类名访问：

~~~cpp
#include <iostream>

class Counter {
public:
    void increase() { ++value_; }
    int value() const { return value_; }

private:
    int value_ = 0; // 成员变量，属于每个 Counter 对象
};

int main() {
    Counter counter;
    counter.increase();
    std::cout << counter.value() << '\n';
}
~~~

`value_` 只能在类的成员函数（以及被授权的友元）中直接访问；`counter.value()` 则通过对象调用成员函数。类作用域是后续学习封装、继承和多态的基础。

## 6. 作用域与生命周期不是一回事

初学者常把“离开花括号后名字不能使用”和“对象已经不存在”当成同一件事。更准确地说：

- **作用域**描述名字在源代码中的可见范围；
- **生命周期**描述对象从构造完成到析构结束的时间。

普通局部变量通常在进入声明所在位置后构造，离开块时销毁：

~~~cpp
#include <iostream>

int next_id() {
    static int id = 0; // 名字只在本函数可见
    ++id;
    return id;
}

int main() {
    std::cout << next_id() << '\n'; // 1
    std::cout << next_id() << '\n'; // 2：static 对象没有因函数返回而销毁
}
~~~

这里的 `id` 具有函数块作用域，但它是 `static` 局部变量：只初始化一次，生命周期持续到程序结束。它适合保存函数内部需要记住的状态，但会引入隐藏状态，多个调用之间不再完全独立，使用时应有意识地权衡。

不要返回普通局部变量的引用或指针：函数返回后对象已经销毁，留下的引用/指针会悬空。

~~~cpp
// 错误示例：不要照这样写
int& bad() {
    int local = 42;
    return local; // 警告：返回了即将销毁的局部变量引用
}
~~~

如果需要把结果交给调用者，优先按值返回；现代 C++ 通常会通过返回值优化避免不必要的复制。若确实要返回引用或指针，必须确保被引用对象在调用结束后仍然存在（例如某个外部对象或合适的静态对象）。

## 7. 全局变量与 `static` 的取舍

全局变量位于全局作用域，整个程序的多个函数都可能访问它：

~~~cpp
int total = 0; // 全局变量

void add_one() {
    ++total;
}
~~~

全局变量生命周期长、访问方便，但会让函数依赖隐藏的外部状态，增加调试和并发编程的难度。初学阶段优先通过参数传入数据、通过返回值交出结果；只有确实表示“整个程序共享的状态”时，才考虑全局对象，并尽量使用 `const` 或更明确的封装。

在一个 `.cpp` 文件中给全局变量或普通函数加 `static`，还可能表示**内部链接**：该名字只在当前源文件可见，不能被其他源文件直接使用。这与函数内的 `static`（延长局部对象生命周期）是不同含义，必须结合所在位置判断。

## 8. 函数设计的实用建议

- 函数名使用动词或清晰的动作短语，例如 `calculate_total`、`print_menu`。
- 一个函数尽量只做一件主要的事；过长的函数可以拆分成多个小函数。
- 参数数量不宜过多。相关数据可以考虑放入结构体或类中。
- 能用返回值表达结果时，少依赖全局变量和输出参数。
- 对不会修改的参数加 `const`，让接口表达意图并帮助编译器检查错误。
- 遇到编译器警告时先理解原因，不要简单地用强制转换或关闭警告掩盖问题。

## 示例与实践

### 1. 一个可运行的综合示例

下面的程序演示了值传递、引用传递、`const` 引用、命名空间、局部作用域和函数重载。将它保存为 `functions_scope.cpp`，在 Windows 的 Developer PowerShell（MSVC）或已配置 MinGW-w64 的 PowerShell 中编译。

~~~cpp
#include <iostream>
#include <string>

namespace demo {

// 按值传递：不会改变调用者的原变量
int add_ten(int number) {
    return number + 10;
}

// 按引用传递：直接修改调用者的变量
void add_ten_in_place(int& number) {
    number += 10;
}

// const 引用：只读且避免复制字符串
void print_message(const std::string& message) {
    std::cout << message << '\n';
}

// 重载：根据参数类型选择不同版本
void print_value(int value) {
    std::cout << "整数：" << value << '\n';
}

void print_value(double value) {
    std::cout << "小数：" << value << '\n';
}

} // namespace demo

int main() {
    int score = 80;

    std::cout << "按值传递的返回结果："
              << demo::add_ten(score) << '\n';
    std::cout << "score 仍然是：" << score << '\n';

    demo::add_ten_in_place(score);
    std::cout << "按引用传递后 score 是：" << score << '\n';

    demo::print_message("函数可以隐藏实现细节");
    demo::print_value(score);   // 选择 int 重载
    demo::print_value(3.14);    // 选择 double 重载

    {
        int score = 0; // 内层变量隐藏外层 score
        std::cout << "内层 score：" << score << '\n';
    }
    std::cout << "外层 score：" << score << '\n';
}
~~~

使用 MSVC：

~~~powershell
cl /std:c++20 /W4 /EHsc functions_scope.cpp /Fe:functions_scope.exe
.\functions_scope.exe
~~~

使用 MinGW-w64：

~~~powershell
g++ -std=c++20 -Wall -Wextra -pedantic functions_scope.cpp -o functions_scope.exe
.\functions_scope.exe
~~~

PowerShell 运行当前目录下的程序时通常要写 `.\` 前缀。若提示 `cl` 或 `g++` 不是命令，请检查是否打开了 Visual Studio Developer PowerShell，或是否已把 MinGW-w64 的 `bin` 目录加入 `PATH`。

### 2. 常见错误对照

| 错误写法或现象 | 原因 | 修改方向 |
| --- | --- | --- |
| 调用函数前没有声明 | 编译器不知道函数的类型 | 在调用前添加声明，或把定义移到调用前 |
| 只有声明，链接时报 `undefined reference` / `unresolved external symbol` | 缺少函数定义，或链接命令漏掉实现文件 | 检查定义是否存在，并把对应 `.cpp`/库加入构建 |
| 试图用返回类型区分重载 | 调用时无法仅凭返回类型选择 | 修改参数列表或改用不同函数名 |
| 非 `void` 函数某条路径没有 `return` | 调用者可能得到无效结果 | 检查所有分支，确保返回合适类型 |
| 把内层变量名写到外层使用 | 内层名字超出作用域 | 在需要的位置重新声明，或把变量移到共同的外层作用域 |
| `T&` 参数传入 `nullptr` | 引用不能表示空对象 | 若确实允许“没有对象”，改用指针并检查 `nullptr` |
| 返回局部变量的引用/指针 | 函数结束时局部对象已销毁 | 按值返回，或返回生命周期足够长的对象 |
| 在头文件中直接定义普通非 `inline` 函数并被多处包含 | 链接阶段产生重复定义 | 将定义放入一个 `.cpp`，或使用合适的 `inline`/模板写法 |

### 3. 练习

1. 编写 `is_even(int)`，返回一个 `bool`，判断整数是否为偶数。
2. 编写 `swap_values(int&, int&)`，使用引用交换两个整数，并观察按值传递为什么不能完成交换。
3. 编写带默认参数的 `print_box(int width = 10, char fill = '*')`，打印指定宽度的一行字符。
4. 将综合示例拆成 `demo.h`、`demo.cpp` 和 `main.cpp` 三个文件；先故意漏掉 `demo.cpp` 的链接，再根据链接器错误修复命令。
5. 在一个函数中声明局部变量，并在函数外尝试访问它；记录编译器报错，再说明这是作用域问题还是生命周期问题。
