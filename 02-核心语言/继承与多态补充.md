# 继承与多态补充

## 会话范围

## 用户问题

> 请以一个新手的角度，分析继承，封装，多态，virtual和override，对于复杂的地方要尽可能详细的解释

## 完整回答

下面以 C++ 为例，从新手角度理解：继承、封装、多态、`virtual` 和 `override`。

## 一、先看整体关系

假设我们有不同类型的动物：

- 所有动物都有名字、年龄
- 狗会叫“汪汪”
- 猫会叫“喵喵”
- 我们希望用统一的方式管理它们

这时：

- **封装**：把动物的数据和行为封装在类中
- **继承**：让 `Dog`、`Cat` 复用 `Animal` 的内容
- **多态**：用 `Animal*` 指针指向不同动物，并调用它们各自的叫声
- **virtual**：告诉 C++，这个函数需要支持运行时多态
- **override**：明确声明“这个函数正在重写父类函数”

# 二、封装

## 1. 什么是封装？

封装就是：

> 把数据和操作数据的函数放在一起，并限制外部直接访问内部数据。

例如：

~~~cpp
class Person {
private:
    int age;

public:
    void setAge(int value) {
        if (value >= 0 && value <= 150) {
            age = value;
        }
    }

    int getAge() {
        return age;
    }
};
~~~

使用：

~~~cpp
Person p;

p.setAge(20);
cout << p.getAge();
~~~

外部不能直接这样写：

~~~cpp
p.age = -100; // 错误，age 是 private
~~~

## 2. 为什么要封装？

如果数据完全公开：

~~~cpp
class Person {
public:
    int age;
};
~~~

任何代码都可以修改：

~~~cpp
Person p;
p.age = -999;
~~~

这会破坏对象的合理状态。

封装后，修改必须经过函数检查：

~~~cpp
p.setAge(-999); // 函数可以拒绝这个值
~~~

因此封装主要解决：

1. 防止数据被随意修改
2. 保证数据合法
3. 隐藏内部实现
4. 降低代码之间的耦合
5. 以后修改内部实现时，不影响外部代码

## 3. `private`、`protected`、`public`

### `public`

外部可以访问：

~~~cpp
class A {
public:
    int x;
};
~~~

~~~cpp
A a;
a.x = 10;
~~~

### `private`

只有当前类的成员函数可以访问。

~~~cpp
class A {
private:
    int x;
};
~~~

派生类和外部都不能直接访问。

### `protected`

当前类和派生类可以访问，但外部不能访问。

~~~cpp
class Animal {
protected:
    string name;
};

class Dog : public Animal {
public:
    void showName() {
        cout << name; // 可以访问
    }
};
~~~

外部：

~~~cpp
Dog d;
// d.name; // 错误
~~~

新手通常可以遵循：

> 数据一般放在 `private`，通过 `public` 函数操作。

# 三、继承

## 1. 什么是继承？

继承表示：

> 一个类可以拥有另一个类的成员和功能。

例如：

~~~cpp
class Animal {
public:
    void eat() {
        cout << "动物吃东西" << endl;
    }
};

class Dog : public Animal {
public:
    void bark() {
        cout << "汪汪" << endl;
    }
};
~~~

使用：

~~~cpp
Dog dog;

dog.eat();  // 来自 Animal
dog.bark(); // Dog 自己的功能
~~~

`Dog : public Animal` 表示：

> `Dog` 继承自 `Animal`。

其中：

- `Animal` 叫父类、基类
- `Dog` 叫子类、派生类

## 2. 继承的意义

### 代码复用

多个类共同拥有的功能，可以放在父类中。

~~~cpp
class Animal {
public:
    void eat() {}
    void sleep() {}
};
~~~

狗、猫都可以复用。

### 表达“是一个”关系

~~~text
Dog 是一种 Animal
Cat 是一种 Animal
~~~

但：

~~~text
Engine 不是 Car
~~~

发动机是汽车的组成部分，不适合用继承，适合组合。

## 3. 子类可以做什么？

子类通常可以：

1. 直接使用父类的 `public` 成员
2. 访问父类的 `protected` 成员
3. 增加自己的成员
4. 重写父类的虚函数
5. 调用父类构造函数

例如：

~~~cpp
class Animal {
protected:
    string name;

public:
    Animal(string n) {
        name = n;
    }

    void eat() {
        cout << name << " 正在吃东西" << endl;
    }
};

class Dog : public Animal {
public:
    Dog(string n) : Animal(n) {}

    void bark() {
        cout << name << " 汪汪叫" << endl;
    }
};
~~~

# 四、继承中的构造和析构

## 1. 构造顺序

创建子类对象时：

1. 先调用父类构造函数
2. 再调用子类构造函数

~~~cpp
class Animal {
public:
    Animal() {
        cout << "Animal 构造" << endl;
    }
};

class Dog : public Animal {
public:
    Dog() {
        cout << "Dog 构造" << endl;
    }
};
~~~

~~~cpp
Dog d;
~~~

输出：

~~~text
Animal 构造
Dog 构造
~~~

原因很简单：

> 子类对象中包含一个父类部分，必须先把父类部分初始化好。

## 2. 析构顺序

析构顺序正好相反：

1. 先调用子类析构函数
2. 再调用父类析构函数

~~~text
Dog 析构
Animal 析构
~~~

# 五、多态

## 1. 什么是多态？

“多态”可以拆成：

- 多：多个
- 态：形态

意思是：

> 同一个接口，在不同对象上表现出不同的行为。

例如，所有动物都有 `speak()`，但：

- 狗执行时是“汪汪”
- 猫执行时是“喵喵”

~~~cpp
class Animal {
public:
    virtual void speak() {
        cout << "动物发出声音" << endl;
    }
};

class Dog : public Animal {
public:
    void speak() {
        cout << "汪汪" << endl;
    }
};

class Cat : public Animal {
public:
    void speak() {
        cout << "喵喵" << endl;
    }
};
~~~

如果不用多态：

~~~cpp
Dog dog;
Cat cat;

dog.speak();
cat.speak();
~~~

当然可以，但调用者必须知道具体是狗还是猫。

有了多态：

~~~cpp
void makeSpeak(Animal* animal) {
    animal->speak();
}
~~~

调用：

~~~cpp
Dog dog;
Cat cat;

makeSpeak(&dog);
makeSpeak(&cat);
~~~

输出：

~~~text
汪汪
喵喵
~~~

`makeSpeak()` 不需要知道传进来的是狗还是猫，只需要知道它是一个 `Animal`。

这就是多态的价值：

> 调用者只依赖抽象接口，不依赖具体类型。

# 六、为什么需要 `virtual`？

看下面的代码：

~~~cpp
class Animal {
public:
    void speak() {
        cout << "动物发声" << endl;
    }
};

class Dog : public Animal {
public:
    void speak() {
        cout << "汪汪" << endl;
    }
};
~~~

调用：

~~~cpp
Animal* p = new Dog();
p->speak();
~~~

很多新手会以为输出：

~~~text
汪汪
~~~

但实际输出：

~~~text
动物发声
~~~

为什么？

因为 `p` 的类型是：

~~~cpp
Animal*
~~~

默认情况下，C++ 根据**指针的类型**决定调用哪个函数。

虽然指针实际指向 `Dog`，但编译器只看到它是 `Animal*`。

## 加上 `virtual`

~~~cpp
class Animal {
public:
    virtual void speak() {
        cout << "动物发声" << endl;
    }
};
~~~

~~~cpp
class Dog : public Animal {
public:
    void speak() {
        cout << "汪汪" << endl;
    }
};
~~~

此时：

~~~cpp
Animal* p = new Dog();
p->speak();
~~~

输出：

~~~text
汪汪
~~~

因为 `virtual` 开启了运行时多态。

# 七、静态绑定和动态绑定

理解 `virtual` 的关键是理解“绑定”。

## 1. 静态绑定

函数调用在编译阶段就决定：

~~~cpp
Animal* p = new Dog();
p->speak();
~~~

如果 `speak()` 不是虚函数，编译器直接决定调用：

~~~cpp
Animal::speak()
~~~

这叫静态绑定，也叫早绑定。

## 2. 动态绑定

函数调用在运行时根据对象实际类型决定：

~~~cpp
Animal* p = new Dog();
p->speak();
~~~

如果 `speak()` 是虚函数，运行时发现 `p` 实际指向 `Dog`，于是调用：

~~~cpp
Dog::speak()
~~~

这叫动态绑定，也叫晚绑定。

可以简单记忆：

| 情况 | 决定依据 |
|---|---|
| 普通函数 | 指针或引用的类型 |
| 虚函数 | 实际对象的类型 |

# 八、`override` 是什么？

`override` 表示：

> 我明确告诉编译器：这个函数应该重写父类中的虚函数。

~~~cpp
class Animal {
public:
    virtual void speak() {
        cout << "动物发声" << endl;
    }
};

class Dog : public Animal {
public:
    void speak() override {
        cout << "汪汪" << endl;
    }
};
~~~

## 1. 为什么推荐使用 `override`？

考虑一个容易犯的错误：

~~~cpp
class Animal {
public:
    virtual void speak() const {
        cout << "动物发声" << endl;
    }
};

class Dog : public Animal {
public:
    void speak() { // 少了 const
        cout << "汪汪" << endl;
    }
};
~~~

这并没有真正重写父类函数，而是定义了一个新的函数。

~~~cpp
Animal* p = new Dog();
p->speak();
~~~

仍然会调用：

~~~text
动物发声
~~~

如果写成：

~~~cpp
void speak() override
~~~

编译器会报错，因为函数签名不一致。

这能及时发现：

- 函数名写错
- 参数类型不一致
- 返回值不一致
- 少了 `const`
- 引用限定符不一致

所以：

> `virtual` 是告诉父类函数支持多态；`override` 是告诉子类函数确实在重写父类函数。

# 九、重载、重写、隐藏的区别

这三个概念很容易混淆。

## 1. 重载 Overload

同一个类中，函数名相同，参数不同：

~~~cpp
class Printer {
public:
    void print(int x) {}
    void print(string s) {}
};
~~~

这是重载。

## 2. 重写 Override

子类重新定义父类的虚函数，函数签名必须匹配：

~~~cpp
class Animal {
public:
    virtual void speak() {}
};

class Dog : public Animal {
public:
    void speak() override {}
};
~~~

这是重写。

## 3. 隐藏 Hide

子类定义了同名函数，即使参数不同，也可能隐藏父类的同名函数：

~~~cpp
class Parent {
public:
    void show(int x) {}
};

class Child : public Parent {
public:
    void show(string s) {}
};
~~~

此时：

~~~cpp
Child c;
// c.show(10); // 可能报错，父类 show 被隐藏
~~~

可以使用：

~~~cpp
class Child : public Parent {
public:
    using Parent::show;

    void show(string s) {}
};
~~~

# 十、纯虚函数和抽象类

有时父类只想规定接口，不想提供具体实现。

~~~cpp
class Animal {
public:
    virtual void speak() = 0;
};
~~~

`= 0` 表示纯虚函数。

包含纯虚函数的类叫抽象类：

~~~cpp
Animal a; // 错误，不能创建抽象类对象
~~~

子类必须实现它：

~~~cpp
class Dog : public Animal {
public:
    void speak() override {
        cout << "汪汪" << endl;
    }
};
~~~

抽象类的作用是定义统一规范：

~~~cpp
class Shape {
public:
    virtual double area() = 0;
};
~~~

任何图形都必须实现 `area()`：

~~~cpp
class Circle : public Shape {
public:
    double area() override {
        return 3.14 * 5 * 5;
    }
};
~~~

# 十一、父类析构函数为什么通常要写 `virtual`？

看代码：

~~~cpp
class Animal {
public:
    ~Animal() {
        cout << "Animal 析构" << endl;
    }
};

class Dog : public Animal {
public:
    ~Dog() {
        cout << "Dog 析构" << endl;
    }
};
~~~

~~~cpp
Animal* p = new Dog();
delete p;
~~~

如果父类析构函数不是虚函数，可能只调用：

~~~text
Animal 析构
~~~

`Dog` 的析构函数没有调用，可能造成资源泄漏。

正确写法：

~~~cpp
class Animal {
public:
    virtual ~Animal() {
        cout << "Animal 析构" << endl;
    }
};
~~~

这样：

~~~cpp
Animal* p = new Dog();
delete p;
~~~

会调用：

~~~text
Dog 析构
Animal 析构
~~~

规则：

> 如果一个类可能被当作父类使用，并且会通过父类指针删除子类对象，父类析构函数应该是虚函数。

# 十二、虚函数内部是如何工作的？

为了支持运行时多态，C++ 通常会为包含虚函数的类建立一个虚函数表，简称 `vtable`。

对象内部通常有一个指向虚函数表的指针，叫 `vptr`。

大致过程：

~~~cpp
Animal* p = new Dog();
p->speak();
~~~

运行时：

1. `p` 指向一个 `Dog` 对象
2. 对象内部找到 `Dog` 的虚函数表
3. 查找 `speak()`
4. 调用 `Dog::speak()`

示意：

~~~text
Animal* p
   |
   v
Dog 对象
   |
   v
Dog 的虚函数表
   |
   v
Dog::speak()
~~~

注意：

- 这是常见实现方式
- C++ 标准没有强制规定必须用 `vtable`
- 使用虚函数通常会有少量运行时和内存开销

不过在绝大多数业务代码中，这种开销通常是值得的。

# 十三、对象、指针和引用对多态的影响

## 1. 直接对象

~~~cpp
Dog dog;
Animal animal = dog;
~~~

这里会发生对象切片，只保留 `Animal` 部分。

~~~cpp
animal.speak();
~~~

不会表现出完整的 `Dog` 行为。

## 2. 指针

~~~cpp
Animal* p = &dog;
p->speak();
~~~

如果函数是虚函数，可以实现多态。

## 3. 引用

~~~cpp
Animal& ref = dog;
ref.speak();
~~~

引用也可以实现多态。

通常推荐：

~~~cpp
void makeSpeak(const Animal& animal) {
    animal.speak();
}
~~~

这样既不复制对象，也支持多态。

# 十四、一个完整例子

~~~cpp
#include <iostream>
#include <vector>
using namespace std;

class Animal {
private:
    string name;

public:
    Animal(string name) : name(name) {}

    string getName() const {
        return name;
    }

    virtual void speak() const = 0;

    virtual ~Animal() = default;
};

class Dog : public Animal {
public:
    Dog(string name) : Animal(name) {}

    void speak() const override {
        cout << getName() << "：汪汪" << endl;
    }
};

class Cat : public Animal {
public:
    Cat(string name) : Animal(name) {}

    void speak() const override {
        cout << getName() << "：喵喵" << endl;
    }
};

int main() {
    Dog dog("小黑");
    Cat cat("小白");

    vector<Animal*> animals;
    animals.push_back(&dog);
    animals.push_back(&cat);

    for (Animal* animal : animals) {
        animal->speak();
    }

    return 0;
}
~~~

输出：

~~~text
小黑：汪汪
小白：喵喵
~~~

这里包含了：

- `Animal`：父类
- `Dog`、`Cat`：子类
- `private name`：封装
- `public` 继承：继承关系
- `virtual speak()`：虚函数
- `= 0`：纯虚函数
- `override`：重写确认
- `Animal*` 指向不同子类：多态
- `virtual ~Animal()`：安全析构

# 十五、最常见的错误

## 错误一：父类函数没有 `virtual`

~~~cpp
class Animal {
public:
    void speak() {}
};
~~~

通过父类指针调用时，不能实现运行时多态。

## 错误二：忘记写 `override`

~~~cpp
void speek() {} // 拼写错误
~~~

编译器可能不会提醒你这不是重写。

建议始终写：

~~~cpp
void speak() override
~~~

## 错误三：父类析构函数不是虚函数

~~~cpp
virtual ~Animal() = default;
~~~

这是多态基类的常见标准写法。

## 错误四：把“有一个”误认为“是一个”

~~~text
Dog 是 Animal：适合继承
Car 有 Engine：适合组合
~~~

不要为了复用代码而滥用继承。

## 错误五：直接使用裸指针管理资源

现代 C++ 更推荐：

~~~cpp
unique_ptr<Animal>
shared_ptr<Animal>
~~~

例如：

~~~cpp
vector<unique_ptr<Animal>> animals;

animals.push_back(make_unique<Dog>("小黑"));
animals.push_back(make_unique<Cat>("小白"));
~~~

这样可以自动释放内存。

# 十六、最后用一句话总结

- **封装**：保护内部数据，只暴露必要接口
- **继承**：子类复用父类，并扩展或修改功能
- **多态**：同一个父类接口，根据实际对象表现不同
- **`virtual`**：开启运行时多态
- **`override`**：确认子类函数确实重写了父类虚函数
- **虚析构函数**：保证通过父类指针删除子类对象时析构完整

最值得记住的代码模式是：

~~~cpp
class Base {
public:
    virtual void function() = 0;
    virtual ~Base() = default;
};

class Derived : public Base {
public:
    void function() override {
        // 子类自己的实现
    }
};
~~~

以及：

~~~cpp
Base* p = new Derived();
p->function(); // 调用 Derived 的实现
delete p;      // 安全析构
~~~
