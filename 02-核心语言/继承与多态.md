# 继承与多态

## 学习目标
- [ ] 理解基类、派生类以及“is-a”关系，能写出基本的继承声明。
- [ ] 区分 `public`、`protected`、`private` 成员和三种继承方式。
- [ ] 解释基类和派生类对象的构造、析构顺序，避免对象切片和未定义行为。
- [ ] 使用 `virtual`、`override` 和纯虚函数设计可扩展的多态接口。
- [ ] 正确处理多态对象的所有权，优先使用 RAII 和智能指针。
- [ ] 在 Windows 上使用 MSVC 或 MinGW-w64 编译并运行示例。

## 要点

## 1. 为什么需要继承与多态

假设程序要表示不同种类的员工：普通员工、经理和实习生。它们都具有姓名、编号等共同信息，但计算工资的规则不同。把共同部分复制到多个类中会造成重复；把所有逻辑挤进一个大类又会越来越难维护。

- **继承（inheritance）**：在已有类的基础上定义新类，让新类复用已有的接口和实现。已有类称为**基类**（base class），新类称为**派生类**（derived class）。
- **多态（polymorphism）**：同一个接口可以对应不同的实现。调用方只需要面对基类接口，运行时由实际对象决定执行哪个派生类版本。

继承适合表达稳定的“是一种”（is-a）关系：`Manager` 是一种 `Employee`，`Circle` 是一种 `Shape`。如果关系是“拥有”（has-a），通常应优先使用组合，例如 `Car` 拥有一个 `Engine`，而不是让 `Car` 继承 `Engine`。

## 2. 最基本的继承语法

~~~cpp
class Person {
public:
    void say_hello() const;

protected:
    int age_ = 0;             // 派生类可以访问，类外代码不能直接访问
};

class Student : public Person { // public 表示“Student 是一种 Person”
public:
    void study() const;
};
~~~

`Student` 对象中包含一个 `Person` 基类子对象，因此可以使用继承到的 `say_hello()`。但基类的构造函数不会被“继承为普通成员函数”：创建 `Student` 时，必须先构造 `Person` 子对象，再构造 `Student` 自己的成员。

### 2.1 三种访问权限

访问权限描述的是“谁能使用这个成员”，不是数据在内存中是否存在。

| 权限 | 基类成员函数 | 派生类成员函数 | 类外代码 |
| --- | --- | --- | --- |
| `public` | 可以 | 可以（通过继承得到） | 可以 |
| `protected` | 可以 | 可以 | 不可以 |
| `private` | 可以 | **不可以直接访问** | 不可以 |

派生类虽然包含基类的 `private` 数据，但只能通过基类提供的 `public`/`protected` 成员函数访问它。例如基类可以提供 `get_name()` 或 `set_name()`，而不是把数据直接改成 `protected`。这有助于保护类的不变量。

### 2.2 `public`、`protected`、`private` 继承

冒号后的关键字控制“基类接口在派生类中的可见性”。对初学者和绝大多数业务建模，通常使用 `public` 继承。

| 继承方式 | 基类 `public` 成员在派生类中的权限 | 基类 `protected` 成员在派生类中的权限 | 基类 `private` 成员 |
| --- | --- | --- | --- |
| `public` | `public` | `protected` | 仍不可直接访问 |
| `protected` | `protected` | `protected` | 仍不可直接访问 |
| `private` | `private` | `private` | 仍不可直接访问 |

如果省略继承方式，`class Derived : Base` 默认为 `private` 继承；若使用 `struct Derived : Base`，默认为 `public` 继承。默认值不同是常见陷阱，因此建议始终明确写出 `public`。

## 3. 派生类的构造与析构顺序

派生类构造时不能跳过基类。顺序固定为：虚基类（如有）→ 直接基类 → 成员（按声明顺序）→ 派生类构造函数体。析构顺序完全相反：先执行派生类析构函数体，再销毁成员，最后销毁基类子对象。

~~~cpp
#include <iostream>

class Base {
public:
    Base() { std::cout << "Base 构造\n"; }
    ~Base() { std::cout << "Base 析构\n"; }
};

class Derived : public Base {
public:
    Derived() { std::cout << "Derived 构造\n"; }
    ~Derived() { std::cout << "Derived 析构\n"; }
};

int main() {
    Derived value;
}
// 输出顺序：Base 构造、Derived 构造、Derived 析构、Base 析构
~~~

如果基类没有默认构造函数，派生类必须在初始化列表中明确调用某个基类构造函数：

~~~cpp
class Person {
public:
    explicit Person(const char* name) : name_(name) {}
private:
    const char* name_;
};

class Student : public Person {
public:
    Student(const char* name, int id)
        : Person(name), id_(id) {} // 先构造 Person，再初始化 id_
private:
    int id_;
};
~~~

注意：派生类不能在初始化列表中初始化基类的私有成员；只能调用基类构造函数，让基类自己完成初始化。

## 4. 向上转型、向下转型与对象切片

### 4.1 向上转型通常安全

派生类对象可以用基类引用或基类指针指向，这叫**向上转型**（upcasting）：

~~~cpp
Student student;                   // 使用前面示例中的默认构造
Person& person_ref = student;  // 引用不复制对象
Person* person_ptr = &student;  // 指针不拥有 student
~~~

`person_ref` 和 `person_ptr` 只能直接使用 `Person` 接口，但它们实际仍引用同一个 `Student` 对象。向上转型不会丢失对象，只是暂时用较窄的接口观察它。

### 4.2 按值传递会发生切片

如果把派生类对象按基类类型传值，函数只会得到一个新的基类子对象，派生类部分被“切掉”，这叫**对象切片**（object slicing）：

~~~cpp
void print_person(Person value);       // 按值：可能切片
void print_person(const Person& value); // 按引用：不会切片
void use_person(const Person* value);   // 按指针：不会切片，但要明确指针是否为空
~~~

需要多态行为时，应使用引用、指针或智能指针，而不是按基类值传递。

### 4.3 向下转型要谨慎

从基类指针/引用转回派生类叫**向下转型**（downcasting）。只有在确定实际对象类型时才可以这样做。对具有至少一个虚函数的多态基类，优先使用 `dynamic_cast`，失败时指针结果为 `nullptr`，引用形式会抛出 `std::bad_cast`：

~~~cpp
if (Student* p = dynamic_cast<Student*>(person_ptr)) {
    p->study(); // 确实是 Student 才执行
}
~~~

频繁向下转型往往说明基类接口设计得不够好；能通过虚函数解决时，不要把类型判断散落在业务代码中。

## 5. 虚函数与动态绑定：多态的核心

先看一个容易误解的例子：

~~~cpp
#include <iostream>

class Animal {
public:
    void speak() const { std::cout << "动物叫声\n"; }
};

class Dog : public Animal {
public:
    void speak() const { std::cout << "汪汪\n"; }
};

int main() {
    Dog dog;
    Animal* animal = &dog;
    animal->speak(); // 调用 Animal::speak，因为它不是 virtual
}
~~~

把基类函数声明为 `virtual` 后，基类指针/引用调用时会根据对象的实际类型选择函数，这就是**动态绑定**（运行时多态）：

~~~cpp
class Animal {
public:
    virtual void speak() const { std::cout << "动物叫声\n"; }
};

class Dog : public Animal {
public:
    void speak() const override { std::cout << "汪汪\n"; }
};
~~~

这里可以区分两个词：表达式或变量声明中写出的类型是**静态类型**（例如 `Animal*`），对象真正创建出来的类型是**动态类型**（例如 `Dog`）。只有通过指针或引用使用多态基类接口时，虚函数才会根据动态类型分派；直接写 `dog.speak()` 则不需要运行时查找。

`virtual` 应写在基类接口中；派生类用 `override` 明确表示“我要重写基类虚函数”。编译器会检查函数名、参数、`const`、引用限定符和返回类型是否匹配。推荐始终使用 `override`，它能及时发现拼写或签名错误。

虚函数的默认参数是另一个容易混淆的例外：默认参数按**静态类型**决定，函数体才按动态类型决定。因此不应在重写函数中更改默认参数，最好把默认值集中写在基类接口中。

### 5.1 重写、重载和隐藏不是一回事

- **重写（override）**：派生类重新实现基类的虚函数，签名必须匹配（允许协变返回类型）。
- **重载（overload）**：同一作用域中函数名相同但参数列表不同，例如 `print(int)` 和 `print(double)`。
- **隐藏（name hiding）**：派生类只要声明了同名函数，就可能隐藏基类同名的所有重载，即使参数不同。

~~~cpp
class Base {
public:
    virtual void draw(int) const {}
    void draw(double) const {}
};

class Derived : public Base {
public:
    void draw(int) const override {}
    // Derived d; d.draw(1.0); // Base::draw(double) 被同名函数隐藏
    using Base::draw;           // 如确实需要，可重新引入基类重载
};
~~~

若希望禁止继续重写，可以写 `final`：`void speak() const final;`。构造函数、析构函数和静态成员函数不能是虚函数；普通成员函数可以是虚函数。

### 5.2 `virtual` 的工作原理（理解层面）

实现通常会为含虚函数的类维护一张虚函数表（vtable），对象中保存指向相应表的隐藏指针。通过基类指针调用虚函数时，程序根据表项找到实际函数。具体布局属于编译器实现细节，不能依赖对象大小或 vtable 的存在方式；理解它只需知道：动态绑定会带来一次间接调用，换来运行时的可扩展性。

## 6. 纯虚函数与抽象类

如果基类只规定接口、不提供有意义的默认实现，可以把函数声明为**纯虚函数**：

~~~cpp
class Shape {
public:
    virtual double area() const = 0; // = 0 表示纯虚
    virtual ~Shape() = default;      // 多态基类通常需要虚析构
};
~~~

含有至少一个纯虚函数的类是**抽象类**，不能直接创建对象（`Shape s;` 会编译错误），但可以声明指针或引用。派生类只有实现所有纯虚函数后，才可以实例化：

~~~cpp
class Rectangle : public Shape {
public:
    Rectangle(double width, double height)
        : width_(width), height_(height) {}

    double area() const override { return width_ * height_; }

private:
    double width_;
    double height_;
};
~~~

抽象类常被称为“接口类”。接口类通常只放少量稳定的虚函数和一个虚析构函数，不要为了复用少量实现就强行建立复杂继承树。

## 7. 虚析构函数与多态对象的所有权

当对象可能通过基类指针销毁时，基类析构函数必须是 `virtual`：

~~~cpp
class Base {
public:
    virtual ~Base() = default;
};

class Derived : public Base {
public:
    ~Derived() override = default;
};

Base* p = new Derived;
delete p; // 安全：先 Derived 析构，再 Base 析构
~~~

如果 `Base::~Base()` 不是虚函数，`delete p` 的行为是未定义的；不能只凭“目前看起来能运行”判断它安全。反过来，如果类明确禁止通过基类指针删除对象，可以将析构函数设为 `protected`，或采用由专门工厂/派生类负责销毁的非虚析构设计；**非虚析构本身并不会让 `delete p` 变安全**。这是更高级的所有权设计，初学阶段应优先使用虚析构。

现代 C++ 更推荐让智能指针表达所有权：

~~~cpp
#include <memory>

std::unique_ptr<Shape> shape = std::make_unique<Rectangle>(3.0, 4.0);
// 离开作用域时自动 delete，Shape 的虚析构函数保证销毁完整
~~~

`std::unique_ptr` 表示唯一所有者，默认首选；`std::shared_ptr` 表示共享所有权，只有确实需要多个所有者时才使用。裸指针（`Shape*`）更适合表示“不拥有对象的观察者”，应在接口文档中说明这一点。

## 8. 构造、析构期间不要依赖多态

在基类构造函数执行时，派生类部分还没有构造完成；在基类析构函数执行时，派生类部分已经销毁。因此，构造/析构函数中调用虚函数不会分派到派生类版本，而是调用当前构造/析构层级的版本。更糟的是，若该层没有可用实现，还可能产生纯虚函数调用错误。

~~~cpp
class Base {
public:
    Base() { initialize(); } // 不会调用 Derived::initialize()
    virtual ~Base() = default;
    virtual void initialize() {}
};
~~~

需要派生类参与初始化时，可以提供普通的 `start()`、`initialize()` 等显式步骤，在完整构造对象后由调用方执行，或使用工厂函数完成创建和初始化。

## 9. 多继承与虚继承（入门）

C++ 允许一个类继承多个基类：

~~~cpp
class Printable { public: virtual void print() const = 0; virtual ~Printable() = default; };
class Serializable { public: virtual void save() const = 0; virtual ~Serializable() = default; };
class Report : public Printable, public Serializable { /* 实现两个接口 */ };
~~~

如果两个父类又共同继承同一个祖父类，可能出现“菱形继承”：最下层对象中有两份祖父类子对象，访问成员会产生歧义。使用 `virtual` 继承可以让它们共享一份虚基类，但会增加理解和初始化成本。初学者应先掌握单继承和多个纯接口的组合；只有确实需要共享同一个基类状态时再研究虚继承。

## 10. 继承还是组合：一个实用判断

继承意味着派生类应当能在需要基类的地方使用（里氏替换原则的直观版本）。如果派生类必须禁止基类的大量行为，或基类的公开接口并不适合它，那么继承关系可能是错误的。

- “`Dog` 是一种 `Animal`”通常适合 `public` 继承。
- “`Car` 拥有一个 `Engine`”通常适合成员对象：`class Car { Engine engine_; };`。
- 只想复用几个函数时，可以使用自由函数、组合、模板或委托，不必为了代码复用建立继承关系。

## 11. 常见错误与排查清单

1. 把 `class Derived : Base` 当成公开继承；`class` 默认是 `private` 继承，建议明确写 `: public Base`。
2. 派生类函数签名不一致却以为重写成功；给重写函数加 `override`，特别留意 `const` 和参数引用。
3. 通过基类指针调用非虚函数，结果不是派生类版本；需要动态绑定时在基类声明 `virtual`。
4. 基类析构函数非虚，却执行 `delete base_ptr`；多态基类应提供 `virtual ~Base() = default`。
5. 按值传递基类参数造成对象切片；多态接口改用 `const Base&`、`Base&` 或智能指针。
6. 在构造/析构函数中调用虚函数，误以为会访问最底层派生类；改为构造完成后的显式初始化步骤。
7. 用 `static_cast<Derived*>` 随意向下转型；不确定类型时使用 `dynamic_cast`，或重新设计基类接口。
8. 让基类拥有派生类细节（例如大量 `if (type == ...)`）；优先把变化行为放进虚函数中。
9. 返回或保存指向已销毁对象的基类指针/引用；明确对象生命周期和所有权，必要时用智能指针。
10. 以为虚函数调用一定“更好”；简单、非扩展场景使用普通函数或组合通常更直接，虚函数也有间接调用和设计成本。

## 示例与实践

### 1. 完整可运行示例：用多态计算不同图形的面积

下面程序演示了抽象基类、纯虚函数、`override`、`std::vector<std::unique_ptr<...>>` 和虚析构函数。它只依赖标准库，可在 Windows 的 MSVC、MinGW-w64 或其他 C++17 及以上编译器中运行。

~~~cpp
#include <iomanip>
#include <iostream>
#include <memory>
#include <numbers>  // C++20 的 std::numbers::pi
#include <vector>

class Shape {
public:
    virtual ~Shape() = default;             // 允许通过 Shape* 安全销毁
    virtual double area() const = 0;        // 每种图形必须实现面积
    virtual const char* name() const = 0;   // 返回用于演示的名称
};

class Rectangle final : public Shape {
public:
    Rectangle(double width, double height)
        : width_(width), height_(height) {}

    double area() const override { return width_ * height_; }
    const char* name() const override { return "矩形"; }

private:
    double width_;
    double height_;
};

class Circle final : public Shape {
public:
    explicit Circle(double radius) : radius_(radius) {}

    double area() const override {
        return std::numbers::pi * radius_ * radius_;
    }
    const char* name() const override { return "圆形"; }

private:
    double radius_;
};

int main() {
    // unique_ptr 表示 vector 拥有这些图形；对象离开 vector 时自动析构
    std::vector<std::unique_ptr<Shape>> shapes;
    shapes.push_back(std::make_unique<Rectangle>(3.0, 4.0));
    shapes.push_back(std::make_unique<Circle>(2.0));

    std::cout << std::fixed << std::setprecision(2);
    for (const auto& shape : shapes) {
        // shape 的静态类型是 unique_ptr<Shape>，但调用会动态绑定到实际类型
        std::cout << shape->name() << "面积：" << shape->area() << '\n';
    }
}
~~~

在 Visual Studio Developer PowerShell 中：

~~~powershell
cl /std:c++20 /W4 /EHsc shape_demo.cpp /Fe:shape_demo.exe
.\shape_demo.exe
~~~

在已配置 MinGW-w64 的 PowerShell 中：

~~~powershell
g++ -std=c++20 -Wall -Wextra -pedantic shape_demo.cpp -o shape_demo.exe
.\shape_demo.exe
~~~

如果编译器只支持 C++17，把 `std::numbers::pi` 换成常量 `constexpr double pi = 3.141592653589793;`，并使用 `-std=c++17` 或 `/std:c++17` 即可。

### 2. 观察切片与虚函数调用

可以把示例中的 `Shape` 再写两个函数进行对比：

~~~cpp
void inspect_by_value(Shape shape);       // 抽象类不能按值传递，且一般会切片
void inspect_by_reference(const Shape& shape); // 推荐的只读多态接口
~~~

由于 `Shape` 是抽象类，`inspect_by_value` 本身就无法实例化参数；在非抽象基类中，按值传递则会发生切片。练习时可先移除纯虚函数、提供普通实现，再观察按值和按引用调用的差异。

### 3. 练习建议

1. 为 `Shape` 增加 `perimeter()` 纯虚函数，让矩形和圆形分别实现周长。
2. 新增 `Triangle` 类，确认没有实现全部纯虚函数时会出现什么编译错误。
3. 把 `std::unique_ptr` 临时改成裸指针，记录谁负责 `delete`，再改回智能指针并解释改进之处。
4. 编写 `Animal`、`Dog`、`Cat`，分别测试普通函数、虚函数和 `override` 拼写错误。
5. 写一个接收 `const Shape&` 的函数，尝试传入不同图形，说明为什么不需要 `dynamic_cast`。
6. 创建一个没有虚析构函数的基类，用基类指针删除派生类（仅作为理解未定义行为的实验，不要在生产代码中这样做）。

完成后应能回答：

- 为什么 `public` 继承要表达“是一种”，而“拥有”关系通常用组合？
- `virtual`、`override` 和纯虚函数各自解决什么问题？
- 为什么多态对象常通过引用、指针或 `std::unique_ptr` 使用？
- 基类析构函数什么时候必须是虚函数？
- 构造/析构期间调用虚函数为什么不会得到最底层派生类行为？
