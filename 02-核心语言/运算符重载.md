# 运算符重载

## 学习目标
- [ ] 理解运算符重载的本质、语法和适用边界。
- [ ] 能为一个值类型设计自然、对称且符合直觉的算术和比较运算符。
- [ ] 区分成员运算符函数、非成员运算符函数和友元运算符函数。
- [ ] 正确实现前置/后置自增自减、复合赋值、下标和流插入等常见运算符。
- [ ] 理解返回值、`const`、引用和异常安全对运算符接口的影响。
- [ ] 在 Windows 上使用 MSVC 或 MinGW-w64 编译并运行示例，识别常见错误。

## 要点

## 1. 什么是运算符重载

我们已经习惯了下面这些内置类型的写法：

~~~cpp
int a = 1;
int b = 2;
int sum = a + b;
~~~

这里的 `+` 是运算符，编译器知道两个 `int` 相加应该如何计算。但是，编译器并不知道两个 `Point` 对象相加是什么意思：是横纵坐标分别相加，还是计算距离，还是合并成一条线？

**运算符重载（operator overloading）**就是为自定义类型定义运算规则，让对象可以使用熟悉的运算符表达式。例如，若为 `Point` 定义了 `operator+`，就可以写成：

~~~cpp
Point left(1, 2);
Point right(3, 4);
Point result = left + right; // 等价于“横坐标相加、纵坐标相加”
~~~

运算符重载本质上仍然是一个函数，只是函数名采用 `operator` 加运算符的形式：

~~~cpp
// 这是一个普通的成员函数声明
Point operator+(const Point& other) const;

// 使用时可以写成更易读的运算符表达式
result = left + right;

// 对成员函数而言，可以把上面的表达式粗略理解为：
result = left.operator+(right);
~~~

如果运算符函数是非成员函数，也可以把表达式粗略理解为 `operator+(left, right)`。实际调用哪个候选函数仍由 C++ 的重载决议决定，但“运算符只是特殊函数”这个理解足以帮助我们入门。

运算符重载的目的不是让代码“看起来更神奇”，而是让类型的操作方式和它表达的概念一致。日期可以相减得到时间间隔，复数可以相加，矩阵可以相乘；这些都是比较自然的语义。若一个运算符的含义必须反复查文档才能猜到，通常就应该使用普通的、有描述性的成员函数。

## 2. 运算符重载能做什么、不能做什么

### 2.1 必须至少涉及一个自定义类型

普通运算符重载至少有一个操作数是类类型或枚举类型。不能通过运算符重载改变两个内置类型的行为：

~~~cpp
// 错误示意：不能为两个 int 定义新的 operator+
/* int operator+(int left, int right); */
~~~

这样做会破坏语言和标准库对基本类型的统一理解。若需要新的计算规则，应使用普通函数，例如 `add_safely(left, right)`。

### 2.2 不能改变运算符的基本形状

运算符重载有明确的边界：

- 不能发明新的运算符。只能重载 C++ 已有的运算符。
- 不能改变优先级和结合性。例如 `*` 仍然比 `+` 优先，不能通过重载改变。
- 不能改变操作数个数。二元 `+` 仍然需要两个操作数，一元 `-` 仍然只有一个操作数。
- 不能把运算符重载成任意数量的参数。成员函数和非成员函数的参数数量规则见下一节。
- 不能保证内置运算符的特殊求值行为。尤其是重载 `&&` 和 `||` 后，两侧通常都会被求值，不再具有内置运算符的短路特性。

下面这些常见运算符不能重载：

~~~text
::     .      .*     ?:     sizeof     typeid     alignof     noexcept
~~~

虽然不能重载 `.`，但可以重载 `->`，这是为了支持智能指针和迭代器一类的“像指针一样使用”的对象。

### 2.3 运算符语义应当符合直觉

重载成功不等于设计成功。一般建议遵循这些约定：

| 运算符 | 常见语义 | 通常的返回类型 |
| --- | --- | --- |
| `+`、`-`、`*`、`/` | 产生一个新的值，不修改操作数 | 按值返回 `T` |
| `+=`、`-=`、`*=`、`/=` | 修改左操作数 | 返回 `T&` |
| `==`、`!=`、`<` 等 | 比较对象的值 | 返回 `bool` |
| 前置 `++x`、`--x` | 修改对象后返回新状态 | 返回 `T&` |
| 后置 `x++`、`x--` | 保存旧状态，再修改对象 | 按值返回旧状态 |
| `<<`、`>>` | 向流写入或从流读取 | 返回 `std::ostream&` 或 `std::istream&` |

例如，`a + b` 如果悄悄修改 `a`，调用者会很难排查问题；`a += b` 修改 `a` 则符合大家对复合赋值的预期。

## 3. 成员函数与非成员函数

### 3.1 作为成员函数重载

成员运算符函数属于类，可以直接访问对象的私有成员。对于二元运算符，左操作数会成为隐含的当前对象，因此函数参数中只需要写右操作数：

~~~cpp
class Point {
public:
    Point(int x, int y) : x_(x), y_(y) {}

    // 左操作数是 *this，参数 other 是右操作数
    Point operator+(const Point& other) const {
        return Point(x_ + other.x_, y_ + other.y_);
    }

private:
    int x_;
    int y_;
};

Point a(1, 2);
Point b(3, 4);
Point c = a + b; // 大致相当于 a.operator+(b)
~~~

成员函数适合以下情况：

- 运算符必须修改当前对象，例如 `operator+=`、`operator=`。
- 运算符天然需要访问当前对象的内部状态。
- 希望左侧操作数必须是当前类的对象。

在 C++17 中，`operator=`、`operator[]`、`operator()`、`operator->` 等运算符应作为非静态成员函数实现。本章按 C++17 的写法讲解；较新的 C++ 标准对个别运算符增加了更多形式，但不影响这里的基本规则。

### 3.2 作为非成员函数重载

非成员运算符函数通常把所有操作数都显式写在参数中：

~~~cpp
class Point {
public:
    Point(int x, int y) : x_(x), y_(y) {}

    int x() const { return x_; }
    int y() const { return y_; }

private:
    int x_;
    int y_;
};

Point operator+(const Point& left, const Point& right) {
    return Point(left.x() + right.x(), left.y() + right.y());
}
~~~

非成员函数尤其适合对称的二元运算符，例如 `+`、`-`、`==` 和 `<`。因为左右两侧地位相同，使用非成员函数也更容易让两侧都参与隐式转换。例如下面的形式中，若转换构造函数允许把某种类型转换为 `Point`，非成员函数能让左侧和右侧都有机会参与转换；成员函数只能把右侧作为参数转换，左侧必须先已经是 `Point`。

~~~cpp
// 成员形式：左侧必须先是 Point
left_point + right_value;

// 非成员形式：两个操作数都作为普通参数参与重载决议
left_value + right_point;
~~~

不过，“能发生隐式转换”不代表“应该允许隐式转换”。为了避免意外的类型转换，转换构造函数通常应加 `explicit`。运算符选择应首先服从清晰的类型设计。

### 3.3 友元运算符函数

非成员函数不能直接访问类的 `private` 成员。如果运算符确实需要访问内部表示，可以在类中把它声明为 `friend`：

~~~cpp
class Point {
public:
    Point(int x, int y) : x_(x), y_(y) {}

    friend Point operator+(const Point& left, const Point& right);

private:
    int x_;
    int y_;
};

Point operator+(const Point& left, const Point& right) {
    // friend 让这个非成员函数可以访问 private 成员
    return Point(left.x_ + right.x_, left.y_ + right.y_);
}
~~~

注意：即使 `operator+` 的声明写在类里面，它仍然是**非成员函数**，没有 `this` 指针；`friend` 只是授予访问私有成员的权限。只有在公开接口无法合理完成工作时才使用友元，否则优先通过公开的查询函数实现，以减少耦合。

### 3.4 如何选择

可以先使用下面的经验判断：

1. `operator=`、`operator+=` 等会改变左侧对象的运算符，放在类中实现。
2. `operator<<` 的左侧是 `std::ostream`，不是自定义类型，通常必须写成非成员函数。
3. 对称的 `+`、`-`、`==` 等，通常优先考虑非成员函数；需要私有访问时再使用友元。
4. 若运算符的语义和普通成员操作一样只属于当前对象，成员函数更直观。
## 4. 从 `+=` 设计 `+`：一组常见模式

算术运算符通常成组设计。先实现会修改对象的 `operator+=`，再用它实现不修改原对象的 `operator+`，可以减少重复代码：

~~~cpp
class Value {
public:
    explicit Value(int number) : number_(number) {}

    Value& operator+=(const Value& other) {
        number_ += other.number_;
        return *this; // 返回当前对象，支持 a += b += c
    }

    friend Value operator+(Value left, const Value& right) {
        left += right; // left 是副本，因此不会修改调用者的原对象
        return left;
    }

private:
    int number_;
};
~~~

这里的 `left` 故意按值传递：`a + b` 调用时先复制一个 `a`，然后在副本上执行 `+=`，最后按值返回副本。这样可以复用逻辑，同时保持 `a` 不变。若类型很大，复制成本需要结合移动语义和异常安全进一步优化，但初学阶段应先保证语义正确。

几个返回值规则很重要：

- `operator+` 返回新对象，所以按值返回，不能返回局部对象的引用。
- `operator+=` 修改当前对象，返回 `*this` 的引用，才能支持 `a += b += c`。
- 只读的算术和比较运算符应加末尾的 `const`，这样 `const` 对象也能参与运算。
- 返回 `const T&` 并不能让 `operator+` 更高效，反而容易返回悬空引用；新结果应按值返回。

## 5. 常见运算符的具体写法

### 5.1 比较运算符：比较值，不要比较地址

值类型的 `operator==` 应比较有意义的状态，而不是比较两个对象的内存地址：

~~~cpp
class Pixel {
public:
    Pixel(int red, int green, int blue)
        : red_(red), green_(green), blue_(blue) {}

    bool operator==(const Pixel& other) const {
        return red_ == other.red_
            && green_ == other.green_
            && blue_ == other.blue_;
    }

private:
    int red_;
    int green_;
    int blue_;
};

Pixel first(255, 0, 0);
Pixel second(255, 0, 0);
// first == second 为 true：三个颜色分量相同
// &first == &second 为 false：它们仍然是两个不同对象
~~~

比较函数一般声明为 `const`，因为比较不应改变对象。C++17 中如果需要 `!=`，通常也要自己定义；C++20 对比较运算符的候选生成和重写规则更丰富，但初学时仍应明确写出自己希望支持的接口，不要依赖难以理解的“魔法”。

### 5.2 流插入运算符 `<<`

希望写出 `std::cout << object` 时，左操作数是 `std::ostream`，所以 `operator<<` 通常是非成员函数：

~~~cpp
std::ostream& operator<<(std::ostream& out, const Pixel& pixel) {
    // 按约定返回原来的流，才能继续写：std::cout << a << b;
    out << "(" << pixel.red() << ", "
        << pixel.green() << ", "
        << pixel.blue() << ")";
    return out;
}
~~~

上面的例子假定 `Pixel` 提供了 `red()`、`green()` 和 `blue()` 这类公开查询函数。如果没有这些函数，也可以把它声明为 `friend` 来访问私有成员。不要把返回类型写成 `void`，否则 `std::cout << a << b` 的链式调用会在第一个对象后中断。

输入运算符 `>>` 遵循类似规则，通常返回 `std::istream&`。当输入格式错误时，应设置流的失败状态或让流自身完成格式处理，不要悄悄把非法输入当成合法值。

### 5.3 前置和后置 `++`、`--`

前置和后置形式都叫 `operator++`，C++ 用一个没有实际用途的 `int` 参数区分它们：

~~~cpp
class Counter {
public:
    explicit Counter(int value = 0) : value_(value) {}

    // 前置：先加一，再返回新状态
    Counter& operator++() {
        ++value_;
        return *this;
    }

    // 后置：先保存旧状态，再加一，返回旧副本
    Counter operator++(int) {
        Counter old(*this);
        ++value_;
        return old;
    }

    int value() const { return value_; }

private:
    int value_;
};
~~~

调用者不需要、也不能通过普通表达式给后置版本传入这个 `int`：

~~~cpp
Counter counter(5);
Counter a = ++counter; // counter 为 6，a 也是 6
Counter b = counter++; // b 为 6，counter 之后变为 7
~~~

前置版本返回引用，避免不必要的复制；后置版本必须返回修改前的旧值，因此通常按值返回。对只需要递增、不需要旧值的代码，前置形式通常更直接。

### 5.4 下标运算符 `[]`

下标运算符通常返回元素的引用，这样既能读取，也能修改元素；同时提供 `const` 重载，保证只读对象也能访问：

~~~cpp
class IntList {
public:
    int& operator[](std::size_t index) {
        return values_.at(index);
    }

    const int& operator[](std::size_t index) const {
        return values_.at(index);
    }

private:
    std::vector<int> values_;
};
~~~

这里有两个需要分开的问题：**返回值类型**决定能否修改原容器，**下标范围**决定访问是否越界。

如果 `operator[]` 返回 `int` 而不是 `int&`，读取时得到的是元素的副本：

~~~cpp
int value = numbers[1]; // value 是副本
value = 42;             // 只修改 value，容器中的元素不会改变
~~~

对于普通的 `int` 返回值，直接写 `numbers[1] = 42` 通常会编译错误，因为返回的临时值不能作为可修改的左值。只有返回 `int&` 时，`numbers[1] = 42` 才能真正修改容器中的元素。

返回引用与是否越界是两个独立问题。上例使用 `vector::at`，因此下标超出范围时会抛出 `std::out_of_range`；标准库 `std::vector::operator[]` 则不会检查范围，越界访问会产生未定义行为。接口采用哪种行为，应在文档中明确说明。

### 5.5 函数调用运算符 `()`

重载 `operator()` 后，对象可以像函数一样被调用，这类对象常称为**函数对象（functor）**：

~~~cpp
class Multiplier {
public:
    explicit Multiplier(int factor) : factor_(factor) {}

    int operator()(int value) const {
        return value * factor_;
    }

private:
    int factor_;
};

Multiplier twice(2);
int result = twice(21); // 调用 twice.operator()(21)，结果为 42
~~~

标准库算法、排序比较器和带状态的回调经常使用函数对象。若只需要一个很短的一次性行为，Lambda 表达式通常更简洁；需要保存状态、复用类型或提供多个重载时，函数对象更合适。

### 5.6 转换运算符 `operator bool`

类可以定义从自身转换到其他类型的转换运算符。最常见的是表示对象是否有效的 `operator bool`：

~~~cpp
class Connection {
public:
    explicit Connection(bool connected) : connected_(connected) {}

    explicit operator bool() const {
        return connected_;
    }

private:
    bool connected_;
};

Connection connection(true);
if (connection) { // if 允许这种“条件上下文转换”
    // 连接可用
}

// int number = connection; // 错误：explicit 防止继续隐式转换为 int
~~~

`explicit` 很重要。若转换运算符不加 `explicit`，对象可能在不相关的算术、比较或函数调用中被意外转换，产生难以发现的重载选择问题。除非转换几乎总是符合调用者预期，否则不要轻易提供隐式转换。

### 5.7 赋值运算符与编译器生成的函数

赋值和相等比较是两个完全不同的概念：

~~~cpp
a = b;  // 把 b 的状态赋给已经存在的 a
a == b; // 判断 a 和 b 的值是否相等
~~~

如果没有手动声明，编译器通常会为类生成拷贝赋值运算符；类成员是 `std::string`、`std::vector` 等正常值类型时，默认行为通常正是我们想要的。手写赋值运算符时，通常应返回 `T&`：

~~~cpp
class Number {
public:
    Number& operator=(const Number& other) {
        if (this != &other) { // 防止自己给自己赋值时破坏数据
            value_ = other.value_;
        }
        return *this;          // 支持 a = b = c
    }

private:
    int value_ = 0;
};
~~~

如果类自己管理文件句柄、动态数组或其他资源，拷贝赋值、拷贝构造、移动操作和析构函数必须整体设计，不能只随手补一个 `operator=`。现代 C++ 通常优先把资源交给 `std::string`、`std::vector`、智能指针等 RAII 类型，遵循“零法则”；对象生命周期与资源管理请参见[[对象生命周期与RAII]]和[[智能指针]]。

## 6. 完整可运行示例一：设计一个 `Money` 值类型

下面的程序用“分”为单位保存金额，避免使用 `double` 保存货币时的二进制浮点误差。它演示了：

- `operator+=` 作为成员函数修改当前对象。
- `operator+` 作为友元非成员函数，复用 `operator+=` 并按值返回。
- `operator==`、`operator!=` 和 `operator<` 比较金额值。
- `operator<<` 作为非成员函数输出对象。
- `const` 成员函数和 `const` 引用参数的使用。

请把下面代码保存为 `money_operator_demo.cpp`：

~~~cpp
#include <iomanip>
#include <iostream>

class Money {
public:
    // 内部统一使用“分”保存金额，例如 123456 表示 1234.56 元
    explicit Money(long long cents) : cents_(cents) {}

    long long cents() const {
        return cents_;
    }

    Money& operator+=(const Money& other) {
        cents_ += other.cents_;
        return *this; // 返回当前对象，支持 total += a += b
    }

    friend Money operator+(Money left, const Money& right) {
        // left 是副本，在副本上修改不会影响调用者的原对象
        left += right;
        return left;
    }

    friend bool operator==(const Money& left, const Money& right) {
        return left.cents_ == right.cents_;
    }

    friend bool operator!=(const Money& left, const Money& right) {
        return !(left == right);
    }

    friend bool operator<(const Money& left, const Money& right) {
        return left.cents_ < right.cents_;
    }

    friend std::ostream& operator<<(std::ostream& out, const Money& money) {
        // 本示例的输入金额均为非负数，因此这样格式化即可
        const long long yuan = money.cents_ / 100;
        const long long fen = money.cents_ % 100;
        out << yuan << '.' << std::setw(2) << std::setfill('0') << fen
            << " 元";
        out << std::setfill(' '); // 恢复流的填充字符，减少对后续输出的影响
        return out;
    }

private:
    long long cents_;
};

int main() {
    const Money salary(123456); // 1234.56 元
    const Money bonus(5000);    // 50.00 元

    Money total = salary + bonus; // 调用 operator+，salary 和 bonus 不改变
    std::cout << "工资加奖金：" << total << '\n';

    total += Money(1000); // 调用成员 operator+=，total 变为 1294.56 元
    std::cout << "加上补贴后：" << total << '\n';

    std::cout << std::boolalpha;
    std::cout << "工资是否小于总额：" << (salary < total) << '\n';
    std::cout << "奖金是否等于 50 元：" << (bonus == Money(5000)) << '\n';
}
~~~

## 7. 完整可运行示例二：前置与后置自增

请把下面代码保存为 `counter_operator_demo.cpp`：

~~~cpp
#include <iostream>

class Counter {
public:
    explicit Counter(int value = 0) : value_(value) {}

    int value() const {
        return value_;
    }

    Counter& operator++() {
        ++value_;
        return *this; // 前置 ++ 返回递增后的当前对象
    }

    Counter operator++(int) {
        Counter old(*this); // 先保存旧状态
        ++value_;
        return old;         // 后置 ++ 返回旧副本
    }

private:
    int value_;
};

int main() {
    Counter counter(5);

    Counter& after_prefix = ++counter;
    std::cout << "执行 ++counter 后，counter = " << counter.value()
              << "，返回值 = " << after_prefix.value() << '\n';

    Counter before_postfix = counter++;
    std::cout << "执行 counter++ 后，旧返回值 = " << before_postfix.value()
              << "，counter = " << counter.value() << '\n';
}
~~~

编译运行命令与上一个示例相同，只需替换源文件名和生成的程序名：

~~~powershell
cl /std:c++17 /W4 /EHsc counter_operator_demo.cpp /Fe:counter_operator_demo.exe
.\counter_operator_demo.exe

g++ -std=c++17 -Wall -Wextra -pedantic counter_operator_demo.cpp -o counter_operator_demo.exe
.\counter_operator_demo.exe
~~~

如果在同一个 PowerShell 窗口中连续执行两套命令，第二套会覆盖同名的 `.exe`，这不影响示例；实际使用时选择已经安装的编译器即可。

## 8. 完整可运行示例三：实现可读写的下标运算符

这个示例使用 `std::vector<int>` 保存数据，并故意通过 `at()` 检查越界。它展示了非 `const` 对象和 `const` 对象需要两套 `operator[]`：

请把代码保存为 `int_list_operator_demo.cpp`：

~~~cpp
#include <cstddef>
#include <initializer_list>
#include <iostream>
#include <stdexcept>
#include <vector>

class IntList {
public:
    IntList(std::initializer_list<int> values) : values_(values) {}

    // 非 const 对象调用这个版本，返回可修改的引用
    int& operator[](std::size_t index) {
        return values_.at(index);
    }

    // const 对象调用这个版本，只能读取，不能修改
    const int& operator[](std::size_t index) const {
        return values_.at(index);
    }

    std::size_t size() const {
        return values_.size();
    }

private:
    std::vector<int> values_;
};

int main() {
    IntList numbers{10, 20, 30};
    numbers[1] = 42; // 返回 int&，所以可以修改原来的元素

    std::cout << "numbers[1] = " << numbers[1] << '\n';

    const IntList readonly{1, 2, 3};
    std::cout << "readonly[0] = " << readonly[0] << '\n';
    // readonly[0] = 9; // 错误：const 版本返回 const int&，不能修改

    try {
        std::cout << numbers[10] << '\n'; // at() 检查越界并抛出异常
    } catch (const std::out_of_range& error) {
        std::cout << "访问失败：" << error.what() << '\n';
    }
}
~~~

在 Windows PowerShell 中编译：

~~~powershell

.\int_list_operator_demo.exe

g++ -std=c++17 -Wall -Wextra -pedantic int_list_operator_demo.cpp -o int_list_operator_demo.exe
.\int_list_operator_demo.exe
~~~

## 9. 常见错误与排查清单

1. **把运算符函数写成了普通函数却忘记作用域**：类外定义成员运算符时要写 `Point Point::operator+(...) const`，不能漏掉 `Point::` 或末尾的 `const`。
2. **把成员函数和非成员函数的参数个数弄混**：成员二元运算符只有一个显式参数；非成员二元运算符有两个显式参数。
3. **忘记给只读运算符加 `const`**：`operator+`、`operator==`、`operator<<` 常常不会修改对象，应使用 `const` 参数或 `const` 成员函数。
4. **用引用返回临时结果**：`operator+` 中的局部结果离开函数后会销毁，必须按值返回，不能返回 `T&` 或 `const T&`。
5. **`operator+=` 返回 `void`**：这样会破坏 `a += b += c` 这类链式表达式，通常应返回 `T&` 并返回 `*this`。
6. **后置 `++` 忘记写占位参数**：前置是 `operator++()`，后置是 `operator++(int)`。这个 `int` 只是签名标记，调用时不传值。
7. **让 `operator<<` 返回 `void`**：流插入应返回传入的 `std::ostream&`，否则无法继续 `std::cout << a << b`。
8. **把 `=` 和 `==` 混淆**：`=` 是赋值，`==` 是比较；为一个类定义了 `operator=`，并不会自动得到按值比较的 `operator==`。
9. **下标返回值而不是引用**：返回 `int` 会让 `list[0] = 1` 只修改临时副本；可写下标通常返回 `T&`，只读重载通常返回 `const T&`。
10. **误以为重载 `&&`、`||` 还能短路**：它们重载后是函数调用形式，不能依赖内置逻辑运算符的短路行为。
11. **为了少写代码而提供危险的隐式转换**：没有 `explicit` 的单参数构造函数或转换运算符，可能让对象参与意外的运算。先问自己“这种转换是否几乎总是合理”，否则使用 `explicit`。
12. **只为“能编译”而重载运算符**：如果运算符的语义不自然，普通成员函数通常更清楚，例如用 `rotate()` 比用 `+` 表示旋转更容易理解。
13. **手写资源类的赋值运算符不完整**：类若管理裸指针、句柄或文件资源，必须同时考虑拷贝、移动和析构；优先使用标准 RAII 类型。

## 10. 学习路线与自测

建议按下面顺序练习：

1. 为二维 `Point` 实现 `operator+`、`operator-` 和 `operator==`，验证算术不会修改原对象。
2. 为 `Point` 添加 `operator+=`，让 `operator+` 复用它，并测试 `a += b += c`。
3. 为一个简单的 `Temperature` 类实现比较运算符，思考摄氏度和华氏度是否应该允许隐式转换。
4. 为自定义容器实现 `operator[]` 的 `const` 和非 `const` 版本，并测试越界行为。
5. 写一个 `operator<<`，观察返回 `std::ostream&` 与返回 `void` 对链式输出的影响。
6. 修改 `Counter` 的前置和后置自增实现，分别记录“返回值”和“对象当前值”，解释两者为什么不同。
