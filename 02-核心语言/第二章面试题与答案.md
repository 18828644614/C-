# 第二章面试题与答案

## 面试官总体判断

第二章考查的不是“会不会写一个类”，而是候选人能否把以下几条线连起来：

1. 用封装维护对象不变量；
2. 用构造、析构和成员初始化建立正确生命周期；
3. 用 RAII 表达资源所有权，并保证异常路径不泄漏；
4. 用继承、虚函数和接口表达可替换性；
5. 用异常安全保证和 `noexcept` 设计失败路径；
6. 用运算符重载表达自然的值类型语义。

面试中，如果只回答“`virtual` 是实现多态的”“析构函数释放内存”，通常只能说明记住了关键词。更好的回答要包含：适用条件、对象模型、生命周期、所有权、未定义行为和工程取舍。

## 使用方式

- 第一遍先只看问题标题，尝试在两分钟内口头回答。
- 第二遍阅读“参考答案”和“面试官追问”，补齐条件、例外和风险。
- 现场代码题先预测输出或指出未定义行为，再说明语言规则，最后给出修正版。
- 本文中的“必须”表示语言规则或安全前提；“通常”表示工程约定，回答时要区分二者。

## 一、类、对象与封装

### 1. 类和对象有什么区别？类定义本身是否占用对象存储空间？

**参考答案：**

类是用户定义的类型，描述数据成员、成员函数、访问权限和继承关系；对象是这个类型的一个具体实例，具有自己的存储空间和生命周期。写出 `class Student { ... };` 只是声明一种类型，不会因此创建一个 `Student` 对象；执行 `Student alice;` 后，`alice` 才是一个对象。

非静态数据成员通常属于每个对象，各对象有自己的值。成员函数的代码通常由同一类型的对象共享，不会因为创建十个对象就复制十份函数代码。静态数据成员属于类，通常不计入每个对象各自的一份实例状态。

类的对象布局还可能包含对齐填充，不能简单地把成员大小相加。即使是空类，标准也要求不同对象具有可区分的地址，因此 `sizeof(Empty)` 通常至少为 `1`。类的大小、布局和虚函数实现细节不能作为跨编译器的稳定协议。

**面试官追问：**

- 类中只有静态成员时，对象是否仍然有大小？有，空对象仍必须有非零大小。
- 成员函数是否存储在对象里？通常不按每个对象复制，但具体布局属于实现细节。
- `sizeof` 能否用来推断所有成员总大小？不能忽略对齐、填充、基类和实现细节。

### 2. `class` 和 `struct` 有什么区别？

**参考答案：**

两者都可以拥有数据成员、成员函数、构造函数、析构函数、继承和模板等能力，核心语言能力没有“`struct` 不能有函数”这种限制。主要默认差异有两个：

- `class` 的默认成员访问权限是 `private`，默认继承方式也是 `private`；
- `struct` 的默认成员访问权限是 `public`，默认继承方式也是 `public`。

工程中常把 `struct` 用作简单的数据聚合，把 `class` 用作需要隐藏实现和维护不变量的类型，但这是约定而不是语言强制规则。实际设计仍应显式写出 `public`、`private` 和继承方式，避免读者依赖默认值。

### 3. 为什么数据成员通常设为 `private`？封装到底解决了什么问题？

**参考答案：**

封装把状态和操作状态的接口放在同一个类型中，并限制外部直接修改内部表示。它的价值不只是“防止别人访问变量”，更重要的是让类可以维护不变量。例如余额不能为负、端口号必须在合法范围、对象建立后句柄必须有效。

如果 `balance_` 是 `public`，任何调用者都可以直接写入非法值，类无法保证后续成员函数面对的是合法状态。将它设为 `private`，通过 `deposit()`、`withdraw()` 等有业务含义的操作修改，类就能集中校验条件。这样以后把内部表示从 `double` 改成整数分、数据库句柄或其他结构时，外部代码也不必跟着修改。

封装不等于“所有成员都必须有 getter/setter”。机械地公开所有字段仍然会泄漏表示细节；公开接口应表达允许的操作，而不是暴露内部布局。

### 4. `public`、`protected`、`private` 的区别是什么？为什么通常不鼓励大量使用 `protected` 数据？

**参考答案：**

`public` 成员构成类对外可用的接口，类外、派生类和类自身都可以访问。`protected` 成员可被类自身和派生类访问，但普通类外代码不能直接访问。`private` 成员只能由类自身的成员函数、友元等受语言规则允许的代码访问，派生类不能直接访问基类的私有成员。

基类的私有成员仍然是派生对象的一部分，只是派生类必须通过基类提供的 `public` 或 `protected` 函数间接使用它。大量暴露 `protected` 数据会让每个派生类都依赖基类内部表示，基类以后修改布局或校验规则时容易破坏派生类。更稳妥的做法是把数据保持为 `private`，通过受控的 `protected`/`public` 操作暴露必要能力。

### 5. `const` 成员函数是什么？为什么它不能通过 `const` 对象调用普通成员函数？

**参考答案：**

成员函数末尾的 `const` 表示该函数承诺不修改当前对象的非 `mutable` 状态。例如：

```cpp
class Temperature {
public:
    double value() const { return value_; }
    void set_value(double value) { value_ = value; }

private:
    double value_ = 0.0;
};
```

`const Temperature t;` 只能调用 `value() const`，不能调用可能修改对象的 `set_value()`。这不是复制对象，也不表示对象一定位于只读内存；它是编译器对成员函数访问当前对象方式的约束。`mutable` 成员可以在 `const` 成员函数中修改，常用于缓存或统计信息，但应保持对调用者可见的对象语义不变。

普通成员函数可以把隐含的 `this` 看作指向对象的指针；在 `const` 成员函数中，它近似为指向 `const` 对象的指针，因此不能通过它修改普通成员。

### 6. 静态成员函数为什么不能使用 `this`？静态数据成员和普通数据成员有什么区别？

**参考答案：**

普通数据成员属于某个对象，每个对象都有一份；静态数据成员属于整个类，所有对象共享一份。静态成员函数属于类本身，可以用 `ClassName::function()` 调用，不需要先创建对象，因此没有特定的当前对象，也就没有 `this` 指针。

静态成员函数可以直接访问静态成员，不能直接访问非静态成员，因为后者需要知道操作哪一个对象。如果确实需要操作对象，应把对象作为参数传入，或使用普通成员函数。C++17 的 `inline static` 数据成员可以在类内定义；较早标准通常需要在某个 `.cpp` 文件中提供类外定义。

### 7. 友元是什么？友元会不会被继承或传递？

**参考答案：**

`friend` 可以授权指定的非成员函数、成员函数或其他类访问当前类的 `private` 和 `protected` 成员。典型用途是实现对称的运算符或紧密协作的序列化函数。友元函数虽然声明写在类里面，但它仍然是非成员函数，没有 `this`。

友元关系不是继承关系，也不会传递。A 是 B 的友元，不代表 A 的调用者、A 的派生类或 B 的派生类自动获得相同权限。友元会增加耦合，应优先通过公开接口完成工作；只有公开接口不能自然表达操作或会造成不必要复制时，才考虑友元。

### 8. 对象、引用和指针在可空性和所有权上有什么区别？

**参考答案：**

对象本身代表一个实体，通常拥有自己的生命周期。引用是已有对象的别名，必须初始化，不能改绑，通常用来表达“调用时必须有一个有效对象”。指针保存地址，可以为空，也可以改变指向，适合表达“对象可能不存在”或与旧式 C API 交互。

它们默认都不表示所有权。`Student&`、`Student*` 指向一个对象，不代表调用者可以 `delete` 它；是否拥有资源必须由接口文档或智能指针类型明确表达。对象用 `.` 调用成员，指针用 `->`，但对空指针使用 `->` 会产生未定义行为。

### 9. 继承和组合如何选择？

**参考答案：**

公共继承应表达稳定的“是一种”（is-a）关系，并满足可以用基类接口替换派生类的直觉。例如 `Circle` 是一种 `Shape`。组合表达“拥有”或“由什么组成”（has-a），例如 `Car` 拥有一个 `Engine`，更适合写成成员对象。

仅仅为了复用几行代码就使用继承，会把基类的全部公开接口和生命周期约束带给派生类，容易违反里氏替换原则。如果派生类必须禁用基类的大量行为，或者调用者不应把它当作基类使用，通常应考虑组合、委托、自由函数或模板。

## 二、构造、析构与特殊成员函数

### 10. 构造函数和析构函数分别做什么？构造函数为什么不能是 `virtual`？

**参考答案：**

构造函数在对象创建时建立初始状态、校验参数并获取必要资源；析构函数在对象生命周期结束时释放对象拥有的资源。构造函数没有返回类型，名字与类名相同，可以重载；析构函数名字是 `~类名`，没有参数和返回值，不能重载。

构造函数不能是 `virtual`，因为虚函数调用依赖一个已经存在且类型信息完整的对象，而构造函数执行时对象仍在分层构造，派生部分还没有建立。若需要“根据类型创建对象”，应使用工厂函数或工厂类；工厂内部仍然调用普通构造函数。

### 11. 什么情况下编译器会生成默认构造函数？声明带参构造后还能否 `T value;`？

**参考答案：**

如果类没有声明任何构造函数，编译器通常会尝试隐式生成默认构造函数；但如果成员或基类无法默认构造，这个默认构造函数可能被定义为删除状态，不能实际使用。一旦类声明了带参构造函数，编译器不会再自动补一个无参构造函数：

```cpp
class Id {
public:
    explicit Id(int value) : value_(value) {}

private:
    int value_;
};

// Id id;             // 错误，没有可用的默认构造函数
Id id{42};            // 正确
```

如果业务确实需要无参构造，可以写 `Id() = default;` 或自己实现；如果类型不应该被默认构造或复制，可以用 `= delete` 明确禁止，减少调用者误用。

### 12. `explicit` 解决什么问题？

**参考答案：**

只有一个有效参数的构造函数可能成为转换构造函数，允许编译器在函数调用、赋值或重载决议中隐式创建对象：

```cpp
class Meters {
public:
    explicit Meters(double value) : value_(value) {}

private:
    double value_;
};

void use(Meters distance);
// use(3.0);            // explicit 后不能隐式转换
use(Meters{3.0});       // 明确构造
```

`explicit` 能防止金额、单位、ID 等概念被普通数值悄悄混用。只有当转换几乎总是符合调用者直觉时，才应考虑允许隐式转换。现代 C++ 也常把转换运算符 `operator bool` 声明为 `explicit`，只允许它在 `if` 等条件上下文中使用。

### 13. 为什么成员初始化列表比构造函数体内赋值更重要？

**参考答案：**

进入构造函数体之前，基类子对象和成员已经按照语言规则开始或完成初始化。初始化列表是真正初始化成员的地方；构造函数体内的 `member_ = value;` 是对已经构造好的成员做赋值。

以下成员必须或基本必须使用初始化列表：

- `const` 成员；
- 引用成员；
- 没有默认构造函数的成员对象；
- 基类子对象。

即使成员可以默认构造后再赋值，初始化列表也通常更高效：直接构造目标状态，避免“先默认构造、再赋值”。

### 14. 成员初始化顺序由什么决定？初始化列表的书写顺序能改变它吗？

**参考答案：**

实际顺序固定为：虚基类、直接基类、非静态数据成员（按类内声明顺序）、构造函数体。初始化列表的文字顺序不能改变成员的实际初始化顺序：

```cpp
class Example {
public:
    Example() : second_(first_), first_(10) {}

private:
    int first_;
    int second_;
};
```

这里仍然先初始化 `first_`，再初始化 `second_`。应让初始化列表顺序与成员声明顺序一致；如果成员之间有依赖，也应让被依赖的成员先声明。编译器通常会对列表顺序和声明顺序不一致发出警告。

### 15. 什么是委托构造？它有什么价值？

**参考答案：**

C++11 起，一个构造函数可以把初始化工作委托给同类的另一个构造函数：

```cpp
class Rectangle {
public:
    Rectangle() : Rectangle(1, 1) {}
    Rectangle(int width, int height)
        : width_(width), height_(height) {}

private:
    int width_;
    int height_;
};
```

委托构造可以集中参数校验和状态建立逻辑，避免不同构造函数之间出现不一致。委托目标构造函数完成成员初始化后，委托构造函数自己的函数体才会执行；同一构造函数不能同时初始化成员并再委托给另一个构造函数。

### 16. 对象的析构顺序是什么？

**参考答案：**

同一作用域中，局部对象按构造顺序的逆序析构。一个派生类对象销毁时，顺序是：先执行派生类析构函数体，再按成员声明顺序的逆序销毁成员，然后销毁直接基类，最后销毁虚基类（如果有）。类析构函数体执行时，成员和基类子对象还没有销毁。

例如：

```cpp
Logger logger;
std::ofstream file;
```

离开作用域时先析构 `file`，再析构 `logger`。如果 `file` 的清理依赖 `logger` 仍然存在，这样的声明顺序就可能错误；更好的设计是减少跨成员的销毁顺序依赖。

### 17. 析构函数为什么不能重载？手动调用析构函数有什么风险？

**参考答案：**

对象离开作用域、执行 `delete` 或容器销毁时，语言规则只需要无参数地结束对象生命周期，因此析构函数没有参数选择过程，不能重载。不同清理策略应设计为普通成员函数，例如 `close()`、`flush()` 或 `commit()`；析构函数负责最终且必须完成的清理。

普通自动对象不应手动调用析构函数：

```cpp
Widget value;
value.~Widget(); // 对象生命周期已结束，但作用域结束时还会再次析构
```

这通常导致重复释放或其他未定义行为。手动析构只在极少数配合 placement `new`、自定义存储管理的场景中使用，并且必须同时精确管理对象生命周期和存储空间。

### 18. 拷贝构造、拷贝赋值、移动构造和移动赋值有什么区别？

**参考答案：**

核心区别是目标对象是否已经存在：

```cpp
Widget a;              // 普通构造
Widget b = a;          // b 尚未存在：拷贝构造
b = a;                 // b 已存在：拷贝赋值
Widget c = Widget{};   // 通常使用移动或直接构造，可能被拷贝消除
Widget d = std::move(a); // 移动构造
```

拷贝通常表示复制值或资源；移动通常把资源控制权转移给新对象，避免深层复制。被移动的源对象仍然存在，但一般只保证处于“有效、可析构、可重新赋值”的状态，不应假定它保留原来的值。

`std::move` 本身不移动资源，它只是把表达式转换成可被移动构造或移动赋值优先匹配的右值类别。真正的移动由目标类型的特殊成员函数完成。

### 19. 什么是 Rule of 0、Rule of 3 和 Rule of 5？

**参考答案：**

如果类使用 `std::string`、`std::vector`、智能指针等 RAII 成员管理资源，通常不需要自己声明析构、拷贝和移动操作，这叫 Rule of 0。让成员类型负责资源管理，代码更容易保证异常安全。

如果类直接拥有裸资源并声明了其中一个析构函数、拷贝构造函数或拷贝赋值运算符，通常要一起设计这三个特殊成员函数，这叫 Rule of 3。C++11 之后还要考虑移动构造和移动赋值，于是扩展为 Rule of 5。

裸指针的默认拷贝通常只是复制地址，可能造成两个对象释放同一资源。此时应明确选择：深拷贝、禁止复制、只允许移动，或把资源改为标准 RAII 成员。面试中，直接回答“编译器会自动生成拷贝构造，所以没问题”通常是不合格的资源管理答案。

### 20. 什么时候基类析构函数必须是 `virtual`？

**参考答案：**

当一个类作为多态基类使用，并且可能通过基类指针或基类智能指针删除派生类对象时，基类析构函数必须是虚函数：

```cpp
class Base {
public:
    virtual ~Base() = default;
    virtual void run() const = 0;
};

class Derived : public Base {
public:
    void run() const override {}
};

std::unique_ptr<Base> value = std::make_unique<Derived>();
```

销毁 `value` 时，虚析构保证先执行 `Derived` 的析构，再执行 `Base` 的析构。若通过 `Base*` 删除 `Derived` 而基类析构非虚，行为是未定义的，而不是简单地“只少调用一次析构函数”。

如果类明确不允许通过基类指针删除对象，可以采用受保护析构、专门销毁接口等设计；但不能在基类析构非虚时继续执行 `delete base_ptr`。是否加虚析构要看多态删除需求，不是所有基类都必须无条件加上。

## 三、对象生命周期、RAII 与所有权

### 21. 作用域、存储期、对象生命周期和资源生命周期有什么区别？

**参考答案：**

作用域描述名字在源代码中的可见范围；存储期描述存储空间从获得到释放的类别，例如自动、动态、静态和线程存储期；对象生命周期是某个对象从初始化完成到销毁的时间；资源生命周期则是文件、锁、连接或操作系统句柄从取得到归还的时间。

局部对象常在作用域结束时销毁，所以初学者容易认为它们是同一个概念；动态对象则可能没有对应的局部名字，必须由 `delete` 或智能指针决定何时销毁。指针变量结束，不等于它指向的动态对象结束；指针只是地址容器，默认不拥有目标对象。

### 22. 临时对象的生命周期何时结束？为什么 `string_view` 容易悬空？

**参考答案：**

临时对象通常存活到所在完整表达式结束。某些局部引用绑定可以延长临时对象的生命周期：

```cpp
const std::string& name = make_name();
```

此时临时字符串通常存活到 `name` 所在作用域结束。但这种规则有明确例外，不能把引用当作通用的保活机制。特别是从函数返回局部对象或临时对象的引用，函数返回后引用会悬空。

`std::string_view` 只保存字符区间的观察视图，不拥有字符串，也不会延长其生命周期：

```cpp
std::string_view view{std::string("temporary")};
// 初始化语句结束后，临时 string 可能已经销毁
```

使用 `string_view` 时必须确认底层字符串在整个视图使用期间仍然存在。

### 23. 什么是 RAII？它为什么能处理异常路径？

**参考答案：**

RAII 是 Resource Acquisition Is Initialization，核心思想是把资源所有权绑定到对象生命周期：构造函数取得资源并建立有效状态，析构函数释放资源。局部 RAII 对象无论通过正常返回、提前 `return` 还是异常离开作用域，都会在离开作用域时析构，因此清理逻辑不需要散落在每个分支中。

```cpp
void work() {
    std::lock_guard<std::mutex> lock(mutex);
    do_work();
} // 正常返回或异常传播时都自动解锁
```

RAII 不是“异常会自动清理所有资源”。栈展开只会调用已经构造完成的自动对象析构函数；裸指针、裸句柄和手写资源如果没有放进 RAII 所有者，仍然会泄漏。现代 C++ 优先使用容器、智能指针、文件流、锁守卫或自定义资源包装类。

### 24. `unique_ptr`、`shared_ptr` 和 `weak_ptr` 应该如何选择？

**参考答案：**

`std::unique_ptr<T>` 表示唯一所有权，不能复制，只能移动，通常是动态多态对象的默认选择。`std::shared_ptr<T>` 表示多个所有者共同管理同一对象，复制会增加引用计数，最后一个所有者销毁时对象才被销毁。`std::weak_ptr<T>` 不拥有对象，不增加引用计数，使用前通过 `lock()` 临时取得一个 `shared_ptr`，常用于观察者、父指针和打破循环引用。

`shared_ptr` 不是“更安全的裸指针”：它有控制块和引用计数开销，不能自动解决对象内部的数据竞争，也不能解决循环引用。只有当所有权确实共享时才使用它；如果只是借用，优先用引用、裸观察指针或 `weak_ptr`，并明确生命周期前提。

### 25. `unique_ptr::get()`、`release()` 和 `reset()` 分别做什么？

**参考答案：**

- `get()` 只返回被管理对象的裸地址，不转移所有权，调用者不能因此 `delete` 该地址。
- `reset()` 释放当前拥有的对象，然后可以接管新的指针；释放动作由删除器完成。
- `release()` 放弃所有权并返回裸指针，智能指针不再负责释放，调用者从此必须接管清理责任。

`release()` 很容易重新引入泄漏，通常只在必须把所有权交给某个明确约定的 C API 时使用。动态对象通常应使用 `std::make_unique`，避免手写 `new` 和异常路径上的泄漏。

### 26. 静态对象初始化顺序有什么风险？

**参考答案：**

同一个源文件中的静态对象初始化顺序通常按定义顺序建立，但不同源文件中的命名空间作用域对象初始化顺序可能不适合建立依赖。如果一个全局对象在初始化时使用另一个文件中的全局对象，可能出现静态初始化顺序问题。

常见改进是使用函数内局部静态对象：

```cpp
Logger& global_logger() {
    static Logger logger;
    return logger;
}
```

C++11 起，函数局部静态对象的初始化是线程安全的，并且在第一次使用时发生。但这并不能替代清晰的依赖设计，复杂全局资源仍应考虑显式初始化和显式销毁顺序。

## 四、异常处理与异常安全

### 27. `try`、`throw` 和 `catch` 各自负责什么？

**参考答案：**

`try` 标记一段可能抛出异常的代码，它本身不会捕获错误；`throw` 抛出异常对象并立即改变控制流，抛出点之后的当前路径不再继续；`catch` 声明能够处理的异常类型，并在匹配时执行处理逻辑。

工程代码通常抛出继承自 `std::exception` 的标准异常或自定义异常，而不是整数、字符串字面量或裸指针。异常类型表达错误类别，`what()` 提供诊断文字，不应让业务逻辑依赖某个实现的具体错误字符串。

### 28. 为什么通常按 `const` 引用捕获异常？多个 `catch` 为什么要从具体到一般？

**参考答案：**

推荐：

```cpp
try {
    read_configuration();
} catch (const std::invalid_argument& error) {
    // 更具体的处理
} catch (const std::exception& error) {
    // 通用处理
}
```

按 `const` 引用捕获可以避免复制异常对象，保留动态类型和派生类信息，并表达处理器不会修改异常对象。派生异常要写在基类异常前，因为处理器从上到下匹配；如果先写 `catch (const std::exception&)`，它会匹配所有标准派生异常，后面的具体处理器将不可达。

`catch (...)` 可以匹配任意异常类型，但拿不到类型和消息，通常只作为最后的兜底处理器。兜底处理后应记录、恢复或重新抛出，不能无条件吞掉错误。

### 29. `throw;` 和 `throw error;` 有什么区别？

**参考答案：**

在 `catch` 中，单独写 `throw;` 表示原样重新抛出当前正在处理的异常对象，保留其动态类型和异常信息：

```cpp
catch (const std::exception& error) {
    log(error.what());
    throw;             // 原样继续传播
}
```

写 `throw error;` 则是把捕获变量当作普通表达式重新抛出，可能按静态类型复制对象并发生切片；它不是严格意义上的原样重抛。如果需要转换异常类型，可以明确抛出新的业务异常，并决定是否用嵌套异常保留原始原因。

### 30. 什么是栈展开？构造函数抛异常时哪些析构函数会执行？

**参考答案：**

异常从抛出点向调用者传播时，C++ 会离开沿途作用域，并析构已经成功构造的自动对象，这个过程叫栈展开。局部 RAII 对象会被清理，所以异常路径也能关闭文件、释放锁和销毁容器。

如果一个对象的构造函数抛出异常，这个完整对象不算构造成功，因此不会调用它自身的析构函数；但已经成功构造的成员、基类子对象会按照规则自动析构。这也是资源应尽早交给 RAII 成员管理的原因：不要把裸资源先放在普通字段里，再期待外层对象自身析构来收尾。

### 31. 基本保证、强保证和不抛保证分别是什么？

**参考答案：**

- 基本保证：异常发生后不泄漏资源，不变量仍成立，对象保持有效，但状态可能已经改变。
- 强保证：异常发生后外部可观察状态保持不变，操作具有“要么全部成功，要么像没有发生”的效果。
- 不抛保证：操作保证不会让异常逃出函数，例如常见的析构、交换或标记为 `noexcept` 的移动操作。

常用的强保证实现方式是“准备—提交”：先在临时对象中完成可能失败的操作，全部成功后用 `swap` 或一次提交更新原对象。异常安全不是靠多写几个 `catch` 获得的，而是由资源所有权、对象不变量和更新顺序共同决定。

### 32. `noexcept` 是什么？为什么移动构造函数常常要正确标记它？

**参考答案：**

`noexcept` 是函数不允许异常逃出的契约，不是“函数内部绝对不会发生任何错误”，也不是自动捕获机制。如果异常从 `noexcept` 函数逃出，程序会调用 `std::terminate()`，外层普通 `catch` 通常接不到它。

析构函数通常应保持不抛，尤其不能在另一个异常传播时再抛出第二个异常。移动构造和移动赋值如果确实不会抛，也常标记为 `noexcept`；标准容器扩容搬移元素时，可能根据移动操作是否不抛来选择移动还是拷贝，以维持异常安全和性能。

不能为了“看起来现代”而随意加 `noexcept`。如果函数内部确实可能把异常推出去，就要修正设计、捕获处理，或不作虚假的不抛承诺。

### 33. 什么时候应该抛异常，什么时候返回状态或 `optional`？

**参考答案：**

异常适合表示当前层无法恢复、需要跨越多层调用传播的失败，例如配置加载、资源初始化或底层错误需要由上层统一记录。应在最早能准确发现错误的地方抛出，在最有能力恢复的地方捕获。

预期的分支结果、用户输入校验、查找不到元素等情况，如果调用者经常需要判断，返回 `bool`、`std::optional`、`std::expected` 或错误码往往更直观。异常不应作为普通循环控制工具，也不能修复数组越界、释放后使用和数据竞争等未定义行为。

## 五、继承、虚函数与多态

### 34. 三种继承方式如何影响基类接口？为什么 `class Derived : Base` 容易出错？

**参考答案：**

在公共继承中，基类 `public` 成员在派生类中仍是 `public`，基类 `protected` 仍是 `protected`；在 `protected` 继承中，基类的 `public` 和 `protected` 成员都变成 `protected`；在 `private` 继承中，它们都变成 `private`。基类私有成员始终不能被派生类直接访问。

省略继承方式时，`class` 默认是 `private` 继承，`struct` 默认是 `public` 继承：

```cpp
class Derived : Base {};  // private 继承
struct Derived : Base {}; // public 继承
```

表达“派生类是一种基类”时应明确写 `public`，不要依赖默认值，否则类外向上转型可能被禁止，接口语义也不清楚。

### 35. 静态类型、动态类型、向上转型和向下转型分别是什么？

**参考答案：**

```cpp
Base* pointer = new Derived;
```

`pointer` 的静态类型是 `Base*`，决定编译器允许直接访问哪些成员；它指向对象的动态类型是 `Derived`，决定虚函数运行时可能调用哪个实现。公共继承下，派生类指针转换为基类指针是安全的向上转型，因为派生对象包含一个基类子对象。

基类指针转派生类指针是向下转型，不能隐式完成，因为一个普通基类对象不一定真的属于该派生类。对于具有多态性质的基类，运行时不确定时应使用 `dynamic_cast` 并检查指针结果是否为 `nullptr`，或重新设计接口避免到处判断具体类型。频繁向下转型通常说明抽象接口不够好。

### 36. `virtual`、`override` 和普通同名函数分别解决什么问题？

**参考答案：**

基类把接口声明为 `virtual`，表示通过基类指针或引用调用时可以根据对象的动态类型进行运行时分派。派生类用 `override` 表示“我明确要重写某个基类虚函数”，编译器会检查函数名、参数、`const`、引用限定符和返回类型是否匹配。

```cpp
class Animal {
public:
    virtual void speak() const {}
};

class Dog : public Animal {
public:
    void speak() const override {}
};
```

如果派生类漏写 `const`，没有 `override` 时可能悄悄定义出一个新函数，基类指针调用仍执行基类版本；写上 `override` 后编译器会直接报告错误。`virtual` 是基类开启多态的设计；`override` 是派生类验证重写关系的保护。

### 37. 重载、重写和隐藏有什么区别？如何解除名称隐藏？

**参考答案：**

- 重载：同一作用域中函数名相同，参数列表不同，例如 `print(int)` 和 `print(double)`。
- 重写：派生类用匹配的签名重新实现基类虚函数。
- 隐藏：派生类声明了同名函数后，可能把基类的所有同名重载隐藏，即使参数不同。

```cpp
class Base {
public:
    virtual void draw(int) const {}
    void draw(double) const {}
};

class Derived : public Base {
public:
    using Base::draw;
    void draw(int) const override {}
};
```

`using Base::draw;` 可以把基类同名重载重新引入派生类作用域。面试时要特别说明：名称隐藏不等于重写，重写必须满足虚函数签名规则。

### 38. 什么是纯虚函数和抽象类？纯虚函数可以有实现吗？

**参考答案：**

纯虚函数使用 `= 0` 声明，表示基类要求派生类提供实现；含有至少一个纯虚函数的类是抽象类，不能直接创建对象，但可以创建指针或引用。派生类只有实现全部纯虚函数后才能实例化。

```cpp
class Shape {
public:
    virtual double area() const = 0;
    virtual ~Shape() = default;
};
```

纯虚函数在某些情况下仍然可以提供类外定义，但这不改变基类的抽象性质，也不意味着可以直接构造抽象类。通常接口类应保持接口少而稳定，并提供虚析构函数以支持多态销毁。

### 39. 什么是对象切片？为什么多态接口通常使用引用、指针或智能指针？

**参考答案：**

派生类对象按基类值传递或初始化时，只会复制其中的基类子对象，派生类新增状态和动态类型信息不会保留，这叫对象切片：

```cpp
void use(Base value);          // 可能切片
void use(const Base& value);   // 不切片，且不拥有对象
void use(const Base* value);   // 不切片，但可能为空
```

需要运行时多态时，使用基类引用、基类指针或 `std::unique_ptr<Base>`。如果接口确实需要独立的基类值，就应明确接受切片或设计虚拟复制、值语义包装器等机制，而不是把切片当作多态。

### 40. 为什么构造函数和析构函数中调用虚函数不会得到最底层派生类行为？

**参考答案：**

构造基类部分时，派生类成员还没有构造完成；析构基类部分时，派生类成员已经销毁。因此在构造或析构期间，虚函数不会分派到最底层派生类版本，而是按当前正在构造或析构的层级处理。这样可以避免调用尚未初始化或已经失效的派生成员。

如果需要派生类参与初始化，应把操作设计成对象完整构造后的显式 `start()`、`initialize()`，或由工厂函数在构造完成后调用。不要在基类构造函数中调用依赖派生状态的虚函数；如果调用了纯虚函数，还可能出现纯虚函数调用错误。

### 41. 解释虚函数的常见实现方式，以及面试中不应做的假设。

**参考答案：**

许多编译器会为含虚函数的类生成虚函数表（vtable），对象中保存一个指向相应表的隐藏指针（常称 vptr）。通过基类指针调用虚函数时，运行时根据对象的动态类型找到对应表项并间接调用派生实现。

这是理解动态绑定成本的常用模型，但 C++ 标准没有强制规定必须使用 vtable，也没有规定对象布局、隐藏指针位置或表的具体内容。不能依赖“对象大小一定增加一个指针”“vtable 地址可直接读取”或某个编译器布局来设计可移植代码。虚函数通常有间接调用和对象布局成本，但换来接口稳定性和运行时扩展能力；是否使用应由设计和性能证据决定。

### 42. 多继承和虚继承解决什么问题？为什么仍要谨慎？

**参考答案：**

多继承允许一个类同时实现多个接口，例如 `Printable` 和 `Serializable`。如果两个父类又共同继承一个祖父类，会形成菱形继承，最底层对象中可能存在两份祖父类子对象，访问成员会产生歧义。

虚继承让多个路径共享一份虚基类子对象，可以解决重复基类状态问题，但会增加构造规则、布局和理解成本。面试回答时应说明：多个纯接口的继承可以是合理的；复杂状态复用则应先考虑组合。不要把“能继承”直接等同于“应该继承”。

## 六、运算符重载与值类型设计

### 43. 运算符重载有什么限制？

**参考答案：**

运算符重载本质上是特殊命名的函数。普通重载至少要有一个操作数是类类型或枚举类型，不能重新定义两个 `int` 相加的含义；只能重载语言已有的运算符，不能发明新运算符；不能改变优先级、结合性或操作数个数。

`::`、`.`、`.*`、`?:`、`sizeof`、`typeid`、`alignof`、`noexcept` 等不能被重载。尤其要注意，重载 `&&` 和 `||` 后通常不再具有内置运算符的短路求值语义，因此不要为了语法好看而改变调用者对副作用的预期。

运算符的语义应符合直觉：`a + b` 通常生成新值且不修改操作数，`a += b` 修改左操作数，比较运算符比较值而不是地址。

### 44. 运算符应该实现为成员函数、非成员函数还是友元？

**参考答案：**

会修改左操作数或必须依赖当前对象的运算符通常适合作为成员函数，例如 `operator=`、`operator+=`、`operator[]`。对称的二元运算符，如 `+`、`-`、`==`，通常适合作为非成员函数，因为左右操作数地位相同，双方都可以参与隐式转换；如果需要访问私有成员，再将其声明为友元。

流插入运算符必须考虑左侧是 `std::ostream`，所以通常写成非成员函数：

```cpp
std::ostream& operator<<(std::ostream& out, const Money& value);
```

成员运算符的左操作数必须是当前类对象，而非成员函数可以自然表达两侧的对称性。最终选择应以语义、隐式转换和封装边界为准，不能只背“某个运算符一定是成员”。

### 45. 为什么通常先实现 `operator+=`，再用它实现 `operator+`？返回值应是什么？

**参考答案：**

`operator+=` 修改当前对象，通常返回 `T&`，这样可以支持链式写法并避免复制：

```cpp
Value& operator+=(const Value& other) {
    value_ += other.value_;
    return *this;
}
```

`operator+` 应保持两个操作数不变并返回一个新值，通常按值返回：

```cpp
friend Value operator+(Value left, const Value& right) {
    left += right;
    return left;
}
```

这里按值接收 `left`，在副本上修改，既复用逻辑又不破坏调用者对象。不要为了“避免复制”返回局部结果的引用；局部对象函数返回后就会销毁，引用会悬空。返回值优化和移动语义通常会处理必要的临时对象成本。

### 46. 前置 `++` 和后置 `++` 如何区分？为什么后置版本多一个 `int` 参数？

**参考答案：**

C++ 用一个没有实际业务意义的 `int` 参数区分后置形式：

```cpp
Counter& operator++() {       // 前置 ++x
    ++value_;
    return *this;
}

Counter operator++(int) {     // 后置 x++
    Counter old(*this);
    ++value_;
    return old;
}
```

前置版本先修改再返回新状态，通常返回 `T&`；后置版本必须保存旧值、修改对象、再按值返回旧副本。调用者写 `counter++` 时不需要手动传入那个 `int`。如果不需要旧值，前置版本通常少一次复制，更适合循环和性能敏感代码。

### 47. 下标运算符为什么通常要同时提供 `const` 和非 `const` 版本？`[]` 是否检查越界？

**参考答案：**

容器类通常提供两个重载：非 `const` 对象返回 `T&`，允许修改元素；`const` 对象返回 `const T&`，只能读取：

```cpp
int& operator[](std::size_t index) { return values_.at(index); }
const int& operator[](std::size_t index) const { return values_.at(index); }
```

返回引用决定调用者能否修改原元素；是否检查范围是另一个问题。示例调用 `vector::at()`，越界会抛出 `std::out_of_range`；标准 `vector::operator[]` 不做范围检查，越界访问是未定义行为。接口应明确性能和安全取舍，不能因为返回了引用就误以为自动检查边界。

### 48. 为什么 `operator<<` 要返回 `std::ostream&`？

**参考答案：**

流插入运算符通常写成：

```cpp
std::ostream& operator<<(std::ostream& out, const Pixel& pixel) {
    out << pixel.red() << ',' << pixel.green();
    return out;
}
```

返回原来的流是为了支持链式调用：`std::cout << first << second;`。如果返回 `void`，第一个自定义对象输出后就无法继续把结果送入下一个 `<<`。运算符通常是非成员函数，因为左操作数是流；如果需要访问私有状态，可以用公开查询函数或谨慎使用友元。

### 49. `operator bool` 为什么通常要写 `explicit`？

**参考答案：**

`operator bool` 常用来表示连接、文件或句柄是否有效。写成 `explicit operator bool() const` 后，对象可以在 `if (connection)` 这类条件上下文中转换为布尔值，但不能轻易参与整数运算或无关的重载选择，减少隐式转换风险。

如果转换运算符不加 `explicit`，对象可能被自动转换成 `int`、参与算术或被传给错误的重载。只有转换几乎总是符合所有调用者预期时，才应允许隐式转换。

### 50. `operator=` 和 `operator==` 有什么区别？手写赋值运算符要注意什么？

**参考答案：**

`operator=` 是赋值，把右侧对象的状态写入已经存在的左侧对象；`operator==` 是比较，判断两个对象的值是否相等。它们表达完全不同的操作，返回类型和副作用也不同。

手写赋值运算符通常返回 `T&`，支持 `a = b = c`，并应考虑自赋值：

```cpp
Number& operator=(const Number& other) {
    if (this != &other) {
        value_ = other.value_;
    }
    return *this;
}
```

如果类管理资源，不能只补一个 `operator=` 就结束；拷贝构造、移动操作和析构函数必须整体设计。优先把资源交给 RAII 成员，遵循 Rule of 0。

## 七、现场代码题与参考答案

### 51. 下面代码的构造和析构输出顺序是什么？

```cpp
struct Trace {
    explicit Trace(const char* name) : name(name) {
        std::cout << "construct " << name << '\n';
    }

    ~Trace() { std::cout << "destroy " << name << '\n'; }
    const char* name;
};

struct Base {
    Trace base{"base"};
};

struct Derived : Base {
    Trace first{"first"};
    Trace second{"second"};
};

int main() {
    Derived value;
}
```

**参考答案：**

构造顺序是：`base`、`first`、`second`。派生类对象先构造基类子对象，再按成员声明顺序构造自己的成员。

析构顺序是：`second`、`first`、`base`。析构函数体如果存在，会先执行当前类析构函数体，然后才按逆序销毁成员和基类。这个题的关键是不能按照初始化列表文字顺序猜，也不能认为成员和基类由声明位置混合排序。

### 52. 下面代码有什么问题？如何修复？

```cpp
class Base {
public:
    virtual void run() const = 0;
    ~Base() = default;
};

class Derived : public Base {
public:
    void run() const override {}
    std::string data{"owned"};
};

Base* value = new Derived;
delete value;
```

**参考答案：**

`Base` 是多态基类，但析构函数不是虚函数。通过 `Base*` 删除 `Derived` 对象的行为是未定义的，不能根据某次运行只看到基类析构就认为“只是派生析构没有打印”。应改为：

```cpp
class Base {
public:
    virtual void run() const = 0;
    virtual ~Base() = default;
};

std::unique_ptr<Base> value = std::make_unique<Derived>();
```

这同时解决了多态销毁和裸 `new/delete` 的所有权问题。若基类明确禁止通过基类指针删除对象，则应设计受保护析构或专门销毁机制，而不是继续执行原来的 `delete value`。

### 53. 下面代码为什么可能悬空？

```cpp
std::string_view make_view() {
    return std::string("temporary");
}
```

**参考答案：**

返回的临时 `std::string` 在返回表达式相关的完整表达式结束后会销毁，`std::string_view` 只保存字符地址和长度，不拥有字符串，也不会延长临时对象生命周期。调用者得到的 view 指向已经销毁的存储，后续读取属于未定义行为。

修复方式是按值返回 `std::string`，让调用者拥有返回对象；或者让调用者提供并保证底层字符串在 view 使用期间持续存在：

```cpp
std::string make_string() {
    return "temporary";
}
```

### 54. 下面异常发生时，哪些对象会析构？

```cpp
void work() {
    std::ofstream file("output.txt");
    std::vector<int> values{1, 2, 3};
    throw std::runtime_error("failed");
}
```

**参考答案：**

异常离开 `work()` 时会发生栈展开。`values` 后构造，所以先析构；`file` 后析构并关闭文件。`throw` 后函数剩余语句不会执行，但已经成功构造的自动对象仍然会清理。

这依赖 `std::vector` 和 `std::ofstream` 本身是 RAII 类型。如果代码改成 `new std::vector<int>` 并只保存一个裸指针，那么异常传播不会凭空执行 `delete`，动态对象会泄漏。

### 55. 下面调用输出什么？怎样改成运行时多态？

```cpp
class Animal {
public:
    void speak() const { std::cout << "animal\n"; }
};

class Dog : public Animal {
public:
    void speak() const { std::cout << "dog\n"; }
};

Dog dog;
Animal* animal = &dog;
animal->speak();
```

**参考答案：**

输出 `animal`。基类函数不是虚函数，调用通过 `Animal*` 的静态类型静态绑定到 `Animal::speak()`。改为：

```cpp
class Animal {
public:
    virtual void speak() const { std::cout << "animal\n"; }
    virtual ~Animal() = default;
};

class Dog : public Animal {
public:
    void speak() const override { std::cout << "dog\n"; }
};
```

`virtual` 让调用通过基类指针或引用进行动态分派，`override` 让编译器检查派生类签名确实匹配。若对象本身是 `Dog dog`，直接写 `dog.speak()` 本来就可以调用 `Dog` 版本，这不是运行时多态的关键场景。

### 56. 设计一个不可复制但可移动的文件资源包装类，应说明哪些点？

**参考答案：**

面试中应先说明设计，而不是只写一段 `new/delete`：

1. 构造函数打开资源，失败就抛异常，不让对象处于半有效状态；
2. 析构函数关闭资源并保证不抛异常；
3. 复制构造和复制赋值删除，因为文件句柄的唯一所有权不能随意复制；
4. 移动构造和移动赋值转移句柄，并把源对象置为空或无效状态；
5. 资源释放操作与实际 API 配对，不能混用 `delete`、`free` 或其他释放函数；
6. 外部只拿到观察句柄时，必须说明包装对象的生命周期仍由谁负责。

如果可以使用标准库，应优先组合 `std::ofstream`、`std::unique_ptr` 或专门的 RAII 类型，让类遵循 Rule of 0。只有在系统句柄没有现成标准包装时，才自己实现删除器和移动语义。

## 八、面试官评分标准与高频陷阱

### 基础合格

- 能解释类、对象、封装、构造、析构和 RAII 的基本含义；
- 能写出成员初始化列表，并说出成员按声明顺序初始化；
- 能区分拷贝构造和拷贝赋值；
- 能说明 `virtual`、`override`、纯虚函数和虚析构函数的基本用途；
- 能指出裸指针、悬空引用、对象切片和异常路径泄漏的风险。

### 中级可靠

- 能从所有权角度选择值、引用、观察指针、`unique_ptr`、`shared_ptr` 或 `weak_ptr`；
- 能解释栈展开、构造失败时的清理、`throw;` 与 `throw error;`；
- 能区分重载、重写和隐藏，并使用 `using Base::name` 处理名称隐藏；
- 能讨论 Rule of 0/3/5、移动后源对象状态、`noexcept` 与容器扩容；
- 能正确设计 `operator+=`、`operator+`、`operator[]` 和 `operator<<` 的返回类型。

### 较强信号

- 不把“虚函数一定通过 vtable”当作标准保证；
- 不把“析构函数必须虚”说成对所有类无条件成立，而是指出多态删除的前提；
- 不把 `std::move` 当作移动操作本身；
- 能讨论异常安全保证、准备—提交模式和资源包装边界；
- 能在继承、组合、所有权和生命周期之间作出有理由的设计取舍，而不是只背语法。

### 最容易答错的六句话

1. “析构函数不是虚函数时只会调用基类析构。”准确说法是：通过基类指针删除派生对象的行为是未定义的。
2. “RAII 可以自动释放所有资源。”准确说法是：只有资源已经交给 RAII 所有者，析构才能负责释放。
3. “`std::move` 会把资源移动走。”准确说法是：它只是转换值类别，真正移动由目标类型的移动操作完成。
4. “纯虚函数不能有函数体。”准确说法是：可以提供定义，但含有纯虚函数的类仍然是抽象类。
5. “所有异常都应该捕获。”准确说法是：在最有能力恢复的边界捕获，无法恢复时应继续传播或在最外层安全处理。
6. “重载、重写和隐藏差不多。”准确说法是：它们分别属于同一作用域的参数多态、继承层级的虚函数替换和名字查找遮蔽。

## 复习结论

第二章真正要掌握的是一条对象模型：对象先通过构造和初始化建立有效状态，再在明确的所有权下使用；离开作用域时由析构和 RAII 完成清理；需要替换行为时通过基类引用、指针或智能指针使用虚接口；失败时依靠栈展开和异常安全保证维持资源与不变量。运算符重载只是这套对象和值语义设计在语法层面的表现，不应脱离类型语义单独背诵。
