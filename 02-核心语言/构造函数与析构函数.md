# 构造函数与析构函数

## 学习目标
- [ ] 说明构造函数和析构函数分别在对象生命周期的哪个阶段运行。
- [ ] 编写默认构造、带参构造、委托构造和显式构造函数。
- [ ] 正确使用成员初始化列表，并理解成员的实际初始化顺序。
- [ ] 区分初始化、赋值、拷贝构造和移动构造。
- [ ] 解释析构顺序、虚析构函数以及 RAII 的基本思想。
- [ ] 在 Windows 上使用 MSVC 或 MinGW-w64 编译并运行示例。

## 要点

## 1. 先建立整体认识：对象有“出生”和“离开”

类是对象的设计图，对象是根据类创建出来的实体。对象从创建到销毁的这段时间叫作**生命周期**。

- **构造函数（constructor）**：对象开始存在时自动调用，用来建立初始状态、检查参数和获取资源。
- **析构函数（destructor）**：对象生命周期结束时自动调用，用来释放对象拥有的资源，例如关闭文件、解锁和释放内存。

~~~cpp
class Counter {
public:
    Counter() { /* 对象刚创建 */ }
    ~Counter() { /* 对象即将销毁 */ }
};

void example() {
    Counter c; // 构造
}              // 离开作用域时自动析构
~~~

构造函数和析构函数通常不由我们直接调用，而是由 C++ 的生命周期规则触发。构造函数抛出异常时，这个对象不算构造成功，因此不会调用它自身的析构函数；已经构造完成的成员和基类子对象仍会自动清理。

## 2. 构造函数的语法与常见形式

构造函数必须满足：名字与类名完全相同、没有返回类型（连 `void` 也不能写）、可以重载，但不能声明为 `static` 或 `virtual`。

### 2.1 为什么构造函数不能是 `static` 或 `virtual`

`static` 成员函数属于类本身，而不属于某个具体对象。调用静态成员函数时不需要对象，因此没有可用的 `this` 指针：

~~~cpp
class Tool {
public:
    static void printVersion() {} // 可以这样通过 Tool::printVersion() 调用
};
~~~

而构造函数的任务恰恰是初始化某一个正在创建的对象，例如 `User u;` 中的 `u`。它必须对这个对象的成员进行初始化，所以不能同时被定义为“不依附任何对象”的 `static` 函数。如果想通过类名调用一个“创建对象的方法”，可以使用静态工厂函数，但工厂函数内部仍然要调用普通构造函数：

~~~cpp
class User {
public:
    static User createDefault() { return User("匿名", 0); }
    User(std::string name, int age)
        : name_(std::move(name)), age_(age) {}
private:
    std::string name_;
    int age_;
};

User u = User::createDefault();
~~~

`virtual` 用于运行时多态：通过一个已经存在的对象（通常是基类指针或引用）调用函数时，再根据对象的动态类型选择派生类版本。但构造函数执行时，对象还处在“正在构造”的过程，派生类部分可能尚未开始构造，不存在一个可以让构造函数先行查询的完整动态对象。因此 C++ 不允许虚构造函数。

构造期间的虚函数调用也不会调用派生类版本：

~~~cpp
class Base {
public:
    Base() { run(); } // 创建 Derived 时，这里调用 Base::run()
    virtual void run() { }
};
class Derived : public Base {
public:
    void run() override { }
};
~~~

这是为了避免调用尚未初始化完成的派生类成员。需要“根据类型决定创建哪个对象”时，应使用工厂函数、工厂类等设计，而不是虚构造函数。

~~~cpp
#include <string>
#include <utility>

class User {
public:
    User() : name_("匿名"), age_(0) {}                 // 默认构造
    User(std::string name, int age)                    // 带参构造
        : name_(std::move(name)), age_(age) {}

private:
    std::string name_;
    int age_;
};
~~~

### 2.2 默认构造函数与 `= default`

默认构造函数是可以不传参数调用的构造函数。若类没有声明任何构造函数，编译器通常会隐式生成一个；但一旦声明带参构造函数，编译器就不会再自动提供无参构造函数：

~~~cpp
class Id {
public:
    explicit Id(int value) : value_(value) {}
    // Id a; // 错误：没有默认构造函数
private:
    int value_;
};
~~~

需要无参构造时应明确写出 `Id() = default;` 或自己实现。反过来，也可以用 `= delete` 禁止某种构造，例如 `T(const T&) = delete;` 表示禁止拷贝。

### 2.3 `explicit`：防止意外的隐式转换

只有一个有效参数的构造函数可能被编译器当作类型转换使用。这样的构造函数常称为**转换构造函数**。对包装类型，通常应加 `explicit`：

~~~cpp
class Meters {
public:
    explicit Meters(double value) : value_(value) {}
private:
    double value_;
};

void use(Meters) {}
// use(3.0);             // 错误：禁止隐式转换
// use(Meters{3.0});     // 正确：明确创建对象
~~~

所谓**隐式转换**，是指我们没有在源代码中明确写出目标类型，编译器却按照语言规则自动完成类型转换。若去掉 `explicit`：

~~~cpp
class Meters {
public:
    Meters(double value) : value_(value) {} // 允许隐式转换
private:
    double value_;
};

void use(Meters distance) { /* ... */ }

use(3.0); // 编译器可按近似下面的方式理解：use(Meters(3.0));
~~~

这里发生的过程是：先调用 `Meters(3.0)` 创建一个临时 `Meters` 对象，再把它传给 `use`。临时对象通常在这条完整表达式结束时销毁，具体的拷贝步骤还可能被编译器优化掉。加上 `explicit` 后，只有明确写出 `Meters(3.0)` 或 `Meters{3.0}` 才能完成转换，从而避免参数单位、金额或 ID 被悄悄混用。

## 3. 成员初始化列表：真正的初始化发生在函数体之前

推荐在初始化列表中给成员设初值：

~~~cpp
#include <string>
#include <utility>

class Student {
public:
    Student(int id, std::string name)
        : id_(id), name_(std::move(name)) {}

private:
    const int id_;       // const 成员必须在初始化列表中初始化
    std::string name_;
};
~~~

如果在函数体中写 `id_ = id;`，`id_` 已经错过初始化时机，代码会编译失败；复杂成员则会先默认构造，再赋值，产生多余操作。以下成员必须（或几乎必须）使用初始化列表：

- `const` 成员；
- 引用成员；
- 没有默认构造函数的成员对象；
- 基类子对象。

### 3.1 为什么说“错过了初始化时机”

构造函数体不是对象构造的第一步。以 `Student s(1001, "小明");` 为例，过程可以简化为：

~~~text
为对象分配存储空间
    ↓
初始化基类子对象
    ↓
按声明顺序初始化成员
    ↓
执行构造函数体
    ↓
对象构造完成
~~~

因此，进入构造函数体时，成员已经必须是“某个已经构造好的对象”。函数体中的语句只能对它们做普通操作（例如赋值），不能把一个已经开始/完成的对象重新初始化。

`const` 成员只能在创建时确定一次：

~~~cpp
class Student {
public:
    Student(int id) : id_(id) {} // 正确：初始化
private:
    const int id_;
};
~~~

若写成 `Student(int id) { id_ = id; }`，进入函数体前 `id_` 就需要先有值，但 `const int` 没有可用的默认初始化方式；即使它已经有值，也不能再次赋值。

引用成员同样必须在创建时绑定对象，之后不能改为引用另一个对象：

~~~cpp
class View {
public:
    explicit View(int& value) : value_(value) {}
private:
    int& value_;
};
~~~

如果成员类型没有默认构造函数，编译器也无法在进入函数体前“凭空”构造它：

~~~cpp
class Name {
public:
    explicit Name(const char*) {}
};

class Person {
public:
    Person() : name_("匿名") {} // 必须告诉编译器怎样构造 name_
private:
    Name name_;
};
~~~

把它改写成函数体赋值，会先尝试调用不存在的 `Name()`，因此编译失败；即使 `Name` 有默认构造，也会变成“先默认构造，再赋值”，比直接初始化多做一步。基类子对象也遵循同一规则：如果基类没有默认构造函数，派生类必须在初始化列表中写出 `Base(参数)`。

> “错过初始化时机”不是说编译器随机错过了某个时间点，而是指 C++ 已经规定：成员和基类必须在构造函数体执行前完成初始化；进入函数体后只能使用或赋值，不能再进行真正的初始化。

### 3.2 初始化顺序由声明顺序决定

成员的实际初始化顺序**永远按照类中声明的顺序**，不是初始化列表的书写顺序：

~~~cpp
class Example {
public:
    Example() : second_(first_), first_(10) {} // 实际仍先初始化 first_
private:
    int first_;
    int second_;
};
~~~

应让初始化列表顺序与成员声明顺序一致。完整构造顺序是：虚基类（如有）→ 直接基类 → 成员（按声明顺序）→ 构造函数体。类内初始化器可提供默认值：

~~~cpp
class Config {
    int timeout_ms_ = 1000; // Config() 使用此值
public:
    Config() = default;
    explicit Config(int timeout) : timeout_ms_(timeout) {}
};
~~~

### 3.3 委托构造

C++11 起，一个构造函数可以把初始化工作委托给同类的另一个构造函数：

~~~cpp
class Rectangle {
public:
    Rectangle() : Rectangle(1, 1) {} // 委托
    Rectangle(int width, int height) : width_(width), height_(height) {}
private:
    int width_;
    int height_;
};
~~~

委托可以集中参数校验和初始化逻辑，避免多个构造函数写出不一致的代码。

## 4. 析构函数：何时调用以及调用顺序

析构函数的名字是波浪号 `~` 加类名，没有参数、没有返回值，也不能重载：

~~~cpp
class FileWriter {
public:
    explicit FileWriter(const char* path) { /* 打开文件 */ (void)path; }
    ~FileWriter() { /* 关闭文件 */ }
};
~~~

普通成员函数可以通过参数列表重载，例如 `print()` 和 `print(int)`。析构函数没有参数，而且对象销毁时由编译器根据对象的类型自动调用；调用点不存在一个“传入不同参数来选择版本”的过程。如果允许多个析构函数，下面这种调用就无法确定：

~~~cpp
// 假想语法（C++ 不允许）
// ~FileWriter();
// ~FileWriter(int mode);
~~~

对象离开作用域、执行 `delete` 或容器销毁时，语言规则只会发起一次无参数的析构调用，因此一个类只能有一个析构函数。可以把不同的清理策略写成普通成员函数（如 `close()`、`flush()`），析构函数则负责无论如何都必须完成的最终清理。`= default`、`= delete` 和 `virtual` 只是对这一个析构函数的不同声明方式，并不构成重载。

常见析构时机如下：

| 对象形式 | 析构时机 |
| --- | --- |
| 函数中的局部对象 | 离开所在作用域时，包括异常离开 |
| 全局/命名空间对象 | `main` 返回后，程序结束阶段 |
| `new T` 创建的对象 | 对它执行 `delete` 时 |
| 容器元素 | 容器销毁、清空或移除元素时 |
| 临时对象 | 完成所在完整表达式后（除非生命周期被延长） |

同一作用域中，局部对象按构造的逆序析构。类对象销毁时，先执行析构函数体，然后按成员声明的逆序销毁成员，最后销毁基类子对象。

~~~cpp
#include <iostream>

class Life {
public:
    explicit Life(const char* name) : name_(name) {
        std::cout << "构造 " << name_ << '\n';
    }
    ~Life() { std::cout << "析构 " << name_ << '\n'; }
private:
    const char* name_;
};

int main() {
    Life first("first");
    {
        Life second("second");
        Life third("third");
    } // 先析构 third，再析构 second
    Life fourth("fourth");
}     // 先析构 fourth，再析构 first
~~~

`new` 必须与 `delete` 配对，`new[]` 必须与 `delete[]` 配对。现代 C++ 优先使用 `std::unique_ptr`、`std::vector`、`std::string` 等 RAII 类型，尽量不直接管理裸指针。

## 5. 拷贝、移动：初始化与赋值不是一回事

构造函数相关的另一组操作是拷贝构造和移动构造：

~~~cpp
Widget a;            // 构造
Widget b = a;        // 拷贝构造：b 以前不存在
b = a;               // 拷贝赋值：b 已经存在
Widget c = Widget{}; // 常会发生拷贝消除
~~~

移动构造通常在用临时对象或 `std::move` 创建新对象时使用，例如 `Widget d = std::move(a);`。移动后原对象仍然存在，但其值通常只保证处于“有效、可析构”的状态，不应假定仍保留原内容。

如果成员都是 `std::string`、`std::vector`、智能指针等 RAII 类型，优先遵循 **Rule of 0**：不手写析构、拷贝和移动操作，让成员类型负责资源管理。只有直接拥有裸资源时，才需要认真设计 Rule of 3/5；初学时更推荐改用标准 RAII 类型。

## 6. 虚析构函数：通过基类指针安全销毁派生类

若类作为多态基类使用，并可能通过基类指针删除对象，析构函数应为 `virtual`：

~~~cpp
#include <iostream>

class Base {
public:
    virtual ~Base() { std::cout << "Base 析构\n"; }
    virtual void run() const = 0;
};

class Derived : public Base {
public:
    ~Derived() override { std::cout << "Derived 析构\n"; }
    void run() const override { std::cout << "运行派生类\n"; }
};

int main() {
    Base* p = new Derived;
    p->run();
    delete p; // 先 Derived，再 Base
}
~~~

如果基类析构函数不是虚函数，`delete p` 的行为未定义，派生类资源可能无法释放。若类不打算被多态删除，则不必仅为“保险”而添加虚析构。

### 6.1 为什么 `Base* p = new Derived;` 合法

假设有公共继承：

~~~cpp
class Base { };
class Derived : public Base { };
~~~

`Derived` 对象中包含一个完整的 `Base` 基类子对象，因此可以说“Derived is-a Base”。`new Derived` 的表达式类型是 `Derived*`，而公共继承允许安全地把派生类指针转换为基类指针：

~~~cpp
Derived* d = new Derived;
Base* p = d; // 向上转型（upcasting）
~~~

所以可以合并写成：

~~~cpp
Base* p = new Derived;
~~~

此时要区分两个概念：`p` 的**静态类型**是 `Base*`，决定了编译器允许直接访问哪些成员；它所指向对象的**动态类型**仍然是 `Derived`，决定虚函数运行时调用哪个覆盖版本。于是 `p->run()` 会调用 `Derived::run()`。

如果 `Base::~Base()` 是虚函数，`delete p` 会先调用 `Derived::~Derived()`，再调用 `Base::~Base()`，从而完整清理派生类和基类部分。若析构函数不是虚函数，通过 `Base*` 删除 `Derived` 对象就会产生未定义行为。

向上转型要求继承关系对当前代码可访问；公共继承表达“派生类是一种基类”，私有继承则不会向类外部公开这种转换。反方向的 `Base*` 到 `Derived*` 不能隐式完成，因为一个基类对象不一定真的是派生类；确有需要时应谨慎使用 `dynamic_cast`，并检查结果是否为空。

## 7. 异常与 `noexcept`

构造函数可以抛出异常表示对象无法建立有效状态。此时已经构造完成的成员会自动析构。析构函数通常应保证不抛异常；如果析构期间已有异常正在传播，又抛出第二个异常，程序可能直接调用 `std::terminate`。

~~~cpp
#include <stdexcept>

class Port {
public:
    explicit Port(int number) {
        if (number <= 0 || number > 65535) {
            throw std::invalid_argument("端口号无效");
        }
    }
    ~Port() noexcept { /* 清理资源 */ }
};
~~~

## 8. 常见错误

1. 给构造函数写返回类型：`void Person()` 是普通成员函数，不是构造函数。
2. 把初始化写成函数体内赋值：对 `const`、引用和无默认构造成员会失败或产生多余操作。
3. 忽略成员声明顺序：真实初始化顺序不受初始化列表顺序影响。
4. 声明带参构造后忘记补默认构造，导致 `T value;` 无法编译。
5. 手动调用普通对象的析构函数，离开作用域时可能再次析构，造成重复释放。
6. `new[]` 与 `delete` 不匹配，或忘记释放动态对象。
7. 非虚析构函数的基类指针被 `delete`，导致未定义行为。
8. 在析构函数中抛异常，可能使程序终止。
9. 裸指针浅拷贝造成两个对象重复释放同一资源；优先使用容器和智能指针。

## 示例与实践

### 1. 完整可运行示例：观察构造、析构和初始化顺序

将下面内容保存为 `constructor_demo.cpp`。它只使用标准库，可在 Windows 的 MSVC、MinGW-w64 或其他 C++20 编译器中运行。不同编译器可能因拷贝消除而有不同的构造次数，但逆序析构规律不变。

~~~cpp
#include <iostream>
#include <string>
#include <utility>

class Person {
public:
    Person() : Person("匿名", 0) { // 委托给带参构造
        std::cout << "执行 Person() 函数体\n";
    }

    Person(std::string name, int age)
        : name_(std::move(name)), age_(age) {
        std::cout << "构造 Person：" << name_ << "，" << age_ << " 岁\n";
    }

    ~Person() noexcept {
        std::cout << "析构 Person：" << name_ << '\n';
    }

    void print() const {
        std::cout << name_ << " 今年 " << age_ << " 岁\n";
    }

private:
    std::string name_; // 先声明，所以先于 age_ 初始化
    int age_;
};

int main() {
    std::cout << "--- 进入 main ---\n";
    Person first;                       // 默认构造（再委托）
    {
        Person second("小明", 18);     // 带参构造
        second.print();
    }                                   // second 在此析构
    Person third("小红", 20);
    std::cout << "--- 离开 main ---\n";
}                                       // third 后析构 first
~~~

在 Visual Studio Developer PowerShell 中：

~~~powershell
cl /std:c++20 /W4 /EHsc constructor_demo.cpp /Fe:constructor_demo.exe
.\constructor_demo.exe
~~~

在已配置 MinGW-w64 的 PowerShell 中：

~~~powershell
g++ -std=c++20 -Wall -Wextra -pedantic constructor_demo.cpp -o constructor_demo.exe
.\constructor_demo.exe
~~~
