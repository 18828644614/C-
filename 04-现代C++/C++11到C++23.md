# C++11到C++23

## 学习目标

- [ ] 知道 C++11、14、17、20、23 各自解决了什么问题，而不是只背特性名称。
- [ ] 能看懂现代 C++ 中常见的 `auto`、Lambda、智能指针、移动语义、结构化绑定和范围写法。
- [ ] 理解“拥有对象”和“只是观察对象”的区别，避免悬空指针、悬空引用和悬空视图。
- [ ] 能用概念（concepts）和范围（ranges）写出更容易读懂、报错更清楚的泛型代码。
- [ ] 知道一个特性属于哪个标准，以及当前编译器和标准库是否真的支持它。

## 先建立正确的时间线

C++ 标准大约每三年发布一次。**标准版本不是编译器名称**：`-std=c++20` 的意思是“要求编译器按 C++20 规则编译”，并不表示存在一个叫“C++20 编译器”的程序。GCC、Clang 和 MSVC 都是逐步实现标准，语言特性和标准库特性的支持时间也可能不同。

| 标准 | 可以记住的主线 | 新手最值得先学的内容 |
| --- | --- | --- |
| C++11 | 现代 C++ 的起点 | `auto`、范围 `for`、`nullptr`、Lambda、智能指针、移动语义、`constexpr`、线程 |
| C++14 | 对 C++11 的易用性补强 | 泛型 Lambda、函数返回类型推导、`make_unique`、更灵活的 `constexpr` |
| C++17 | 让代码更简洁、库更实用 | 结构化绑定、`if constexpr`、折叠表达式、`optional`/`variant`、`string_view`、`filesystem` |
| C++20 | 泛型和并发模型的一次大升级 | 概念、范围、协程、模块、三路比较、`jthread`/`stop_token`、`consteval` |
| C++23 | 继续完善库和表达能力 | `expected`、`print`/`println`、范围增强、显式对象参数、`if consteval`、`mdspan` |

不要把版本看成互相割裂的语言。C++23 程序通常也会使用 C++11 引入的 RAII、Lambda 和移动语义；版本号表示“在这些能力之上再增加什么”。

### 应该选择哪个版本作为日常基线？

- 学习新代码时，C++17 是兼容性较好的起点，C++20 是理解现代泛型和并发的较好起点。
- 维护旧项目时，以项目的 CMake、IDE 或 CI 配置为准，不要为了使用一个新语法而擅自提高标准版本。
- 使用 C++23 的库特性前，先在目标编译器上做一个最小编译测试。语言语法已经支持，并不代表标准库头文件和实现也完整支持。
- 无论使用哪个版本，都建议打开警告：GCC/Clang 使用 `-Wall -Wextra -Wpedantic`，MSVC 使用 `/W4`。

CMake 中可以把要求写在目标上，而不是依赖开发者手动记住命令行参数：

```cmake
add_executable(app main.cpp)

# 告诉 CMake：这个目标至少需要 C++20。
# CMake 会根据当前编译器生成对应的编译选项。
target_compile_features(app PRIVATE cxx_std_20)
```

## 一、C++11：从“能写”到“写得安全”

### 1. `auto`、范围 `for` 和 `nullptr`

`auto` 让编译器根据初始化表达式推导类型，适合类型很长或类型由模板产生的情况。它不是“动态类型”：变量的类型在编译期确定，之后不能随意改成另一种类型。

```cpp
#include <iostream>
#include <vector>

int main() {
    auto count = 3;        // 推导为 int，不是“任意类型”
    const auto pi = 3.14;  // 推导为 const double

    std::vector<int> numbers{1, 2, 3};
    for (const auto number : numbers) {
        // const auto 表示只读副本；修改 number 不会改动容器
        std::cout << number << '\n';
    }

    for (auto& number : numbers) {
        // auto& 表示引用容器中的元素，修改会写回容器
        number *= 2;
    }
}
```

`nullptr` 是专门表示“空指针”的值，优于旧式的 `0` 或 `NULL`。 `0` 既可以是整数也可以被当作空指针，重载函数时容易产生歧义。

```cpp
void inspect(int value);
void inspect(int* pointer);

// inspect(0);       // 可能在两个重载之间产生歧义
// inspect(NULL);    // NULL 在某些实现中仍是整数常量
inspect(nullptr);    // 明确调用指针版本
```

### 2. Lambda：把“小函数”写在使用位置

Lambda 是没有名字的函数对象，常用于算法的比较、过滤和转换。捕获列表决定 Lambda 如何访问外部变量；捕获不是越多越好，尤其要警惕引用捕获导致的生命周期问题。

```cpp
#include <algorithm>
#include <iostream>
#include <vector>

int main() {
    std::vector<int> numbers{1, 2, 3, 4, 5, 6};
    const int limit = 3;

    std::for_each(numbers.begin(), numbers.end(), [limit](int value) {
        // [limit] 按值捕获 limit；Lambda 不依赖外部变量的后续变化
        if (value > limit) {
            std::cout << value << ' ';
        }
    });
}
```

Lambda 的一般形状是：

```cpp
[捕获列表](参数列表) -> 返回类型 {
    // 函数体
};
```

返回类型通常可以省略，让编译器推导。如果函数体的不同分支返回不同类型，推导会失败，此时需要显式写出返回类型。

### 3. 智能指针：先问“谁拥有这个对象？”

现代 C++ 的第一原则是：**资源的释放责任应该绑定在对象的生命周期上**，这就是 RAII。优先使用：

- `std::unique_ptr`：一个明确的所有者，不能复制，可以移动；默认首选。
- `std::shared_ptr`：多个所有者共享生命周期，使用引用计数；只在确实需要共享所有权时使用。
- `std::weak_ptr`：观察 `shared_ptr` 管理的对象，不增加引用计数，可打破循环引用。

```cpp
#include <memory>

struct Device {
    void start() {}
};

void use_device() {
    auto device = std::make_unique<Device>();
    device->start();
    // 离开函数时，device 自动销毁 Device；不需要手写 delete
}
```

智能指针并不代表“任何地方都要传智能指针”。如果函数只临时使用对象而不负责销毁，通常传引用或指针即可：

```cpp
void start_device(Device& device) {
    device.start(); // 只借用，不改变所有权
}
```

### 4. 困难部分：移动语义到底移动了什么？

移动语义主要解决“临时对象或即将销毁的对象不需要保留资源”的问题。复制通常要重新分配并复制数据；移动则可以把资源的控制权转给新对象。

`std::move` **本身不移动任何字节**，它只是把表达式转换成一个右值，告诉重载决议：“这个对象可以被当作即将结束使用的对象”。真正的移动发生在移动构造函数或移动赋值运算符中。

```cpp
#include <iostream>
#include <string>
#include <utility>

int main() {
    std::string source = "一段可能很长的文字";
    std::string target = std::move(source);

    std::cout << target << '\n';
    // source 仍然是有效的 std::string 对象，但内容处于“有效但未指定”状态。
    // 可以销毁它，也可以重新赋值；不要依赖它仍然保存原文字。
    source = "重新赋值";
}
```

一个带有自定义资源的类型通常遵循“五法则”：如果需要自定义析构、复制构造、复制赋值、移动构造或移动赋值中的一个，就应检查其他特殊成员函数是否也需要定义。实际工程中更推荐让 `std::string`、`std::vector` 和智能指针管理资源，从而遵循“零法则”，尽量不手写这些函数。

### 5. `constexpr` 和类型安全的枚举

`constexpr` 表示表达式有机会在编译期计算，但并不是“强制所有情况都在编译期执行”。如果输入只在运行时才知道，同一个函数也可以在运行时调用。

```cpp
constexpr int square(int value) {
    return value * value;
}

constexpr int size = square(4); // 编译期可计算，可用于数组大小
int input = 5;
int result = square(input);     // input 运行时才知道，所以运行时计算
```

`enum class` 不会把枚举值隐式转换成整数，也不会把枚举成员泄漏到外层作用域，更适合表示有限状态：

```cpp
enum class ConnectionState { Disconnected, Connecting, Connected };

ConnectionState state = ConnectionState::Connected;
if (state == ConnectionState::Connected) {
    // 名字带作用域，读代码时更清楚
}
```

## 二、C++14：让 C++11 的写法更顺手

C++14 没有大幅改变语言模型，主要是降低模板和 Lambda 的书写成本。

### 泛型 Lambda、返回类型推导和 `make_unique`

Lambda 的参数可以写成 `auto`，因此同一个 Lambda 可以接受多种类型。函数返回类型也可以使用 `auto` 推导，但所有返回路径必须得到同一个类型。

```cpp
#include <iostream>
#include <memory>

int main() {
    auto twice = [](auto value) {
        return value + value;
    };

    std::cout << twice(2) << '\n';      // int
    std::cout << twice(1.5) << '\n';    // double

    auto value = std::make_unique<int>(42);
    // C++14 的 make_unique 让 unique_ptr 的创建方式与 make_shared 对称。
}
```

如果你在旧代码里看到 `std::unique_ptr<T>(new T(...))`，通常应考虑改成 `std::make_unique<T>(...)`：表达式更短，也能减少异常安全问题。

## 三、C++17：把常见样板代码压缩成清晰意图

### 1. 结构化绑定：一次拆出多个值

结构化绑定可以把数组、`pair`、`tuple` 或满足特定接口的类型拆成多个名字。注意：`auto [a, b]` 默认可能产生副本；需要修改原对象时使用 `auto&`。

```cpp
#include <map>
#include <string>

int main() {
    std::map<std::string, int> scores{{"Alice", 90}, {"Bob", 85}};

    for (const auto& [name, score] : scores) {
        // const auto& 同时避免复制 pair，并保证循环体不修改元素
        (void)name;
        (void)score;
    }
}
```

### 2. `if constexpr`：在编译期选择分支

普通 `if` 的两个分支都必须先通过语法和类型检查；`if constexpr` 的未选分支会在模板实例化时丢弃，因此可以针对不同类型选择不同代码。这是 C++17 泛型编程的关键工具。

```cpp
#include <iostream>
#include <string>
#include <type_traits>

template <typename T>
void describe(const T& value) {
    if constexpr (std::is_integral_v<T>) {
        std::cout << "整数: " << value << '\n';
    } else {
        std::cout << "其他类型: " << value << '\n';
    }
}

int main() {
    describe(42);
    describe(std::string{"hello"});
}
```

### 3. `optional`、`variant` 和 `any`：把“可能没有值”写进类型

- `std::optional<T>`：结果可能是一个 `T`，也可能没有值；适合“查找失败”而不是用特殊数字表示失败。
- `std::variant<A, B>`：值是列出的几种类型之一；比无类型的 `void*` 更安全。
- `std::any`：可以保存任意可复制类型，但读取时需要知道正确类型；不要把它当作默认的多态方案。

```cpp
#include <optional>
#include <string>

std::optional<int> find_score(const std::string& name) {
    if (name == "Alice") {
        return 95;
    }
    return std::nullopt; // 明确表示“没有找到”
}

int main() {
    if (auto score = find_score("Alice")) {
        // optional 在条件中表示“里面有值”
        int value = *score;
        (void)value;
    }
}
```

### 4. `string_view`：不拥有字符串的观察窗口

`std::string_view` 通常只是一个指针加长度，它不负责保存文字。它很适合只读函数参数，可以避免不必要的字符串复制；但视图不能比被观察的字符串活得更久。

```cpp
#include <iostream>
#include <string>
#include <string_view>

void print_name(std::string_view name) {
    std::cout << name << '\n';
}

int main() {
    std::string name = "Alice";
    print_name(name); // 只读观察，不复制整段文字

    // 危险示例：临时 string 在这一行结束后销毁，不能保存下面的 view。
    // std::string_view bad = std::string{"temporary"};
}
```

看到 `string_view`、迭代器或引用时，都要问一句：“它指向的对象还活着吗？”这比记住某个语法更重要。

### 5. 折叠表达式和 `filesystem`

折叠表达式把参数包按某个运算符展开，常见于“对所有参数执行同一操作”。`std::filesystem` 则把路径、目录遍历和文件属性纳入标准库；仍要处理权限、路径不存在等运行时错误。

```cpp
#include <iostream>

template <typename... Args>
void print_all(const Args&... args) {
    // (std::cout << ... << args) 是左折叠：依次输出所有参数
    (std::cout << ... << args) << '\n';
}

int main() {
    print_all("数量: ", 3, ", 状态: ", "ok");
}
```

## 四、C++20：约束泛型代码，并把“惰性处理”串起来

### 1. 概念（concepts）：在接口处说明“类型必须会什么”

传统模板常在实例化深处才报错，错误信息很长。概念把要求写在模板接口上，让调用者更早看到问题。概念不是运行时检查，也不会自动把所有模板代码变快；它主要改善约束表达、重载选择和诊断信息。

```cpp
#include <concepts>
#include <iostream>

template <typename T>
concept Printable = requires(const T& value, std::ostream& out) {
    { out << value } -> std::same_as<std::ostream&>;
};

template <Printable T>
void print_value(const T& value) {
    std::cout << value << '\n';
}
```

上面的 `requires` 可以读成：“给定一个 `const T&` 和输出流，表达式 `out << value` 必须存在，并且结果必须是 `std::ostream&`。”使用时若传入没有输出运算符的类型，编译器会在 `print_value` 的入口处说明不满足 `Printable`。

### 2. 范围（ranges）：把算法写成数据处理管道

范围视图通常是**惰性的**：创建视图不会立即遍历或生成新容器，真正迭代时才执行过滤和变换。这既能减少中间容器，也意味着源容器必须在视图使用期间保持有效。

```cpp
#include <iostream>
#include <ranges>
#include <vector>

int main() {
    const std::vector<int> numbers{1, 2, 3, 4, 5, 6};

    auto even_squares = numbers
        | std::views::filter([](int value) { return value % 2 == 0; })
        | std::views::transform([](int value) { return value * value; });

    for (int value : even_squares) {
        // 这里才会依次过滤、再计算平方：4 16 36
        std::cout << value << ' ';
    }
}
```

不要从函数返回一个引用局部容器的视图；也不要在视图仍在使用时销毁或改变其底层容器。需要独立保存结果时，显式构造 `std::vector` 等拥有数据的容器。

### 3. 协程：可以暂停和恢复的函数

协程不是“自动开一个线程”。`co_await`、`co_yield` 和 `co_return` 描述的是一个可以暂停的函数状态机；谁负责恢复它、结果保存在哪里，取决于协程返回类型和执行器。C++20 只提供语言机制，具体的任务类型、事件循环和调度器仍通常由库提供。

```cpp
// 这是展示语义的片段，不是可独立编译的完整程序：
Task load_data() {
    auto connection = co_await open_connection();
    auto data = co_await connection.read();
    co_return data;
}
```

可以把它类比为“编译器帮你保存局部变量和下一条要执行的位置”。学习协程时应先掌握普通函数、对象生命周期和异步任务的所有权，再学习具体库的 `Task` 类型；否则很容易把“暂停”误认为“阻塞线程”，或在协程恢复时访问已经销毁的对象。

### 4. `jthread`、停止请求和三路比较

`std::jthread` 在析构时会自动请求停止并等待线程结束，比裸 `std::thread` 更不容易忘记 `join()`。停止是协作式的：线程函数必须主动检查令牌，系统不会强行杀死线程。

```cpp
#include <chrono>
#include <iostream>
#include <thread>

int main() {
    std::jthread worker([](std::stop_token token) {
        while (!token.stop_requested()) {
            std::cout << "working\n";
            std::this_thread::sleep_for(std::chrono::milliseconds(10));
        }
    });

    std::this_thread::sleep_for(std::chrono::milliseconds(30));
    // 离开作用域时 jthread 会请求停止并等待 worker 结束
}
```

## 五、C++23：用标准库表达“成功或失败”，并减少样板代码

C++23 的使用策略应更保守：先确认编译器和标准库实现，再决定是否在生产代码中依赖某个库特性。很多项目会使用 `-std=c++23`，但仍可能缺少某个头文件的完整实现。

### 1. `expected`：把可恢复错误作为返回值

`std::expected<T, E>` 表示结果要么是一个 `T`，要么是一个 `E` 错误。它适合输入解析、文件读取、配置加载等“失败是正常分支”的场景，避免用异常或魔法返回值表达所有错误。

```cpp
#include <expected>
#include <string>

std::expected<int, std::string> parse_positive(int value) {
    if (value < 0) {
        return std::unexpected("value 不能为负数");
    }
    return value;
}

int main() {
    auto result = parse_positive(-1);
    if (!result) {
        // error() 取出错误信息；value() 只应在确认有值后调用
        const std::string& message = result.error();
        (void)message;
    } else {
        int value = *result;
        (void)value;
    }
}
```

### 2. 范围和输出工具的增强

C++23 为范围增加了 `std::ranges::to`、`views::zip` 等更方便的组件，也提供 `std::print`/`std::println` 作为格式化输出接口。它们的优点是表达清晰、类型安全，但实现支持度仍需检查。

```cpp
// 需要支持相应 C++23 标准库实现的编译器。
#include <print>

int main() {
    std::println("答案是 {}", 42);
}
```

如果目标环境还没有 `<print>`，可以继续使用 `std::cout` 或项目已经依赖的格式化库，不要为了一个输出函数强行更换整个工具链。

### 3. 显式对象参数（deducing this）

C++23 允许成员函数把隐含的 `this` 写成显式参数，从而减少 const/non-const 重载的重复代码。语法较新，适合在已经理解成员函数、引用限定符和模板之后学习。

```cpp
#include <utility>

struct Box {
    int value = 0;

    // this 是显式的第一个参数；auto&& 允许 const 和非 const 对象复用代码
    template <typename Self>
    auto&& get(this Self&& self) {
        return std::forward<Self>(self).value;
    }
};
```

这段代码的核心思想不是“让成员函数变成普通函数”，而是让编译器根据调用对象的类型推导 `Self`，从而保留正确的 const 性和左值/右值性质。

### 4. `if consteval` 与编译期/运行时双路径

`if consteval` 专门判断当前代码是否在常量求值环境中执行。它与 C++17 的 `if constexpr` 不同：`if constexpr` 判断的是类型或编译期条件并丢弃分支，`if consteval` 判断的是“这一次调用是否正在编译期求值”。

```cpp
consteval int compile_time_only(int value) {
    return value * 2;
}

constexpr int value = compile_time_only(21); // 必须在编译期完成
```

初学时可以先掌握 `constexpr`，只有在需要严格禁止运行时调用或为编译期、运行时提供不同实现时再使用 `consteval`/`if consteval`。

## 六、把版本特性组合成一段现代代码

下面的示例使用 C++17 的 `optional`、结构化绑定和 `string_view`，再配合 C++11 的 Lambda、`auto` 与范围 `for`。版本特性通常是叠加使用的，而不是孤立的“语法练习”。

```cpp
#include <algorithm>
#include <iostream>
#include <optional>
#include <string>
#include <string_view>
#include <vector>

struct User {
    std::string name;
    int age;
};

std::optional<User> find_user(const std::vector<User>& users,
                              std::string_view wanted_name) {
    auto it = std::find_if(users.begin(), users.end(),
                           [wanted_name](const User& user) {
                               return user.name == wanted_name;
                           });
    if (it == users.end()) {
        return std::nullopt;
    }
    return *it; // 返回一个 User 副本；调用者获得独立的数据所有权
}

int main() {
    const std::vector<User> users{{"Alice", 20}, {"Bob", 17}};

    if (auto result = find_user(users, "Alice")) {
        const auto& [name, age] = *result;
        std::cout << name << " is " << age << " years old\n";
    }
}
```

阅读这段代码时可以按“责任”拆解：`vector` 拥有所有 `User`；`string_view` 只借用查找条件；Lambda 描述查找规则；`optional` 表示“可能找不到”；结构化绑定只负责让结果更易读。

## 七、从旧代码迁移到现代写法的顺序

不要一次性把整套旧项目“改成 C++23”。更安全的迁移顺序是：

1. 打开警告并修复未定义行为，再考虑语法美化。
2. 用 `nullptr` 替换空指针常量，用 `enum class` 替换容易冲突的旧枚举。
3. 用 `std::vector`、`std::string`、`std::unique_ptr` 和 RAII 接管资源，逐步减少裸 `new`/`delete`。
4. 用范围 `for`、标准算法和 Lambda 表达意图；不要为了“现代”而把简单循环改得难读。
5. 需要多种结果状态时使用 `optional`、`variant` 或 `expected`，避免魔法数字和无类型指针。
6. 对公共模板接口添加概念或 `requires`，让错误尽量在接口处出现。
7. 最后再评估范围、协程、模块和 C++23 库特性，并用基准测试和工具链矩阵验证收益。

现代 C++ 的目标不是“使用最多的新语法”，而是让所有权、生命周期、错误处理和算法意图更明确。一个简单、可维护的 C++17 实现，通常比充满未经验证的新特性的 C++23 实现更适合生产环境。

## 示例与实践

### 检查编译器标准支持

GCC/Clang：

```powershell
g++ --version
g++ -std=c++20 -Wall -Wextra -Wpedantic main.cpp -o app.exe
```

MSVC（开发者 PowerShell）：

```powershell
cl /std:c++20 /W4 /EHsc main.cpp
```

把 `c++20` 换成 `c++23` 或把 MSVC 的选项换成项目要求的版本，并不等于所有库特性都可用；最可靠的检查方式是编译一个只包含目标头文件的最小示例，并在 CI 中使用实际部署的编译器版本。

### 动手练习

1. 把一个使用裸指针和手写 `delete` 的示例改为 `std::unique_ptr`，说明所有权在哪里转移。
2. 写一个返回 `std::optional<int>` 的查找函数，再改为返回 `std::expected<int, std::string>`，比较“没有结果”和“发生错误”的区别。
3. 给 `std::vector<int>` 写一条 C++20 范围管道：过滤偶数、平方、再把结果保存到新容器。
4. 故意让 `std::string_view` 指向一个已经离开作用域的 `std::string`，用 AddressSanitizer 或调试器观察为什么这是错误的。
5. 用 `std::jthread` 写一个能够响应 `stop_token` 的循环任务，并解释它为什么仍然需要任务代码主动检查停止请求。
