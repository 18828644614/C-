# 结构化绑定与初始化

## 学习目标

- [ ] 区分初始化和赋值，并能选择清晰、安全的初始化写法。
- [ ] 理解花括号初始化、构造函数和初始化列表之间的关系。
- [ ] 使用成员初始化列表和类内默认成员初始化器，正确初始化对象成员。
- [ ] 使用 C++17 结构化绑定拆出数组、`pair`、`tuple` 和简单结构体中的值。
- [ ] 分辨结构化绑定产生的是副本还是引用，避免无意的拷贝、修改失败和悬空引用。

## 1. 先区分：初始化不是赋值

**初始化（initialization）**发生在对象刚刚创建时；**赋值（assignment）**发生在对象已经存在之后。两者都可能写成 `=`，但发生的时间和调用的操作不同：

~~~cpp
int score = 80; // 初始化：score 在这里第一次创建
score = 90;     // 赋值：score 已经存在，把新值写进去
~~~

对类对象来说，初始化通常会调用构造函数，赋值通常会调用赋值运算符。构造函数负责“把一个不存在的对象建立好”，赋值运算符负责“替换一个已有对象的状态”。

~~~cpp
#include <string>

int main() {
    std::string first{"Alice"};
    std::string second{first}; // 初始化 second，通常调用拷贝构造函数
    second = first;            // second 已存在，这里是拷贝赋值
}
~~~

如果一个对象有 `const` 成员或引用成员，它们必须在初始化时确定，不能等到构造函数体中再赋值；这正是成员初始化列表重要的原因，见[[构造函数与析构函数]]。

## 2. 常见初始化形式：从简单类型开始

### 2.1 几种常见写法

~~~cpp
int a;       // 默认初始化：局部 int 没有确定值，不要直接读取
int b{};     // 值初始化：b 为 0，初学时很推荐
int c = 10;  // 复制初始化：c 为 10
int d(10);   // 直接初始化：d 为 10
int e{10};   // 直接列表初始化：e 为 10，推荐
~~~

在普通局部变量中，`int a;` 不会自动变成 0。读取它的值可能导致未定义行为。养成“声明时给初值”的习惯：

~~~cpp
int count{};          // 明确从 0 开始
std::string message{}; // 空字符串
bool finished{false};  // 明确的布尔初值
~~~

数组也可以用空花括号把所有元素值初始化：

~~~cpp
int scores[3]{};        // 三个元素都是 0
int scores2[3]{90, 80}; // {90, 80, 0}，未提供的元素为 0
~~~

### 2.2 为什么推荐花括号初始化

花括号初始化又叫**列表初始化**。它的一个重要优点是：很多可能丢失数据的窄化转换会直接被编译器拒绝。

~~~cpp
// int wrong{3.14}; // 编译错误：double 转 int 会丢失小数部分
int explicit_value{static_cast<int>(3.14)}; // 明确表示“我知道会截断”

int accepted = 3.14; // 某些编译器允许，结果通常为 3，容易隐藏错误
~~~

这不是说 `=` 写法永远错误，而是花括号能把一部分潜在错误提前变成编译错误。列表初始化也会检查整数范围等问题：

~~~cpp
// unsigned count{-1}; // 编译错误：负数不能安全地列表初始化为无符号数
unsigned count{0};
~~~

### 2.3 花括号并不等于“任何地方都一样”

对类来说，花括号会参与构造函数重载选择；有 `std::initializer_list` 构造函数时，它还可能优先匹配该构造函数。最经典的例子是 `std::vector`：

~~~cpp
#include <vector>

std::vector<int> values1(3, 7); // 三个元素，每个都是 7：{7, 7, 7}
std::vector<int> values2{3, 7}; // 两个元素，分别是 3 和 7：{3, 7}
~~~

初学时看到容器初始化，先问自己：“我是想指定元素个数，还是想列出元素值？”不要只因为花括号看起来现代就机械替换。

### 2.4 一个容易误解的语法：最烦人的解析

下面的声明看起来像“创建一个 `Widget` 对象并调用默认构造函数”，但在某些上下文中，编译器可能把它解析成函数声明：

~~~cpp
// Widget widget(); // 可能被解析为“声明一个返回 Widget 的函数 widget”
Widget widget{};    // 用花括号明确表示这是一个对象
~~~

这类问题通常被称为“最烦人的解析（most vexing parse）”。使用 `{}` 能让意图更明确，但仍应理解：花括号会改变重载选择，遇到复杂构造函数时要查看类型的接口。

## 3. 类对象的初始化：成员初始化列表

### 3.1 成员初始化列表做什么

构造函数冒号后面的部分叫**成员初始化列表**。它在构造函数体执行之前，用于直接构造成员：

~~~cpp
#include <string>
#include <utility>

class Student {
public:
    Student(int id, std::string name)
        : id_(id), name_(std::move(name)) { // 先初始化成员
        // 构造函数体在成员已经构造完成后才执行
    }

private:
    int id_;
    std::string name_;
};
~~~

对于 `std::string`，直接在初始化列表中构造通常比先默认构造、再在构造函数体中赋值更自然，也可能减少一次操作：

~~~cpp
class User {
public:
    User(std::string name) : name_(std::move(name)) {}

private:
    std::string name_;
};

// 不推荐把它理解成“先初始化 name_，再赋值”：
// User(std::string name) { name_ = std::move(name); }
// 这里 name_ 会先默认构造，再进行一次赋值。
~~~

使用 `std::move` 需要包含 `<utility>`。如果暂时还没有学习移动语义，也可以先写 `name_(name)`；重要的是理解成员应当在初始化列表中初始化。

### 3.2 `const` 成员和引用成员必须用初始化列表

`const` 对象和引用必须在创建时绑定到确定的值，之后不能重新绑定，因此不能在构造函数体中“再赋值”：

~~~cpp
class Reading {
public:
    Reading(int value, const int& source)
        : value_(value), source_(source) {}

private:
    const int value_;  // 必须初始化，之后不能改变
    const int& source_; // 必须在创建时绑定到某个 int 对象
};
~~~

下面的写法是错误的：

~~~cpp
// class Wrong {
// public:
//     Wrong(int value, int& source) {
//         value_ = value;   // 错误：const 成员不能在构造函数体中赋值
//         source_ = source; // 这不是重新绑定，而是修改 source_ 所引用的对象
//     }
// private:
//     const int value_;
//     int& source_;
// };
~~~

引用成员还要特别小心生命周期：如果它引用的对象先销毁，类对象中的引用就会悬空。若类需要“保存一个值”，通常直接保存值或使用智能指针比保存引用更安全。

### 3.3 成员初始化顺序不是列表书写顺序

成员总是按照**在类中声明的顺序**初始化，而不是按照初始化列表中的书写顺序：

~~~cpp
class Rectangle {
public:
    Rectangle(int width)
        : area_(width_ * width_), width_(width) { // 看起来先写 area_
    }

private:
    int width_; // 实际先初始化 width_
    int area_;  // 再初始化 area_
};
~~~

上例中 `width_` 实际上先初始化，所以结果通常符合预期；但把列表顺序写反会误导读者，也可能在修改成员声明顺序后产生问题。应当始终按成员声明顺序书写初始化列表：

~~~cpp
class Rectangle {
public:
    Rectangle(int width)
        : width_(width), area_(width * width) {}

private:
    int width_;
    int area_;
};
~~~

开启较高警告级别时，编译器通常会提醒初始化列表顺序和成员声明顺序不一致。

### 3.4 类内默认成员初始化器

如果成员的大多数对象都使用同一个默认值，可以直接在类定义处提供默认成员初始化器：

~~~cpp
class Options {
private:
    bool verbose_{false}; // 默认关闭详细输出
    int timeout_seconds_{30};
};
~~~

构造函数可以覆盖这个默认值：

~~~cpp
class Options {
public:
    Options() = default; // 使用类内默认值
    explicit Options(int timeout)
        : timeout_seconds_(timeout) {} // 只覆盖 timeout

private:
    bool verbose_{false};
    int timeout_seconds_{30};
};
~~~

若某个成员同时出现在初始化列表和类内默认成员初始化器中，以初始化列表为准。默认成员初始化器适合表达稳定的默认状态；构造函数初始化列表适合表达由参数决定的状态。

### 3.5 委托构造函数

一个构造函数可以把工作委托给同一个类的另一个构造函数，避免重复校验：

~~~cpp
class Point {
public:
    Point() : Point(0, 0) {} // 委托给带参数的构造函数
    Point(int x, int y) : x_(x), y_(y) {}

private:
    int x_;
    int y_;
};
~~~

委托构造时，委托构造函数的初始化列表只能指定被委托的构造函数，不能同时再次初始化普通成员。

## 4. 结构化绑定：一次拆出多个值

### 4.1 它解决什么问题

C++17 引入了**结构化绑定（structured binding）**。当一个对象包含多个有逻辑关系的值时，可以在声明处把它们分别绑定到名字上：

~~~cpp
#include <iostream>
#include <string>
#include <utility>

std::pair<int, std::string> get_student() {
    return {1001, "小王"};
}

int main() {
    auto result = get_student();
    int id = result.first;             // 传统写法：通过 first/second 访问
    std::string name = result.second;

    auto [id2, name2] = get_student(); // 结构化绑定：直接拆成两个名字
    std::cout << id2 << ' ' << name2 << '\n';
}
~~~

`auto [id2, name2]` 不是“调用一个返回两个值的函数”。C++ 函数仍然只返回一个对象，这个对象可以是 `std::pair`、`std::tuple` 或自定义类型；结构化绑定只是让访问其中各部分更方便。

### 4.2 可以绑定哪些对象

初学阶段记住下面三类即可：

1. **数组**：按下标绑定每个元素。
2. **`std::pair`、`std::tuple` 等 tuple-like 类型**：按 `get<0>`、`get<1>` 等位置绑定。
3. **简单聚合类型**：按声明顺序绑定可访问的数据成员。

~~~cpp
#include <array>
#include <tuple>
#include <utility>

int numbers[2]{10, 20};
auto [first, second] = numbers; // first == 10，second == 20

std::array<int, 2> scores{90, 95};
auto [math, english] = scores;

std::tuple<int, double, char> record{1, 9.5, 'A'};
auto [number, average, grade] = record;

struct Color {
    int red;
    int green;
    int blue;
};

Color color{255, 128, 0};
auto [r, g, b] = color; // 按成员声明顺序绑定
~~~

自定义类型要满足结构化绑定的规则，不能把任意带 `private` 成员的类随意拆开。若只是想传递一组公开数据，简单 `struct` 往往比强行暴露复杂类的内部状态更合适。

### 4.3 最重要的区别：副本还是引用

结构化绑定中的 `auto` 默认会创建一个新的“隐藏对象”，绑定名字访问这个对象的各部分。因此，下面的修改不会改变原来的 `point`：

~~~cpp
struct Point {
    int x;
    int y;
};

Point point{1, 2};
auto [x, y] = point; // x、y 访问的是 point 的副本
x = 100;
// point.x 仍然是 1
~~~

如果希望绑定名直接引用原对象，使用 `auto&`：

~~~cpp
auto& [x_ref, y_ref] = point; // x_ref、y_ref 是 point 成员的引用
x_ref = 100;
// point.x 现在是 100
~~~

可以把它暂时想象成下面的“近似展开”（这不是编译器真正生成的源码，只是帮助理解）：

~~~cpp
Point hidden = point; // auto [x, y] = point; 先得到一个副本
// x 大致指向 hidden.x，y 大致指向 hidden.y
~~~

因此，修改 `x` 修改的是 `hidden.x`，而不是原来的 `point.x`。写成 `auto& [x, y]` 时，隐藏对象则是对 `point` 的引用，绑定名最终会访问原对象的成员。

只读访问通常使用 `const auto&`：

~~~cpp
const auto& [x_readonly, y_readonly] = point;
// x_readonly = 5; // 错误：通过 const 引用不能修改 point
~~~

可以用下面的速记来选择：

| 写法 | 大致含义 | 常见用途 |
| --- | --- | --- |
| `auto [a, b]` | 拆出副本 | 需要独立修改，或对象很小、复制成本低 |
| `auto& [a, b]` | 绑定到原对象，可修改 | 需要修改原数组/结构体/容器元素 |
| `const auto& [a, b]` | 绑定到原对象，只读 | 避免拷贝的大对象，只读访问 |
| `auto&& [a, b]` | 转发引用形式 | 泛型代码；初学阶段先谨慎使用 |

注意：`auto&` 只能绑定到一个仍然存在的对象，不能绑定到返回后马上销毁的普通临时对象。

### 4.4 在范围 `for` 中使用结构化绑定

关联容器的元素通常是 `std::pair<const Key, T>`。下面的写法会复制每个元素：

~~~cpp
#include <map>
#include <string>

std::map<std::string, int> scores{{"数学", 90}, {"英语", 95}};

for (auto [subject, score] : scores) {
    // subject 和 score 是每个 pair 的副本
    // 修改 score 不会写回 scores
}
~~~

只读遍历时，推荐使用 `const auto&` 避免复制：

~~~cpp
for (const auto& [subject, score] : scores) {
    // subject、score 直接引用容器元素，只读且不复制
}
~~~

需要修改值时可以使用 `auto&`：

~~~cpp
for (auto& [subject, score] : scores) {
    score += 5; // 修改 map 中的 value
    // subject 仍然是 const 字符串，因为 map 的 key 不能被修改
}
~~~

不要在循环体中修改 `subject` 来“重命名”键；关联容器必须维护键的排序或哈希规则，键通常被设计成不可修改。

### 4.5 临时对象和生命周期

用 `auto [a, b] = 函数返回的对象` 时，结构化绑定自己保存一份返回对象，因此在当前作用域内访问是安全的：

~~~cpp
std::pair<int, int> make_range() {
    return {1, 10};
}

auto [begin, end] = make_range();
// 返回的 pair 被绑定声明持有，begin/end 在这里仍然有效
~~~

`const auto&` 绑定到临时对象时，临时对象的生命周期通常会延长到引用的作用域结束：

~~~cpp
const auto& [begin_ref, end_ref] = make_range();
// 临时 pair 的生命周期延长到这条声明所在作用域结束
~~~

但不要把这种引用返回给外部，也不要让它超过绑定声明的作用域。尤其要避免把结构化绑定中的引用保存到一个更长寿命的对象里，否则很容易产生悬空引用。

### 4.6 绑定名不是普通变量声明的简单替代品

结构化绑定的每个名字不能单独写类型，也不能只绑定对象的一部分：

~~~cpp
std::pair<int, double> value{1, 2.5};
auto [number, price] = value; // 正确：数量必须与元素数量匹配
// auto [only_number] = value; // 错误：pair 有两个元素
~~~

如果只需要其中一个字段，传统写法反而更直接：`value.first`。不要为了使用新语法而拆出自己不需要的所有值。

## 5. 初始化与结构化绑定中的常见错误

| 问题 | 原因 | 建议 |
| --- | --- | --- |
| `int value;` 后直接输出 | 局部变量没有确定的初值 | 写成 `int value{};`，或先明确赋值 |
| `int n = 3.14;` 得到 3 | `=` 初始化允许隐式窄化 | 优先写 `int n{3.14};` 让编译器报错；若确实要截断，使用 `static_cast<int>` |
| 把 `vector<int>{3, 7}` 当成 3 个 7 | 花括号选择了元素列表构造 | “个数+值”使用 `vector<int>(3, 7)` |
| 在构造函数体给 `const` 成员赋值 | `const` 成员创建后不可赋值 | 放到成员初始化列表 |
| 初始化列表顺序与成员声明顺序不同 | 成员按声明顺序初始化，而不是按书写顺序 | 两者保持相同，消除误解和警告 |
| `auto [x, y] = object` 后修改 `x`，原对象没变 | `auto` 绑定的是副本 | 需要写回原对象时使用 `auto&` |
| 用 `auto&` 绑定函数返回的临时对象 | 非 `const` 左值引用不能绑定临时对象 | 使用 `auto` 拷贝，或只读时使用 `const auto&` |
| `for (auto [k, v] : map)` 中修改 `v` 无效 | 循环变量是每个元素的副本 | 修改容器时使用 `auto&` |
| 通过结构化绑定修改 map 的键 | map 的键是 `const`，修改会破坏容器不变量 | 删除旧键后插入新键，或使用合适的容器接口 |
| 把引用绑定保存到更长生命周期 | 原对象或临时对象已经销毁 | 检查引用指向对象的生命周期，必要时改为按值保存 |

排查这类问题时，可以按顺序问自己：

1. 对象是在这一行创建，还是已经存在？这是初始化还是赋值？
2. 花括号是否触发了我没有预期的构造函数或 `initializer_list`？
3. 结构化绑定需要副本还是需要引用？是否真的要修改原对象？
4. 被引用对象在使用期间是否一直存在？

## 示例与实践

### 1. 完整可运行示例：初始化、成员初始化列表和结构化绑定

下面程序使用 C++17，演示默认成员初始化器、委托构造、`std::pair` 返回值、`auto` 副本绑定、引用绑定和 `map` 遍历。

~~~cpp
#include <iostream>
#include <map>
#include <string>
#include <utility>

class Student {
public:
    Student() : Student(0, "未命名") {} // 委托给带参数的构造函数

    Student(int id, std::string name)
        : id_(id), name_(std::move(name)) {
        // id_、name_ 在进入构造函数体前已经初始化完成
    }

    int id() const { return id_; }
    const std::string& name() const { return name_; }

    void rename(std::string name) { name_ = std::move(name); }

private:
    int id_{0};          // 没有被构造函数显式初始化时，默认使用 0
    std::string name_{}; // 没有被显式初始化时，默认是空字符串
};

std::pair<int, std::string> make_summary(const Student& student) {
    // 函数返回一个 pair，而不是“返回两个独立值”
    return {student.id(), student.name()};
}

int main() {
    Student student{1001, "小王"};

    auto [id, name] = make_summary(student);
    // id、name 是返回 pair 中内容的副本
    std::cout << "学号：" << id << "，姓名：" << name << '\n';

    struct MutableData {
        int value;
        std::string text;
    } data{10, "原始数据"};

    auto [value_copy, text_copy] = data;
    value_copy = 20; // 只改了副本
    std::cout << "data.value：" << data.value << '\n'; // 仍为 10

    auto& [value_ref, text_ref] = data;
    value_ref = 30; // 通过引用修改原对象
    text_ref = "已修改";
    std::cout << "data：" << data.value << "，" << data.text << '\n';

    std::map<std::string, int> scores{
        {"数学", 90},
        {"英语", 95},
    };

    for (const auto& [subject, score] : scores) {
        // const auto&：不复制 pair，也不修改容器
        std::cout << subject << "：" << score << '\n';
    }

    for (auto& [subject, score] : scores) {
        // score 是 map 中真实的 value，可以被修改
        score += 1;
        // subject 是 const key，不能被修改
    }
}
~~~

### 2. 练习

1. 声明一个 `std::array<int, 3>`，使用结构化绑定读取三个成绩，并计算平均值。
2. 写一个返回 `std::pair<bool, std::string>` 的函数表示“查找是否成功”和“提示信息”，使用结构化绑定读取结果。
3. 创建一个包含 `const` 成员和引用成员的类，分别尝试在构造函数体和初始化列表中初始化，观察编译错误并解释原因。
4. 将 `for (auto [key, value] : map)` 分别改成 `auto&` 和 `const auto&`，观察是否能修改容器，以及是否发生拷贝。
5. 把 `std::vector<int> a{3, 7}` 和 `std::vector<int> b(3, 7)` 打印出来，说明两个对象为什么不同。
6. 让一个函数返回局部 `std::pair`，分别使用 `auto`、`const auto&` 绑定返回值；再尝试把其中一个引用保存到函数外，说明为什么生命周期很重要。

完成后尝试回答：

- 初始化和赋值发生在什么时候？对类对象分别可能调用什么操作？
- 为什么花括号初始化能帮助发现窄化转换？它为什么又可能改变 `vector` 的含义？
- 成员初始化列表为什么不是“构造函数体里的赋值”？成员实际按照什么顺序初始化？
- `auto [a, b]`、`auto& [a, b]` 和 `const auto& [a, b]` 的区别是什么？
- 遍历 `std::map` 时，为什么键不能通过结构化绑定修改？
- 结构化绑定使用引用时，需要检查哪些生命周期问题？
