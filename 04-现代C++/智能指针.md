# 智能指针

智能指针（smart pointer）是“像指针一样使用、自动管理对象生命周期”的类模板。它们位于 `<memory>` 头文件中，最常用的有：

| 类型 | 所有权关系 | 典型用途 |
| --- | --- | --- |
| `std::unique_ptr<T>` | 一个对象只能有一个拥有者 | 默认选择、树节点、资源句柄 |
| `std::shared_ptr<T>` | 多个指针共同拥有对象 | 生命周期确实由多个对象共同决定 |
| `std::weak_ptr<T>` | 不拥有对象，只观察对象 | 观察 `shared_ptr` 对象、打破循环引用 |

## 学习目标

- [ ] 能解释“所有权”和“生命周期”，知道为什么智能指针能减少 `delete`。
- [ ] 能在 `unique_ptr`、`shared_ptr` 和 `weak_ptr` 之间做出合理选择。
- [ ] 能安全地使用 `make_unique`、`make_shared`、`std::move` 和 `weak_ptr::lock()`。
- [ ] 能识别循环引用、手动 `delete`、从同一个裸指针构造多个 `shared_ptr` 等常见错误。

## 一、先理解：指针不等于所有权

普通指针（裸指针）只是保存一个地址。它本身不知道：

1. 这个地址指向的对象是谁创建的；
2. 谁负责释放它；
3. 这个对象是否已经被释放。

例如：

```cpp
#include <iostream>

void print_value(int* p) {
    // p 只是“借来”的地址，这个函数不应该 delete p。
    if (p != nullptr) {
        std::cout << *p << '\n';
    }
}

void create_value() {
    int* p = new int(42);
    print_value(p);
    delete p; // 创建者负责释放；任何路径漏掉这行都会造成内存泄漏
}
```

当函数中间发生异常或提前 `return` 时，手动 `delete` 很容易被跳过。智能指针把“释放资源”放进析构函数中，这就是 RAII（资源获取即初始化）的思想：离开作用域时自动清理。

```cpp
#include <iostream>
#include <memory>

void create_value_safely() {
    auto p = std::make_unique<int>(42);
    std::cout << *p << '\n';
    // 离开函数时 p 自动析构，所指向的 int 自动释放，不需要 delete。
}
```

> 智能指针不是“更高级的裸指针”，而是一个记录所有权规则的对象。写代码前先回答：**这个对象由谁拥有？什么时候应该销毁？**

## 二、`unique_ptr`：独占所有权（默认选择）

### 2.1 基本用法

`std::unique_ptr<T>` 表示“同一时刻只有一个拥有者”。它不能被复制，只能被移动。

`std::make_unique` 从 C++14 开始提供；如果项目必须使用 C++11，可以写
`std::unique_ptr<T>(new T(...))`，但新项目应优先使用 C++14 及以上的 `make_unique`。

```cpp
#include <iostream>
#include <memory>
#include <utility>

struct User {
    explicit User(int id) : id(id) {
        std::cout << "User " << id << " 构造\n";
    }

    ~User() {
        std::cout << "User " << id << " 析构\n";
    }

    int id;
};

int main() {
    // 推荐使用 make_unique：表达清楚，也避免手写 new。
    auto user = std::make_unique<User>(7);

    if (user) {                    // 可以像判断裸指针一样判断是否为空
        std::cout << user->id << '\n';
    }

    // auto another = user;        // 错误：unique_ptr 不能复制
    auto another = std::move(user); // 所有权转给 another

    // 移动后，user 仍然是一个有效的 unique_ptr，但通常为空。
    // 不要再通过 user 访问原来的对象。
    std::cout << std::boolalpha << (user == nullptr) << '\n';
}
```

`std::move` 本身不搬运对象，也不释放对象；它只是允许进行“移动构造/移动赋值”。移动后，原指针放弃所有权，新指针成为唯一拥有者。

### 2.2 参数和返回值怎么写

```cpp
// 只使用对象，不取得所有权：用引用或裸指针表达“借用”。
void show_user(const User& user);

// 可能没有对象：用裸指针（允许 nullptr）表达“可选借用”。
void show_optional_user(const User* user);

// 调用者把所有权交给函数：按值接收 unique_ptr。
void save_user(std::unique_ptr<User> user);

// 函数创建并交出所有权：按值返回 unique_ptr。
std::unique_ptr<User> make_user(int id) {
    return std::make_unique<User>(id);
}

void example() {
    auto user = make_user(1);
    save_user(std::move(user)); // 明确表示 user 不再拥有对象
}
```

经验法则：**不涉及所有权时，不要为了“现代”而传智能指针；涉及独占所有权时，传 `unique_ptr`。**

### 2.3 `get`、`release` 和 `reset` 的区别

这三个函数名称很像，但责任完全不同：

```cpp
auto p = std::make_unique<int>(10);

int* borrowed = p.get();
// get() 只拿到裸指针的“观察视图”，p 仍然拥有对象。
// 不要 delete borrowed，也不要让它在 p 销毁后继续使用。

int* raw = p.release();
// release() 放弃所有权，并返回裸指针；此时不会自动 delete。
// 只有在马上交给另一个明确的资源管理者时才使用，否则会泄漏。
delete raw; // 这里由我们重新承担释放责任

auto q = std::make_unique<int>(20);
q.reset(); // 释放当前对象，并让 q 变为空
q.reset(new int(30)); // 释放旧对象，改为管理新对象；一般更推荐 make_unique
```

### 2.4 管理数组和自定义删除器

```cpp
#include <cstdio>
#include <memory>

// 数组版本会使用 delete[]，不要把它和 unique_ptr<int> 混用。
auto numbers = std::make_unique<int[]>(3);
numbers[0] = 10;

// 文件等资源不一定用 delete 释放，可以提供自定义删除器。
struct FileCloser {
    void operator()(std::FILE* file) const {
        if (file != nullptr) {
            std::fclose(file);
        }
    }
};

using FilePtr = std::unique_ptr<std::FILE, FileCloser>;
FilePtr file(std::fopen("data.txt", "r"));
// file 离开作用域时自动调用 FileCloser，而不是 delete。
```

## 三、`shared_ptr`：共享所有权

### 3.1 引用计数是什么

`std::shared_ptr<T>` 允许多个指针共同拥有一个对象。它通常通过“控制块”记录引用计数：

- 复制一个 `shared_ptr`，强引用计数加一；
- 一个 `shared_ptr` 被销毁或 `reset()`，计数减一；
- 强引用计数变成零时，对象被销毁；
- 控制块还可能继续存在，直到所有 `weak_ptr` 也消失。

```cpp
#include <iostream>
#include <memory>

auto first = std::make_shared<int>(42);
std::cout << first.use_count() << '\n'; // 1

{
    auto second = first;                  // 共同拥有同一个 int
    std::cout << first.use_count() << '\n'; // 2
}

std::cout << first.use_count() << '\n'; // 1，second 离开作用域
```

推荐 `std::make_shared<T>(...)`，因为它通常能一次分配对象和控制块，代码也更安全、更简洁。

### 3.2 什么时候才需要 `shared_ptr`

只有在“多个独立对象都必须延长同一对象的生命周期”时，才考虑 `shared_ptr`。例如多个任务共同使用一个共享配置对象，而且无法明确哪一个任务最后结束。

如果实际上只有一个拥有者，却使用 `shared_ptr`，会增加引用计数、控制块和线程同步等开销，还会让所有权关系变得模糊。**能用 `unique_ptr` 就不要默认改成 `shared_ptr`。**

### 3.3 不要从同一个裸指针构造两个 `shared_ptr`

下面的写法会产生两个控制块，最终很可能对同一地址执行两次 `delete`：

```cpp
// 错误示例：不要这样写
int* raw = new int(42);
std::shared_ptr<int> a(raw);
std::shared_ptr<int> b(raw); // a、b 各自认为自己是唯一控制者
```

正确做法是复制已经存在的 `shared_ptr`：

```cpp
auto a = std::make_shared<int>(42);
auto b = a; // a、b 共享同一个控制块，安全
```

同理，不要对 `shared_ptr.get()` 返回的裸指针调用 `delete`；对象的释放由 `shared_ptr` 负责。

## 四、`weak_ptr`：观察而不拥有

### 4.1 为什么需要它

`weak_ptr` 不会增加 `shared_ptr` 的强引用计数。它适合表示“我想访问这个对象，但不应该阻止它销毁”。

最重要的用法是 `lock()`：它会尝试生成一个临时的 `shared_ptr`。

```cpp
#include <iostream>
#include <memory>

std::weak_ptr<int> observer;

{
    auto owner = std::make_shared<int>(42);
    observer = owner; // observer 只观察，不延长 int 的寿命

    if (auto current = observer.lock()) {
        // lock 成功：current 在本作用域内拥有一个临时强引用。
        std::cout << *current << '\n';
    }
}

// owner 已销毁，observer.expired() 为 true。
if (auto current = observer.lock()) {
    std::cout << *current << '\n';
} else {
    std::cout << "对象已经销毁\n";
}
```

不要只检查 `expired()` 后再单独使用对象：检查和使用之间对象可能被另一个线程销毁。应直接判断 `lock()` 返回的 `shared_ptr`，并在这个临时指针存活期间访问对象。

### 4.2 用 `weak_ptr` 打破循环引用

如果两个对象互相持有 `shared_ptr`，引用计数永远不会归零：

```cpp
#include <iostream>
#include <memory>

struct Node {
    std::shared_ptr<Node> next;
    ~Node() { std::cout << "Node 析构\n"; }
};

auto first = std::make_shared<Node>();
auto second = std::make_shared<Node>();
first->next = second;
second->next = first; // 循环：离开作用域后两个 Node 都不会析构
```

把“不需要拥有对方”的一边改成 `weak_ptr`：

```cpp
struct SafeNode {
    std::shared_ptr<SafeNode> child; // 父节点拥有子节点
    std::weak_ptr<SafeNode> parent;   // 子节点只观察父节点，不形成拥有环
};

auto parent = std::make_shared<SafeNode>();
auto child = std::make_shared<SafeNode>();
parent->child = child;
child->parent = parent;
// parent、child 离开作用域后可以正常释放。
```

## 五、`enable_shared_from_this`：从成员函数安全地获得 `shared_ptr`

如果对象已经由 `shared_ptr` 管理，成员函数有时需要把“自己”交给异步任务。不能直接写 `shared_ptr(this)`，因为这会新建一个控制块，导致重复释放。

```cpp
#include <memory>

class Session : public std::enable_shared_from_this<Session> {
public:
    std::shared_ptr<Session> self() {
        // shared_from_this() 会复用已有的控制块。
        return shared_from_this();
    }
};

auto session = std::make_shared<Session>();
auto same_session = session->self(); // 两个 shared_ptr 共享控制块
```

注意：对象必须先由 `shared_ptr` 创建和管理，才能调用 `shared_from_this()`。如果直接在栈上创建 `Session local;`，或用裸指针 `new Session` 后直接调用，可能抛出 `std::bad_weak_ptr`。

## 六、三种智能指针的选择流程

可以按下面的问题顺序判断：

1. 这个函数/对象是否负责销毁资源？
   - 不负责，只是借用：用引用或裸指针（必要时允许 `nullptr`）。
2. 需要负责销毁，并且只有一个拥有者吗？
   - 是：用 `unique_ptr`。
3. 确实有多个独立拥有者吗？
   - 是：用 `shared_ptr`。
4. 只是观察一个由 `shared_ptr` 管理的对象，且不应延长其寿命吗？
   - 是：用 `weak_ptr`。

简化成一句话：

> 默认 `unique_ptr`，需要共享时才用 `shared_ptr`，只观察共享对象时用 `weak_ptr`；不表达所有权时不要传智能指针。

## 七、常见错误清单

### 7.1 手动 `delete` 智能指针管理的对象

```cpp
auto p = std::make_unique<int>(1);
// delete p.get(); // 错误：p 析构时还会再次释放同一对象
```

### 7.2 让裸指针活得比智能指针久

```cpp
int* raw = nullptr;
{
    auto owner = std::make_unique<int>(1);
    raw = owner.get();
} // owner 已销毁
// std::cout << *raw; // 错误：raw 已悬空（dangling pointer）
```

### 7.3 把 `shared_ptr` 当成线程安全的对象

不同 `shared_ptr` 实例对同一控制块的引用计数操作通常是安全的，但这不代表它们指向的业务对象可以无锁并发读写。对象数据是否安全，仍然需要互斥量或其他同步手段。

### 7.4 用 `use_count()` 做业务判断

`use_count()` 适合调试，不适合写“计数等于 1 才执行”的业务逻辑，尤其在多线程环境中，计数可能随时改变。需要判断对象是否仍存在时，用 `weak_ptr::lock()`。

## 八、一个小型综合示例

下面的例子模拟“目录拥有文件，外部代码可以观察目录，但不能阻止目录销毁”：

```cpp
#include <iostream>
#include <memory>
#include <string>
#include <utility>
#include <vector>

class File {
public:
    explicit File(std::string name) : name_(std::move(name)) {}
    const std::string& name() const { return name_; }

private:
    std::string name_;
};

class Directory {
public:
    explicit Directory(std::string name) : name_(std::move(name)) {}

    void add_file(std::unique_ptr<File> file) {
        // Directory 取得 file 的独占所有权。
        files_.push_back(std::move(file));
    }

    const std::string& name() const { return name_; }

private:
    std::string name_;
    std::vector<std::unique_ptr<File>> files_;
};

int main() {
    auto directory = std::make_shared<Directory>("docs");
    directory->add_file(std::make_unique<File>("readme.md"));

    std::weak_ptr<Directory> watcher = directory;
    directory.reset(); // 没有其他 shared_ptr 后，Directory 和其中的 File 都销毁

    if (auto alive = watcher.lock()) {
        std::cout << alive->name() << '\n';
    } else {
        std::cout << "目录已经销毁\n";
    }
}
```

这里有三层关系：`directory` 是 `Directory` 的拥有者；`Directory` 用 `unique_ptr` 独占每个 `File`；`watcher` 只是观察目录，不会阻止目录销毁。
