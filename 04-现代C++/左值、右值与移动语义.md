# 左值、右值与移动语义

## 学习目标

- [ ] 从“能否取地址、能否再次使用”的角度理解左值和右值。
- [ ] 知道左值、右值引用的写法和适用场景。
- [ ] 区分拷贝构造、拷贝赋值、移动构造和移动赋值。
- [ ] 理解 `std::move` 只是类型转换，不会自己搬运任何字节。
- [ ] 能为拥有资源的类型写出基本的移动操作，并正确处理“移动后对象”。
- [ ] 理解为什么移动操作通常要标记为 `noexcept`，以及容器扩容时的影响。
- [ ] 对转发引用和 `std::forward` 有一个够用的入门认识。

## 要点

## 1. 先建立直觉：表达式是“有名字的对象”还是“临时结果”

在 C++ 中，**左值（lvalue）**和**右值（rvalue）**描述的不是“写在赋值号左边还是右边”，而是表达式的一种**值类别（value category）**。

初学时可以先用两个问题判断：

1. 这个表达式是否代表一个可以在下一条语句中继续找到的对象？
2. 是否可以对它取地址（写 `&表达式`）？

通常：

- 有名字、可以稳定地再次使用的对象是左值；
- 临时计算结果、即将结束生命周期的对象是右值。

~~~cpp
int a = 10;       // a 是左值：有名字，生命周期还在继续
int b = a + 1;    // a + 1 的结果是右值：一个临时的计算结果

int* p = &a;      // 可以对左值 a 取地址
// int* q = &(a + 1); // 错误：不能对这个临时结果直接取地址
~~~

“左值”这个名字来自早期 C 语言里“可以出现在赋值号左侧”的对象，但现代 C++ 中不能只靠赋值号位置来判断。比如字面量 `10` 写在等号右边，它本身仍是右值；函数返回的临时对象也通常是右值。

~~~cpp
int value = 0;
value = 42;       // value 是左值，42 是右值

// 42 = value;    // 错误：字面量不是可修改的左值
~~~

## 2. C++ 的值类别：先掌握三层结构

标准把值类别分成三层。刚入门时不必一次记住所有术语，但理解它们有助于读懂标准库接口：

~~~text
                    表达式
                   /      \
              glvalue     rvalue
              /    \      /    \
          lvalue  xvalue      prvalue
~~~

- **左值（lvalue）**：代表一个仍然存在的对象，通常有名字，可以取地址，例如变量 `name`。
- **将亡值（xvalue）**：代表一个仍然存在、但资源可以被“移交”的对象，例如 `std::move(name)`。
- **纯右值（prvalue）**：主要是临时计算结果，例如 `1 + 2`、字面量 `42`、临时对象 `std::string("hi")`。
- **广义左值（glvalue）**：左值和将亡值的总称；它们都能定位到某个对象。
- **右值（rvalue）**：将亡值和纯右值的总称；它们适合绑定到右值引用。

可以先记住最实用的对应关系：

| 类别 | 常见例子 | 主要用途 |
| --- | --- | --- |
| lvalue | `value`、`obj.member`、`*ptr` | 修改或观察一个仍要继续使用的对象 |
| xvalue | `std::move(value)` | 明确表示可以把资源交出去 |
| prvalue | `42`、`a + b`、`Type{}` | 产生临时结果，常触发移动或拷贝消除 |

`std::move(value)` 看起来像“移动”，实际上只是把 `value` 转换成 xvalue。真正执行资源转移的是目标类型的移动构造函数或移动赋值运算符，后文会详细说明。

## 3. 左值引用与右值引用

### 3.1 左值引用：给已有对象起一个别名

左值引用写作 `T&`。它不会创建新对象，只是给已有对象起了另一个名字：

~~~cpp
int score = 90;
int& ref = score; // ref 和 score 指向同一个 int 对象

ref = 100;        // 修改 ref，也就是修改 score
// int& bad = 10;  // 错误：普通左值引用不能绑定到临时右值
~~~

`const T&` 是一个很有用的例外：它可以绑定到左值，也可以绑定到右值，并且不会修改对象。

~~~cpp
void print(const std::string& text) {
    // const 引用只借用对象，不取得所有权
}

std::string name = "Alice";
print(name);                       // 绑定到左值
print(std::string("temporary"));  // 也能绑定到临时右值
~~~

把临时对象绑定到局部 `const T&` 时，临时对象的生命周期通常会延长到该引用离开作用域；但这条规则有例外，不能因此返回局部引用或把引用保存到更长生命周期的对象中。

### 3.2 右值引用：接住“可以被消耗”的对象

右值引用写作 `T&&`，主要用于两件事：

1. 接收临时对象；
2. 在明确不再需要原对象内容时，允许转移资源。

~~~cpp
std::string&& temporary = std::string("hello");
// temporary 这个名字本身是左值！
~~~

这是一个很容易踩的坑：**只要有名字，表达式通常就是左值**。即使变量的类型是 `std::string&&`，使用变量名 `temporary` 时，它仍然是左值。若要再次把它当作右值传递，需要写 `std::move(temporary)`。

右值引用本身仍然是引用，不拥有对象；它只是允许被调用者选择移动资源。生命周期和所有权仍由原对象决定。

## 4. 为什么需要移动语义：昂贵的深拷贝

假设一个字符串对象内部拥有一块堆内存。复制它时，通常要重新申请内存并复制每个字符：

~~~text
拷贝：source 的字符  ──复制每个字节──> 重新分配的 destination 内存
移动：source 的指针  ──转交给──> destination
      source 留在有效但通常为空的状态
~~~

移动并不是把对象“整体搬到另一个地址”，而是**转移对象管理的资源**。对于 `std::string`、`std::vector`、`std::unique_ptr` 这类内部拥有动态资源的类型，移动通常只需交换或接管几个指针、大小和容量，成本远低于深拷贝。

~~~cpp
#include <string>

std::string make_message() {
    return std::string(1000, 'x'); // 创建一个较大的临时字符串
}

void use_message() {
    std::string message = make_message();
    // 现代 C++ 通常会进行返回值优化（RVO/NRVO），
    // 即使没有优化，也优先尝试移动，而不是复制 1000 个字符。
}
~~~

移动语义还让“只允许一个拥有者”的类型可以安全地传递。例如 `std::unique_ptr` 禁止复制，但允许移动：

~~~cpp
#include <memory>

auto first = std::make_unique<int>(42);
// auto copy = first;             // 错误：不能复制唯一所有权
auto second = std::move(first);   // 正确：把所有权移动给 second

// first 仍然是一个有效的 unique_ptr，但现在通常为空。
// second 负责最终删除那个 int 对象。
~~~

## 5. 四种特殊成员操作：拷贝和移动的完整对照

需要区分“初始化一个新对象”和“给已有对象赋值”：

~~~cpp
Widget a;                 // 普通构造
Widget b = a;             // 拷贝构造：b 还不存在
Widget c = std::move(a);  // 移动构造：c 还不存在

b = a;                    // 拷贝赋值：b 已经存在
b = std::move(c);         // 移动赋值：b、c 都已经存在
~~~

对应的成员函数通常长这样：

~~~cpp
class Widget {
public:
    Widget(const Widget& other);             // 拷贝构造
    Widget& operator=(const Widget& other);  // 拷贝赋值

    Widget(Widget&& other) noexcept;             // 移动构造
    Widget& operator=(Widget&& other) noexcept;  // 移动赋值
};
~~~

参数中的 `const Widget&` 可以绑定左值和右值，因此拷贝构造也能处理临时对象；但当传入右值时，移动构造提供了更高效的选择。编译器会根据参数的值类别选择更匹配的重载。

## 6. 一个完整的移动示例：自己管理动态数组

下面的 `Buffer` 故意直接管理一块动态数组，用来观察移动发生了什么。真实项目中优先使用 `std::vector<int>`，因为它已经正确实现了这些操作。

~~~cpp
#include <algorithm>
#include <cstddef>
#include <iostream>
#include <utility>

class Buffer {
public:
    explicit Buffer(std::size_t size)
        : size_(size), data_(size ? new int[size]{} : nullptr) {
        std::cout << "普通构造\n";
    }

    ~Buffer() {
        delete[] data_; // delete[] nullptr 也是安全的
        std::cout << "析构，size = " << size_ << '\n';
    }

    // 深拷贝：申请一块新数组，再复制每个元素
    Buffer(const Buffer& other)
        : size_(other.size_), data_(size_ ? new int[size_] : nullptr) {
        if (size_ > 0) {
            std::copy(other.data_, other.data_ + size_, data_);
        }
        std::cout << "拷贝构造\n";
    }

    // 移动构造：直接接管 other 的数组指针
    Buffer(Buffer&& other) noexcept
        : size_(other.size_), data_(other.data_) {
        // 把 other 置为空，避免两个对象析构时 delete[] 同一块内存
        other.size_ = 0;
        other.data_ = nullptr;
        std::cout << "移动构造\n";
    }

    // 先释放自己的旧资源，再接管 other 的资源
    Buffer& operator=(Buffer&& other) noexcept {
        if (this == &other) { // 防止 buffer = std::move(buffer) 出现问题
            return *this;
        }

        delete[] data_; // 释放当前对象原来拥有的数组
        size_ = other.size_;
        data_ = other.data_;
        other.size_ = 0;
        other.data_ = nullptr;
        std::cout << "移动赋值\n";
        return *this;
    }

    // 为了示例完整，拷贝赋值直接删除，表示本示例只关注移动。
    Buffer& operator=(const Buffer&) = delete;

    std::size_t size() const { return size_; }

private:
    std::size_t size_ = 0;
    int* data_ = nullptr;
};

Buffer make_buffer() {
    Buffer local(1024);
    return local; // 可能发生 NRVO；否则可使用移动构造
}

int main() {
    Buffer a(10);
    Buffer b = std::move(a); // b 接管 a 的数组；a 变为空状态

    std::cout << "a.size() = " << a.size() << '\n';
    std::cout << "b.size() = " << b.size() << '\n';

    Buffer c(1);
    c = std::move(b);        // c 先释放旧数组，再接管 b 的数组
    std::cout << "b.size() = " << b.size() << '\n';
}
~~~

这个例子体现了移动操作的三个关键步骤：

1. 目标对象接管源对象的资源；
2. 目标对象先释放自己原来拥有的资源（移动赋值时尤其重要）；
3. 源对象被置为“有效但资源为空”的状态，仍然可以析构或重新赋值。

如果一个类直接拥有裸指针资源，通常需要同时认真设计析构、拷贝构造、拷贝赋值、移动构造和移动赋值，这就是 **Rule of 5**。更推荐把 `int*` 换成 `std::vector<int>` 或 `std::unique_ptr<int[]>`，遵循 **Rule of 0**，让标准库成员自动完成正确的拷贝和移动。

## 7. `std::move` 的真实含义：转换，不是动作

`std::move` 位于 `<utility>`，它做的事情可以粗略理解为：把一个表达式转换成右值引用（更准确地说是 xvalue），从而允许重载决议选择移动构造或移动赋值。

~~~cpp
#include <string>
#include <utility>

std::string source = "hello";
std::string target = std::move(source);
// 这里是 string 的移动构造函数真正执行了资源转移。
// std::move 本身没有复制字符，也没有释放 source。
~~~

移动后不要继续依赖原对象的具体内容：

~~~cpp
// source 仍然是有效对象，可以：
source.clear();       // 重新赋值或清空
source = "new text";
std::cout << source.size();

// 但不要假设 source 一定是空字符串。
// 标准通常只保证“有效但未指定状态”（valid but unspecified）。
~~~

以下做法很危险：

~~~cpp
std::string name = "Alice";
consume(std::move(name));
// 不要再假设 name == "Alice"；它可能为空，也可能保留其他合法状态。
~~~

`std::move` 也不会让 `const` 对象变得可移动：

~~~cpp
const std::string text = "read only";
std::string copy = std::move(text); // 通常只能调用拷贝构造，因为不能窃取 const 对象的资源
~~~

原因是移动操作一般需要修改源对象（例如把指针设为 `nullptr`），而 `const` 对象不允许修改。

## 8. 返回值优化、拷贝消除与“不要过度手写 std::move”

C++17 对某些纯右值场景保证了拷贝消除：

~~~cpp
Widget make_widget() {
    return Widget{}; // 通常直接在调用者的存储位置构造 Widget
}

Widget w = make_widget(); // 不一定有任何拷贝或移动
~~~

命名返回值可能进行 NRVO（命名返回值优化）：

~~~cpp
Widget make_widget() {
    Widget result;
    return result; // 编译器通常会做 NRVO；不要为了“强制移动”而写 std::move(result)
}
~~~

在 `return std::move(result);` 中，显式转换可能阻碍 NRVO，通常不如直接 `return result;`。另一方面，函数参数是按值接收时，若确实要把参数存入成员，常见写法是：

~~~cpp
class Person {
public:
    explicit Person(std::string name)
        : name_(std::move(name)) {} // 参数是本函数的局部对象，可以安全移动进成员
private:
    std::string name_;
};
~~~

这里移动 `name` 是合理的，因为函数结束后参数本来也会销毁。调用者传入左值时会先拷贝到参数，传入右值时则通常直接移动到参数，再移动到成员。

## 9. `noexcept` 与标准容器的移动策略

移动构造函数如果保证不会抛异常，应声明为 `noexcept`：

~~~cpp
class SafeBuffer {
public:
    SafeBuffer(SafeBuffer&& other) noexcept;
};
~~~

原因是 `std::vector` 扩容时需要把旧元素搬到新内存。如果移动元素可能抛异常，搬到一半时可能既无法恢复旧数组，又没有完整的新数组。为了提供异常安全保证，容器可能改用拷贝构造；若类型不可拷贝，才会退而使用可能抛异常的移动。

因此，资源转移确实不会抛异常的类型，应把移动构造和移动赋值标记为 `noexcept`。标准库类型（如 `std::unique_ptr`）已经正确完成了这件事。

可以用类型特征观察某种类型是否支持不抛异常移动：

~~~cpp
#include <type_traits>

static_assert(std::is_nothrow_move_constructible_v<std::string>);
~~~

## 10. 转发引用与 `std::forward`：先知道它解决什么问题

模板中出现 `T&&` 时，它不一定是普通右值引用；如果 `T` 是待推导的模板参数，它可能是**转发引用（forwarding reference，也常称万能引用）**：

~~~cpp
template <typename T>
void log_and_call(T&& value) {
    // value 有名字，所以在函数体内是左值。
    // std::forward<T> 会恢复调用者传入时的左值/右值属性。
    use(std::forward<T>(value));
}
~~~

调用时：

~~~cpp
std::string text = "hello";
log_and_call(text);               // T 推导为 std::string&，保持左值
log_and_call(std::string("hi"));  // T 推导为 std::string，保持右值
~~~

如果写成 `use(value)`，无论调用者传入左值还是右值，`value` 在函数体内都有名字，因此都会按左值传递，可能错过移动。`std::forward<T>(value)` 才能在泛型代码中“原样转发”值类别。

初学阶段可以先遵循这个边界：普通函数需要转移资源时使用 `std::move`；只有在编写泛型包装函数、工厂函数或容器适配器时，再使用 `std::forward`。

## 11. 常见误区

### 11.1 “等号左边就是左值，右边就是右值”

错误。值类别属于表达式本身，和它在语句中的位置没有直接关系：

~~~cpp
int x = 1;       // x 是左值，1 是纯右值
x = x + 1;       // 等号右边的 x 仍然是左值；x + 1 整体是右值
~~~

### 11.2 “右值引用变量永远是右值”

错误。变量名 `ref` 是左值；需要移动时要写 `std::move(ref)`。

### 11.3 “调用 std::move 后原对象就不能用了”

错误。原对象仍然存在，但通常处于有效、未指定状态。可以析构、清空、重新赋值，也可以调用文档保证对该状态安全的成员函数；不要读取并假设原来的业务值还在。

### 11.4 “所有地方都写 std::move 会更快”

错误。过度使用可能阻碍返回值优化、让代码更难读，或者错误地移动一个后面还要使用的对象。只在确认对象之后不再需要原内容、且目标接口确实支持移动时使用。

### 11.5 “移动一定比拷贝快”

不一定。对只包含几个整数的小对象，移动和拷贝可能完全一样；对 `std::string` 的短字符串，可能因为小字符串优化而不需要堆内存。移动语义首先是正确表达资源转移，再谈性能收益。

### 11.6 “自定义析构函数不会影响移动”

如果类声明了析构函数、拷贝操作或移动操作中的某些成员，编译器可能不再隐式生成移动构造/移动赋值。遇到自定义资源类型时，应明确检查 `= default`、`= delete` 或自己实现的特殊成员函数，或者改用 Rule of 0。

## 示例与实践

### 1. 可运行示例：观察左值、右值和移动

将下面内容保存为 `value_category_demo.cpp`：

~~~cpp
#include <iostream>
#include <string>
#include <utility>

void take(const std::string& text) {
    std::cout << "const 左值引用接收：" << text << '\n';
}

void take(std::string&& text) {
    std::cout << "右值引用接收：" << text << '\n';
}

int main() {
    std::string name = "Alice";

    take(name);                 // name 是左值，调用 const std::string& 版本
    take(std::string("Bob"));  // 临时对象是右值，调用 std::string&& 版本
    take(std::move(name));      // 显式把 name 转为右值，允许移动

    // name 现在仍然存在，但内容处于“有效、未指定状态”。
    name = "重新赋值";          // 重新赋值后可以正常使用
    std::cout << name << '\n';
}
~~~

在 Windows PowerShell 中编译：

~~~powershell
cl /std:c++20 /W4 /EHsc value_category_demo.cpp /Fe:value_category_demo.exe
.\value_category_demo.exe
~~~

或使用 MinGW-w64：

~~~powershell
g++ -std=c++20 -Wall -Wextra -pedantic value_category_demo.cpp -o value_category_demo.exe
.\value_category_demo.exe
~~~

不同标准库实现可能对移动后的字符串保留不同内容，但调用的重载顺序和“移动后仍可重新赋值”的结论不变。

### 2. 练习建议

1. 为 `take` 增加一个 `void take(std::string& text)` 重载，观察非常量左值和右值分别匹配哪个版本。
2. 给 `Buffer` 增加拷贝赋值运算符，使用 `std::copy` 实现深拷贝，并测试 `a = b` 与 `a = std::move(b)` 的差异。
3. 删除 `Buffer` 的移动构造函数，观察 `Buffer b = std::move(a);` 是否还能编译，以及编译器会选择什么操作。
4. 用 `std::vector<Buffer>` 反复 `push_back`，分别比较移动构造函数带 `noexcept` 和不带 `noexcept` 时的行为。
5. 编写一个模板 `forward_to`，分别用 `value` 和 `std::forward<T>(value)` 调用重载函数，观察值类别是否被保留。
